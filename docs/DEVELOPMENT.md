# Development notes

How `yt2html` works, where it takes its data from, and how to test and release it. For using the program see [README.md](../README.md); for the history of versions see [CHANGELOG.md](../CHANGELOG.md).

YouTube does not document the page data the program reads. The paths below were checked on real pages (reference videos in the sections and in `tests/test_online.py`); when YouTube changes something, this document says where to look.

## Working on the project

Requirements: [uv](https://docs.astral.sh/uv/) and git.

```powershell
git clone https://github.com/mwislowski/yt-video-archiver
cd yt-video-archiver
uv sync                                   # creates .venv with the project and pytest
uv run yt2html.py --version               # run from the source folder
uv run pytest                             # tests
```

To use the source folder as the `yt2html` command everywhere, install it *editable* (changes to `yt2html.py` work at once):

```powershell
uv tool install --editable PATH\TO\yt-video-archiver
```

An editable install changes the everyday command with every edit, experiments included. For a stable everyday command, install a release instead and work on the code with `uv run yt2html` in the project folder:

```powershell
uv tool install git+https://github.com/mwislowski/yt-video-archiver@v0.9.1          # a tested release
uv tool install --force git+https://github.com/mwislowski/yt-video-archiver@v1.0.0  # later: switch to a newer one
```

After a change in `pyproject.toml` (dependencies, command) add `--reinstall`. To update yt-dlp in the project: `uv lock --upgrade-package yt-dlp`, then `uv sync`, and commit the updated `uv.lock`.

`.gitignore` excludes `.venv`, the test cache (`.pytest_cache/`), build output (`build/`, `dist/`), `*.html`, `*.html.part` and `*.info.json` (pages created when the command is run in the project folder), and `*.local.md` (private notes, kept only on this computer, so without a copy on GitHub). The repository contains only code, configuration and documentation, never archived pages.

## Version, packaging, releases

- **One source of the version:** `__version__` in `yt2html.py`. `pyproject.toml` has `dynamic = ["version"]` and `[tool.hatch.version] path = "yt2html.py"`, so the package version and `yt2html --version` always agree. `--version` prints it together with the yt-dlp version (most problems come from an outdated yt-dlp).
- **Versioning:** the second number for new features or visible changes (0.2.0, 0.3.0), the third for fixes (0.2.1). What changed in each version is in [CHANGELOG.md](../CHANGELOG.md).
- **Command:** `[project.scripts] yt2html = "yt2html:main"`; the wheel contains only `yt2html.py` (`[tool.hatch.build.targets.wheel] only-include`). `main()` returns the exit code, which the generated command passes on.
- **Release:** run the tests (also `--online`), change `__version__`, move the *Unreleased* entries in `CHANGELOG.md` under the new version with its date (and update the compare links at the bottom), commit, then `git tag -a vX.Y.Z -m "..."`, `git push` and `git push origin vX.Y.Z`. The changelog entries can serve as the GitHub release notes.

## Conventions

- **English everywhere in code:** identifiers, comments, CLI options, program messages, fixed page labels and invisible HTML (classes, ids, meta tags). Only the archived content itself is in its original language.
- **Configuration in constants at the top of `yt2html.py`** (`DEFAULT_OUTPUT_DIR`, `OUTPUT_TEMPLATE`, `DATE_FORMAT`, `THOUSANDS_SEPARATOR`, `AVATAR_SIZE`, `IMAGE_WORKERS`, ...); per-run choices are CLI options.
- **One output file, works without JavaScript.** Static HTML + CSS; every image is a `data:` URI. The page must work when opened from disk with no network. The only script is the built-in player (`PLAYER_JS`), which adds something and never replaces content; index pages have no script.
- Program messages are prefixed with `[yt2html]`; yt-dlp prints its own `[youtube]` progress lines.
- A failure for one URL does not stop the others; the exit code is 1 if anything failed.

## How the data is obtained

`yt_dlp.YoutubeDL(...).extract_info(url, download=False)` with:

- `skip_download`, `noplaylist`, `getcomments`;
- `extract_flat: "in_playlist"`: a safety net. `noplaylist` only turns watch URLs with `&list=` into the video; an unrecognised URL that leads to a playlist or channel would otherwise be extracted video by video, comments included. With it, yt-dlp returns only the flat list, and `archive()` fails with `this URL leads to a playlist or channel`. Playlist URLs never get here (see *Playlists*), channel URLs fail before any request (`is_channel_url()`);
- `ignore_no_formats_error: True` — the video is not downloaded, so missing formats (e.g. when no JavaScript runtime is installed for YouTube's player challenges) must not abort the run;
- `extractor_args = {"youtube": {"comment_sort": ["new"], "max_comments": [N or "all", "all", "all", "all"]}}`.

Then, in the same `YoutubeDL` instance (same cookies and consent), the watch page is fetched once more with `ydl.urlopen()` for the timestamp lists and the description extras (see below). The program adds keys of its own to the info dict (constants `*_KEY` at the top of `yt2html.py`), all kept by `--write-json`, among them: `yt2html_archived` (ISO date of fetching), `yt2html_marker_lists`, `yt2html_description_extras`, `yt2html_channel_avatar` (the avatar URL, see *The page, part by part*), `yt2html_youtube_comment_count` (the comment count text from the comments panel header, `engagementPanels[]` with `panelIdentifier` `engagement-panel-comments-section` → `header.engagementPanelTitleHeaderRenderer.contextualInfo`), `yt2html_comments_message` (YouTube's message in place of the comments: `contents.twoColumnWatchNextResults.results.results.contents[]` → `itemSectionRenderer` with `sectionIdentifier` `comment-item-section` → `contents[].messageRenderer.text`, the runs without a link, so `Comments are turned off.` without *Learn more*; seen on `okT1dSP6gQQ`, 13.11.2026, where the comments panel and its count are missing; `null` when the section holds comments) and `yt2html_max_comments` (the `--max-comments` value, `null` for no limit).

Why the program reads the comment count itself: when yt-dlp downloads comments, it **replaces** `comment_count` with the number of comments it downloaded (and sets it to `null` after `Ctrl+C`). So with `--max-comments 50` yt-dlp's `comment_count` is 50. `youtube_comment_count()` therefore uses the page's count; without it, yt-dlp's `comment_count` is used only when it can be trusted (comments not downloaded, or downloaded completely without a limit).

Used fields: `id`, `title`, `webpage_url`, `uploader`, `uploader_url`, `channel_is_verified`, `channel_follower_count`, `view_count`, `like_count`, `comment_count`, `duration`, `release_timestamp` / `timestamp` / `upload_date`, `thumbnail`, `thumbnails`, `description`, `chapters` (fallback only), `comments`.

Each comment: `id`, `parent` (`"root"` or the parent's id), `text`, `author`, `author_url`, `author_thumbnail`, `author_is_uploader`, `author_is_verified`, `like_count`, `is_pinned`, `is_favorited`, `timestamp`, `_time_text`.

## Comment order

- yt-dlp emits comments depth-first: a top-level comment, then its replies, then the next top-level comment.
- With `comment_sort=new` the top level comes **newest first** in YouTube's exact order; the program reverses it. The pinned comment arrives first regardless of its age.
- Replies come in YouTube's thread order, which is oldest first.
- YouTube gives only relative times (`2 years ago`), so `timestamp` is a coarse estimate. `chronological()` does a **stable** sort by it: the exact order from YouTube is kept within equal estimates, and only items whose estimate clearly disagrees (the pinned comment) move. Missing timestamps inherit the previous item's value.
- Comments whose parent is missing are shown at the top level. Deeper nesting (if YouTube ever returns it) is rendered recursively.

## Description extras (AI-generated video summary, People mentioned, Explore the podcast)

YouTube shows extra elements below the description text. They are the `items` of the engagement panel `engagement-panel-structured-description` (`content.structuredDescriptionContentRenderer.items`), in display order, e.g. (reference video `Z8lf5oWKfj0`): `expandableVideoDescriptionBodyRenderer` (the description itself), `expandableMetadataRenderer` (the summary), `howThisWasMadeSectionViewModel` (*How this was made*), `horizontalCardListRenderer` (the chapter cards), `videoDescriptionCourseSectionRenderer`, `videoDescriptionTranscriptSectionRenderer`, `videoDescriptionInfocardsSectionRenderer`.

`parse_description_extras()` reads these items, keeping YouTube's order, into `info["yt2html_description_extras"]` (`None` if the extra request failed, `[]` if there are none):

| `type` | Source item | Stored | Rendered |
|---|---|---|---|
| `video_summary` | `expandableMetadataRenderer` whose `expandedContent` is a `videoSummaryContentViewModel` | `title` (`header.expandedTitle`, `AI-generated video summary`), `paragraphs` (`paragraphs[].videoSummaryParagraphViewModel.text.content`). The collapsed teaser, the disclaimer subtitle and the feedback button are left out. | Before the chapters: `<section class="desc-extra video-summary">`, one `<p>` per paragraph (with `linkify()`). |
| `people` | `videoAttributesSectionViewModel` (`parse_people_section()`) | `title` (`headerTitle`, `People mentioned`), `subtitle` (`headerSubtitle`, `2 people`), `info` (the text of the ⓘ dialog: `headerInfoButton…dialogViewModel.content.basicContentViewModel.paragraphs[0].text`), `people[]`: `name` (`videoAttributeViewModel.title`), `description` (`subtitle`), `image` (`image.sources`, the smallest ≥ 240 px). | After the chapters: `<section class="desc-extra people">`; cards `.person` 150 px wide with photo, name and the full description (`.about`, wrapped, never cut). |
| `playlists` | `videoDescriptionCourseSectionRenderer` (`parse_playlist_section()`), items `mediaLockups[].structuredDescriptionPlaylistLockupRenderer` | `title` (`sectionTitle`, `Explore the podcast`), `items[]`: `title`, `url` (`navigationEndpoint.browseEndpoint.browseId` without the leading `VL` → `/playlist?list=…`), `byline` (`shortBylineText`), `count` (`videoCountShortText`, `557 episodes`), `image` (`thumbnail.thumbnails`, ≥ 240 px). `topicLink` (the *Podcasts* button) is left out. | After *People mentioned*: `<section class="desc-extra playlists">`, cover 120 px with the details aligned to its top; the podcast title is bold 14 px under the 16 px section heading (the same step as chapter headings in the transcript); cover and title link to the playlist. |

Attributed text (`attributed_text()`, `render_attributed()`): YouTube text with `commandRuns`. Only runs that open a web address (`innertubeCommand.urlEndpoint.url`) become links; others, such as *send feedback* (`userFeedbackEndpoint`, which runs YouTube's own script), stay plain text. `startIndex`/`length` count UTF-16 code units (as in JavaScript), so the text is sliced in UTF-16.

Images of the extras are collected by `extra_image_urls()` and embedded by `fetch_images()` (in parallel, unchanged size). A missing image becomes a grey box with the first letter (`.img-placeholder`).

CSS class names must not clash with existing ones: `description` (the description box) and `extra` (the grey Snapshot tile) are taken; hence `desc-extra`, `.about`, `.img-placeholder`.

Seen on reference video `9uSXOr-AdAU` (People mentioned + Explore the podcast) and `Z8lf5oWKfj0` (Explore the podcast). According to YouTube Help, *People mentioned* is generated automatically and being extended to more videos; *Explore the podcast* appears for videos in a playlist marked as a podcast in YouTube Studio.

## License

- On YouTube the license is a row of the video's metadata (`videoSecondaryInfoRenderer.metadataRowContainer.metadataRowContainerRenderer.rows[].metadataRowRenderer` with `title` `License`), not part of the expanded description's *Video details* list. It exists only for non-standard licenses. Reference video `KZtvWKpXPro`: `Creative Commons Attribution license (reuse allowed)` → `https://www.youtube.com/t/creative_commons`.
- `parse_license()` keeps the text runs and their web links (`navigationEndpoint.urlEndpoint.url`; YouTube `/redirect?q=` links are unwrapped by `unwrap_redirect()`). Stored in `info["yt2html_license"]` as `{title, runs: [{text, url}]}`, `None` when the video has none.
- `license_of()`: if the watch page could not be read (or for an older JSON file), yt-dlp's plain-text `license` field is used instead, without the link.
- Rendered after the transcript, before the comments, as `<section class="desc-extra license">`.

## Chapters and other timestamp lists

Everything is read from `ytInitialData` of the watch page, downloaded once more by `add_watch_page_data()` (`/watch?v=ID&hl=en`), which also reads the description extras above; the JSON after `ytInitialData =` is parsed with `json.JSONDecoder().raw_decode()`, which stops exactly at the end of the object. yt-dlp is not used for this: it keeps only one list as `chapters`, without its name or origin, and when the progress bar has no chapters it takes the first panel, which can be *Walkthroughs*.

Two places in `ytInitialData` hold timestamp lists:

| Place | Path | What it says |
|---|---|---|
| Progress bar | `playerOverlays.playerOverlayRenderer.decoratedPlayerBarRenderer.decoratedPlayerBarRenderer.playerBar.multiMarkersPlayerBarRenderer.markersMap[]` | `key` = `DESCRIPTION_CHAPTERS` or `AUTO_CHAPTERS`; `value.chapters[].chapterRenderer` with `title` and `timeRangeStartMillis`. The older `chapteredPlayerBarRenderer.chapters` (no key) is read too. |
| Engagement panels | `engagementPanels[].engagementPanelSectionListRenderer` with `content.macroMarkersListRenderer` | `panelIdentifier` and header title; items `macroMarkersListItemRenderer` with `title`, `timeDescription` and `onTap.watchEndpoint.startTimeSeconds`. Info rows (`macroMarkersInfoItemRenderer`, e.g. "These chapters are auto-generated") are skipped. |

Panel identifiers seen so far (04.11.2026): `engagement-panel-macro-markers-description-chapters`, `engagement-panel-macro-markers-auto-chapters` (both titled `Chapters`) and `engagement-panel-macro-markers-problem-walkthroughs` (`Walkthroughs`; the progress bar has no markers for it). Reference videos: `Z8lf5oWKfj0` (description chapters), `qyqCTMirNWg` (auto chapters), `hz6-3-7GGyI` (Walkthroughs only).

`parse_marker_lists()` builds the lists:

- **Chapters** (panels whose id contains `chapters`, plus the progress bar): the progress bar defines the chapters and their times (a chapter panel is used only when the bar has none); the panel gives the heading. Shown first, as one list.
- **Origin** (`decide_chapter_source()`): YouTube's own markings (progress-bar key and panel id) are combined with an independent check of the description (`description_chapter_starts()`: the run of consecutive timestamped lines beginning with the first `0:00` line, at least three, ascending, each chapter at least 10 s — YouTube's rules).
  - YouTube says *description* and the description has a valid list with the same start times → `description`.
  - YouTube says *auto* and the description has no valid list → `auto`.
  - Anything else — markings that disagree with each other or with the description, or an unknown key/panel id → `uncertain`: neutral heading, warning `Chapter source unclear: ...` on screen, the reason kept in `source_problem`. The program never guesses an origin.
- **Other panels** (e.g. Walkthroughs): as they are, `source: null`, in page order after the chapters.

Stored in `info["yt2html_marker_lists"]` as `[{id, title, source, source_problem?, items: [{start_time, time_text, title}]}]`. `None` means the extra request failed: the page then falls back to yt-dlp's `chapters` under a neutral `Chapters` heading (it may even be a Walkthroughs list). An empty list means the video has none.

Rendered after the description as `<section class="markers">` with an `<ol>`, one row per item; the origin note is `<span class="source">` (grey) in the heading, using the labels in `SOURCE_NOTES`.

## Transcript

- YouTube's own transcript panel loads its text from `/youtubei/v1/get_transcript` (parameters in `engagement-panel-searchable-transcript`). Checked on 05.11.2026: a request built outside the browser is refused (`400 Precondition check failed`); the browser sends extra integrity data that only YouTube's own JavaScript produces. So the program does not use it.
- The panel shows the text of a caption track, so `fetch_transcript()` downloads that track instead, from the URLs yt-dlp has already extracted (`info["subtitles"]`, `info["automatic_captions"]`; yt-dlp also deals with tokens YouTube may require for captions). Format `json3`, read with `ydl.urlopen()`.
- Track choice: the panel opens with the caption track of the **original audio**, which matters for auto-dubbed videos. They have one audio track per dubbed language and automatic captions for each of them, and yt-dlp marks every one of those with `-orig` (reference video `Z8lf5oWKfj0`: English original, 20 dubs; taking the first `-orig` track gave Arabic).
  - `default_caption_track()` reads `ytInitialPlayerResponse` from the watch page: `captions.playerCaptionsTracklistRenderer.audioTracks[defaultAudioTrackIndex]` is the original audio; its `defaultCaptionTrackIndex` points into `captionTracks` (language and `kind: "asr"` for automatic captions). Without that index, the language of the audio stream whose `audioTrack.displayName` contains `original` (e.g. `English (US) original`, id `en-US.4`) is used, else the audio track's id, else its first caption track. Stored as `info["yt2html_default_caption_track"]` = `{language, kind: "asr" | "manual" | null}`.
  - `choose_caption_track()` then picks from yt-dlp's tracks in that language: automatic captions first if the page says `asr`, otherwise author subtitles first (`en`, `en-US`, ...), then automatic captions (`<lang>-orig`, `<lang>`). Without page data the original language comes from yt-dlp's formats (`language_preference` 10 = original), then `info["language"]`, then a single `-orig` track; with none of these, any author subtitles. `live_chat` is ignored; translated tracks are never used.
- `parse_json3_captions()`: one cue per json3 event with `segs`; the `utf8` pieces are joined, line breaks and repeated spaces become single spaces; events holding only a line break (automatic captions add them) are skipped. Cue start = `tStartMs` / 1000.
- Stored in `info["yt2html_transcript"]` as `{language, name, kind: "manual" | "auto", cues: [{start, text}], translations?: {LANG: {language, name, cues}}}`; `missing?: {LANG: reason}` (the translations YouTube did not have or did not send); `None` if the video has no transcript (the reason in `yt2html_transcript_missing`); absent without `--transcript` (nothing is downloaded). The cues are kept, so `--load-json` can rebuild the page with any versions (without `--transcript` there a saved transcript is left out; a `bilingual:CODE` needs that translation in the file, or a reason in `missing`, else `TranscriptError` and nothing is written).
- Bilingual (`bilingual:CODE`): `fetch_translation()` downloads the same caption track with `tlang=CODE` added (`with_query()`), i.e. YouTube's auto-translate, which keeps the original timing; several languages are downloaded one after another. The languages YouTube offers are read from the watch page (`ytInitialPlayerResponse` → `captions.playerCaptionsTracklistRenderer.translationLanguages`) into `info["yt2html_translation_languages"]` (`{code: name}`). YouTube answers `HTTP 429 Too Many Requests` to auto-translated captions requested soon after the video data was fetched; original captions and author subtitles are not affected. Until early November 2026 about a minute was enough (yt-dlp issue #13831, where a maintainer confirmed that waiting at least 60 s works); since about 12.11.2026 the refusal often lasts for days, from other networks, for other videos, also for yt-dlp alone, with curl_cffi impersonation, the `mweb` client and browser cookies, while the browser shows the translations (probably a PO token for subtitles is needed; not tried yet: a PO token provider plugin such as bgutil). So a translation is requested once, `translation_wait()` (a random 70–100 s, `TRANSLATION_WAIT`; a fixed delay looks automated) after fetching started (comments downloaded meanwhile count towards it), and not retried. What YouTube does not have (`TranslationUnavailable`: a language not offered, the message listing the available codes; a language equal to the transcript's own; an empty translation) or does not send (`TranslationRefused`, a subclass: 429 or any failed download, the reason from `refusal_reason()`, e.g. `YouTube refused to send it (HTTP 429 Too Many Requests)`) is logged (`No translation into 'fi': …`; a refusal adds that the page counts as finished and `--overwrite` adds it later) and kept in `missing`; the page leaves that version out and *About this copy* names it (`not available: bilingual:fi (reason)`). A video without captions is logged as `No transcript: …`. Only a failed download of the transcript itself raises `TranscriptError` during fetching, so nothing is written, not even `--write-json`, and the next run tries again (a page that is there counts as finished).
- **One download per caption track and run** (`caption_data()`): every caption track, for the transcript and for `--video sub:` files alike, is fetched as json3 (`fmt=json3` set on any address) through `caption_cache`, keyed by `caption_key()`: the address's `v`, `lang`, `kind`, `name` and `tlang`, so the same track from another fetch (other signature and expiry) is the same entry. A failure is kept too and raised again, so a refused translation is asked for once per run. The wait until `not_before` happens only on a real download. `main()` empties the cache at the start of a run (and `conftest.py` for each test). `align_translation()` gives each original cue the translated cues starting at the same time (or before the next original cue); `render_bilingual_transcript()` draws rows as a 3-column CSS grid (time, original, translation; on narrow screens the translation goes under the original, in grey).
- Option: `--transcript [VERSIONS]`, like `--video`: `nargs="?"`, `const=""` (the option alone: `[("plain", None)]`), default `[]` (no transcript: `fetch_info()` downloads none); one comma-separated argument, parsed by `transcript_spec()` into an ordered list of `(version, language)` pairs: `plain`, `timestamps`, `bilingual:CODE`. The value being optional, an address after a bare `--transcript` would be taken as versions: README documents `yt2html URL --transcript [VERSIONS]`, and an unknown item ends with "the video's address goes before --transcript". Anything unknown, `none` too, gets one message, `'none' is not a parameter (use plain, timestamps or bilingual:CODE); …`, worded like that of `--video`. Any case of letters: the items are lowered, the language code goes through `standard_code()` (language lower case, a two-letter region upper case, a script capitalised: `PT-br` → `pt-BR`, `zh-hans` → `zh-Hans`; YouTube's codes are written this way, checked on 164 codes in the test data), so no comparison against the data has to ignore case. A mutant `len(part) <= 3` survives on purpose: three-character regions are digits (`es-419`). Errors (argparse, before anything is fetched): empty item, unknown version (also `none`), `bilingual` without a language code, a code that is no language code (`check_code()`: `LANGUAGE_CODE` and yt-dlp's ISO 639-1 table or three letters, as `recognised_code()`; `jp` is not one), a language after `plain`/`timestamps`, a repeated item. The Command row of *About this copy* gives `--transcript` alone for `plain`, the versions otherwise, nothing without a transcript. `render_transcripts()` makes one section per item, in order (`render_transcript()`, class `transcript` or `transcript with-timestamps`; `render_bilingual_transcript()`, class `transcript bilingual`).
- `render_transcript()` puts each cue under the last chapter that starts at or before it (chapters from the chapter list described above; `<h3>` per chapter, empty chapters skipped). Without timestamps one `<p>` per part; with timestamps `<div class="cue">` rows.
- The cues are the caption lines, which is also how the panel divides the text; tiny differences to the panel are possible.

**Speaker changes.** YouTube's automatic captions start a new speaker's words with `>>` (`>>>` for a new topic), a convention of TV captions; translations do not have it. `speaker_html()` replaces each mark (`SPEAKER_RE`) with ours: in the timestamped and bilingual transcripts an empty `<span class="speaker" aria-hidden="true">` whose icon comes from CSS (`.speaker::before`: a speech bubble outline as an SVG `mask`, painted with `currentColor`, i.e. the grey `--muted`), and the translation of a cue with a mark gets one at its start too; in the continuous transcript a grey `<span class="speaker">|</span>` between spaces, left out at the start of a part (`at_start=False`). The cue data (and `--write-json`) keep YouTube's text. The lines under the video remove the marks (`textOf()` in `PLAYER_JS`).

## Images

- `fetch_image()` downloads with `urllib` (browser User-Agent, timeout, retries) and returns a `data:` URI; the MIME type comes from the response header or is sniffed from the bytes.
- Avatars are requested small: `=s88-...` in the URL is replaced by `=s{AVATAR_SIZE}`. They are downloaded in parallel (`ThreadPoolExecutor`).
- Each avatar is embedded **once** as a CSS class (`.av12{background-image:url(data:...)}`) and referenced by every comment of that author. The `<style>` in `<head>` is generated after the body, when all classes are known.
- A failed or missing avatar becomes a coloured circle with the first letter of the name (hue from a CRC32 of the name, so it is stable).
- The thumbnail falls back through `thumbnails` from best to worst if `thumbnail` fails.

## Text to HTML

`linkify()` escapes everything and recognises, in one regex pass: URLs (`http(s)://...`, `www....`; trailing punctuation and unbalanced `)`/`]` are cut off), timestamps `M:SS` / `H:MM:SS` (only valid values not longer than the video), `#hashtags` (not purely numeric), `@handles` (not inside e-mail addresses). Newlines are kept via `white-space: pre-wrap`.

## Theme

- All colours are CSS variables on `:root` (`--bg`, `--text`, `--muted`, `--panel`, `--line`, `--link`, `--chip`, `--media-bg`); the dark values are in `CSS`, the light ones (YouTube's light theme) in `LIGHT_VARIABLES`. New styles must use these variables, not fixed colours, or they break one of the themes. Exceptions that work on both: the red heart, the white letter on the coloured avatar circles.
- `theme_css()` adds, after `CSS`: nothing for `dark`; `:root{light variables}` for `light`; the same inside `@media (prefers-color-scheme: light)` for `auto`, so the page follows the device setting and changes with it, without JavaScript. `color-scheme` (CSS property and `<meta name="color-scheme">`) makes the browser draw scrollbars and the like in the matching colours.
- `--theme {auto,dark,light}` (any case: `type=str.lower`), default `auto`: the page itself follows the light/dark setting of whatever device or browser opens it, each time it is opened (in most browsers "device" means the system setting unless the browser's own appearance setting overrides it). Works with `--load-json` too (the theme is not stored in the data).

## Snapshot date

`render_page()` receives the date from `info["yt2html_archived"]` (today for older JSON files without it), so a page rebuilt with `--load-json` keeps the date of the original fetch. The `Snapshot` tile uses the class `fact extra` (grey value); `show_snapshot=False` (`--no-snapshot`) omits it. *About this copy* and the comments note always show the date.

## File names

`ydl.prepare_filename({**info, "ext": "html"}, outtmpl=OUTPUT_TEMPLATE)` — yt-dlp's own sanitizer, so characters forbidden on Windows are replaced exactly as in the video file name (e.g. `:` → `：`).

## Existing pages, `--overwrite`

- **One rule for files with an id** (`files_with_id()` / `file_with_id()`, since 0.7.0): in the output folder (not its subfolders), a file whose name contains `[ID]` anywhere (with the brackets, the whole id) and ends with the right extension, in any case; the rest of the name does not matter. Pages and indexes: `.html` (`existing_page()`), saved data: `.info.json` (`saved_data_path()`), videos: `VIDEO_EXTENSIONS` (`video_files_for()`). Several matches: the first by name, with a note printed once per folder, id and kind (`_SEVERAL_NOTED`). Before 0.7.0 the names had to end with `[ID].html` or `[ID].info.json`, and videos were only tried by exact names.
- A video counts as archived when the output folder holds such a page; pages may be renamed.
- The id is read from the URL without any request (`video_id_from_url()`: yt-dlp's `YoutubeIE.suitable()` / `extract_id()` for `watch?v=`, `youtu.be/`, `shorts/` and bare ids; the `v=` parameter for watch URLs with `&list=`, which yt-dlp gives to its playlist extractor). So a skipped video costs nothing. If the URL shows no id, the check is repeated after fetching, with `info["id"]`.
- Default: skip (`Skipped (page exists): ...`), and `archive()` returns `None`; `main()` counts saved, skipped and failed. `--overwrite` makes the page again; `--load-json` always does (no requests, and re-rendering is its purpose). A replaced page keeps its existing (possibly renamed) file name.
- Pages are written by `write_atomically()`: first `NAME.html.part`, then renamed (`os.replace`). An interrupted run leaves at most a `.part` file, which never counts as a finished page; a video that failed has no page and is tried again on the next run.

## Sources given by page names

`source_from_page_name()` turns a file name with an id in square brackets (`id_in_name()`: only the last path part counts, any extension, the last bracketed part that is an 11-character video id or a playlist id, so `Song [Remix] [ID] (copy).mp4` works and `[Remix]` is never taken for an id; not a URL) into the watch URL or the playlist URL; anything else stays as it is. `collect_sources()` applies it to the command line and to list files before removing duplicates, except with `--load-json` (see below).

## Sources with `--load-json`

- **Patterns:** `expand_pattern()` expands a source with `*` or `?` itself (Windows shells pass patterns on unchanged), sorted, in the command line and in `-a` files. Square brackets are made literal (`[` → `[[]`), since every page and JSON name ends with `[VIDEO_ID]`. A pattern without matches stays and fails as `no file matches ...`.
- **`saved_data_path()`**, in `archive()`: an existing file is used as it is (so nothing that worked before changes); otherwise a video id, or any file name with a video id in square brackets (`id_in_name(…, playlists=False)`), is looked up in the output folder (`-o`) as a `.info.json` file with `[ID]` in its name, where `--write-json` writes it. Failures say what was looked for: `no saved data for ID in FOLDER (looked for *[ID]*.info.json)`, `no such file: ...`.
- An id starting with `-` would be taken for an option; then give the file or page name.
- **One JSON option at a time:** `parse_args()` refuses `--write-json` with `--load-json` (the latter only reads; the file stays as it is). `--write-json` itself saves after a normal download (`rebuild()` in `archive()`), replacing an older file of the same name.
- **Comments at a rebuild** (`narrow_saved_comments()`): `--no-comments` leaves out the saved comments; `--max-comments N` keeps the first N in the saved order (yt-dlp's, replies counted), i.e. the comments a download with that limit gets, and sets the limit, so a cut after `Ctrl+C` counts as limited. A larger limit cannot widen the data: when the saved comments are limited or interrupted, a note says to download again. `--cookies-from-browser` has no effect and gets a note.

## Batch files (`-a`)

- `read_batch_file()` reads the file as UTF-8 (`utf-8-sig`, so a byte order mark from a Windows editor does no harm), strips each line and drops blank lines and lines starting with `#`. A file that cannot be read, is not UTF-8 or lists nothing is an error.
- `collect_sources()`, called from `parse_args()`, builds the final list: the URLs from the command line first, then each `-a` file in the order given. A video is kept once: two URLs are the same video if `video_id_from_url()` gives the same id (`youtu.be/ID`, `watch?v=ID`, a bare id); other lines (playlist URLs, `.info.json` paths with `--load-json`) must match exactly. It logs `Read N URLs from FILE (M duplicates ignored).` per file.
- Errors in the files themselves end the program through `parser.error()` (exit code 2) before anything is fetched. A playlist line is expanded like a playlist in the command (see *Playlists*); a bad line (wrong URL, channel) only fails that line in `main()`, like a bad URL on the command line.
- The file is only read, never changed: what is done follows from the pages in the output folder, so running the same list again archives what is missing and retries what failed.

## Playlists

- `playlist_id_from_url()` recognises `/playlist?list=ID` (also `m.youtube.com`, a trailing `/`) and bare playlist ids (yt-dlp's `YoutubePlaylistIE.suitable()`), without a request; watch URLs with `&list=` stay videos. `is_channel_url()`: anything else that yt-dlp's `YoutubeTabIE` handles (`@handle`, `/channel/`, `/c/`, their tabs); these fail with a hint to use a playlist.
- `fetch_playlist()`: `extract_info(url, download=False, process=False)` with `extract_flat: "in_playlist"` (and the cookies): only the list, no video is extracted; `process=False` avoids yt-dlp's `Downloading item N of M` line per entry. A `url` / `url_transparent` result is followed (up to 3 times); anything but `_type: playlist` is an error. The entries are read inside the `YoutubeDL` block, because yt-dlp fetches further pages (about 100 videos each) lazily.
- `entry_video_id()`: the entry's `id` if it is a video id, else the id in its `url`; nested playlists and channels give `None` and are left out. Private and deleted videos are entries too: they fail when fetched (`FAILED: URL`) and are retried on every run.
- `main()` expands each playlist where it stands among the sources into watch URLs and archives them one by one, exactly like separate URLs (skipping, failures, summary). `seen` holds the video ids handled in this run: a video twice in a playlist, in two playlists or also given separately is archived once (`Playlist "TITLE": N videos (M duplicates ignored).`, or `Ignored duplicate: URL` for a separate URL after the playlist). A playlist that cannot be read counts as one failure. The summary counts videos and is printed whenever a playlist was given.
- Nothing about the run is stored: the next run reads the list again (new episodes are found), skips the videos with a page and tries the rest again.

**Ctrl+C.** yt-dlp catches `Ctrl+C` while it downloads comments: it ends only the comments, keeps those fetched so far and sets `comment_count` to `None` (`comments_interrupted()`; with comments disabled there is no list). `archive()` still makes the page and then raises `CommentsInterrupted` (a `KeyboardInterrupt`), so a run with several videos does not go on with the next one. `main()` catches any `KeyboardInterrupt` between and during videos, prints the summary without a traceback and returns 130. The page made from interrupted comments counts as finished on later runs (`--overwrite` remakes it).

The page plays a downloaded copy of the video lying next to it. Parts: `PLAYER_TILE` (a `<button class="fact play">`, first in `.facts`, same size as the other tiles: value `▶ Play` / `✕ Close`, label `Player` until the script knows the file: then `labelTile()` writes YouTube's quality name and the language of the audio in the video, `1080p · en-US`. - **Tables:** size columns are right-aligned and never wrap (`class="size"`), the rest wraps; a table wider than the page scrolls sideways (`.formats`); an empty cell is a dash. From `formats` (`video_formats()`): video-only and audio-only formats without DRC variants (YouTube's *Stable volume*: a compressed copy of the same track); combined formats only when there is nothing else (storyboards drop out, having neither codec).
- **image:** one row per quality, i.e. YouTube's quality name and the frame rate, descending (`youtube_qualities()`: the number in yt-dlp's format note, `1080p`, `720p60`, `1080p Premium`; else the name of another format of the same size, since HLS formats have no note; else `quality_from_size()`: the shorter side, or 9/16 of the longer one when that is more, to the nearest step of `QUALITY_LADDER`, so a frame wider than 16:9 is named after its width as YouTube does, 1920×804 and 1080×1920 both `1080p`; else the height). A column `resolution` after it gives the real size (`1920×1080`; several sizes in one row joined by commas; an HLS-only row the HLS size). `quality_label()`: `1080p, 30 fps`; two rows when YouTube offers two frame rates at one height; a height only in HLS shows alone). A quality a download can take (up to `DEFAULT_MAX_HEIGHT`, with an ordinary AV1 or H.264 format: `RULE`) gets its parameter in brackets (`quality_parameter()`: `1080p, 30 fps (1080p30)`); higher qualities, vp9-only and Premium-only ones have none, since the download never takes them; × codecs (`codec_name()`: avc1→h264, av01→av1, vp9/vp09→vp9, hev1/hvc1→h265); the best format of each (the largest of alike formats), a dynamic range other than SDR, size with the main audio. Formats for Premium accounts (`is_premium()`: "Premium" in yt-dlp's format note) get their own columns after the ordinary column of the same codec (also in the audio table); kept on purpose, since sometimes they are the whole difference between data fetched signed in and not; never in the planned default. **HLS** formats (`is_hls()`: protocol `m3u8…`) have no size, only a declared bitrate, which proved far too high (3262 kbit/s against 276 kbit/s for the same 1080p h264 as one DASH file); they are only named, per height, in a last column *HLS (sizes unknown)*, and never used for sizes, the main audio (unless there is no other audio) or the planned default. Signed in, yt-dlp gets no HLS formats at all.
- **audio rows:** one row per track, i.e. language and role: columns `code` (first: the rows are in its order, and it is what `audio:CODE` will take), `language`, `role`, then aac and opus sizes; no caption hint (the table informs, it does not instruct). The language name (`language_name()`): yt-dlp's English format note of a single-file format of the track, its first part without ` original (default)` / ` descriptive` (`English (US) original (default), medium` → `English (US)`; a note that is only a quality word, such as `medium` for videos without dubs, gives no name); HLS notes are in the track's own language (`العربية - dubbed-auto`), so not used; else the name of the author's subtitles in that code (`Portuguese (Brazil)`, `Chinese (China)`; also for rows of subtitles alone); else YouTube's list of translation languages from the watch page (`yt2html_translation_languages`, full code, then the language alone); else the code. Audio formats without any language (seen on a TED talk: one track, no language in the data): `FormatChoice` takes `transcript_language()` (the watch page's default subtitles for the track, the same guess the *Transcript* row shows as "original language"), so the track's code joins the author's subtitles in one row; with nothing to go by it stays `UNKNOWN_LANGUAGE`. `download_video()` builds its `FormatChoice` with the page's `CAPTION_KEY` and `TRANSLATIONS_KEY` for the same guess. `subtitle_tracks()` lists codes alphabetically (console and `--video-formats`); a refused translation (429) ends with `TRANSLATION_HINT`, as for bilingual transcripts. The role is YouTube's kind of track (`audio_kind()`), which yt-dlp does not pass on but every format address carries in its `xtags` (`…&xtags=acont%3Ddubbed-auto%3Alang%3Dpl&…`, in HLS addresses a path part `/xtags/…/`): `acont=original` → *original*, `dubbed` → *dubbed* (by the author: YouTube's multi-language audio), `dubbed-auto` → *auto-dubbed* (YouTube's automatic dubbing), `descriptive` → *descriptive* (audio description); another value is shown as it is (`AUDIO_KINDS`). `xtags` is undocumented, so without it the role comes from yt-dlp's `language_preference`: 10 original, -10 descriptive; a video with a single language has nothing to mark it by, so that track is the original; otherwise *dubbed* when an original is known, else no role. In the console list (`--video-formats`) the tracks are grouped by role (original, dubbed, auto-dubbed, descriptive, other kinds by name, no role), then by language code; on the page they are ordered by language (see *languages*); one language may have two rows. A track without a language in the data (`UNKNOWN_LANGUAGE`, e.g. Shorts) has no code (`–`) and the name `unknown`; texts leave the language out (`sizes include the audio: aac`, `… av1 + aac, mp4`, `audio: original` in the summary), `--video-formats` says `unknown language`, and the player tile shows the quality alone. YouTube names some Shorts formats of 608×1080 `480p` (vp9 `779`/`780`, av1 `787`/`788`), so a row may have two resolutions (`480×854, 608×1080`). The main audio is the original's aac, else its other codec; without an ordinary (non-Premium) original, the largest ordinary track, an audio description only when there is nothing else.
- **languages** (one table for audio and subtitles, caption `languages`): the audio rows above, plus columns `subtitles by the author` (`subtitles` without `live_chat`) and `auto-generated subtitles` (yt-dlp's `-orig` tracks: made from one audio track's speech, so a dub has its own). Joining (`joined()`): the author's subtitles belong to the video, so they go to the row of the same code, else the only row of the same language (an audio description only when it is the only one); automatic ones go to their audio's row by language, or to the only audio track when its language is unknown; anything else gets a row of its own (code from the subtitles, name from the translation list, `–` for audio and sizes). A cell may list several codes (`es, es-ES`), each the code its parameter will take. Order (`language_order()`): languages with audio first, the original's language first, then the others alphabetically by language; within a language, audio rows by role (then code), then the subtitles' own rows; languages without audio at the end, alphabetically. The subtitles the transcript takes are not marked: no subtitles file is downloaded by default, and a mark will show only an actual choice (`sub:` with `--video`, yellow). Under the table, one line in four versions, always `machine-translated subtitles: …` (the label says subtitles, since an auto-dubbed track is a machine translation too): `possible in N other languages for each row with subtitles` (N: YouTube's list of target languages from the watch page, `yt2html_translation_languages`, given only for videos with subtitles, else yt-dlp's translation entries, minus the source; "for each row" so that it does not read as N more languages; YouTube translates any subtitles on request with `tlang`, nothing is stored per language); `none (no subtitles to translate)` (no subtitles at all); `unknown (YouTube listed no translation languages)` (subtitles, list read but empty: YouTube's side, trying again will not help); `unknown (not read from YouTube; make the page again later)` (subtitles, no list in the data: the watch page could not be read, or older data; technical, may pass). yt-dlp's own translation entries take the first automatic track as the source (for auto-dubbed videos a dub), so yt2html never uses them: translations are built from the original track, as for the transcript.
- **Choice and presentation are apart:** `FormatChoice` (made by `video_choice()`, None without video or audio formats) holds what a download can take, with no HTML: DASH and HLS formats, audio tracks (`track()`: language and `role_of()`), `original`, `main_audio`, `audio_for()`, `best()`, `quality()` (YouTube's names), `with_audio()` (size with the main audio) and `variants` (up to `DEFAULT_MAX_HEIGHT`, best first, each with height, fps, format, codec, quality label, parameter and size). `video_overview()` builds the tables, the summary and the console lines from it and adds each variant's place in the image table (`row`, `column`). `--video` is meant to take from `FormatChoice` directly (on a fresh list of formats).
- **The planned default** (what the download will take without parameters): the first of `video_overview()["variants"]`, i.e. the best quality up to `DEFAULT_MAX_HEIGHT` (1080p; highest frame rate first) that has AV1 or H.264, then AV1 there, else H.264 (never vp9 or Premium: the file is mp4 and plays everywhere), with the main audio, mp4. The quality comes first: 1080p only in H.264 beats 720p in AV1. Its cell is marked with `class="planned"` (text in `--planned`: light blue `#9cc3e8` in the dark theme, blue `#2f6a9e` in the light one; softer than links; yellow is reserved for what the user actually chose, once `--video` downloads), as is the main audio in the languages table; the captions carry no colour legend (README explains the colours; with `--video` blue would soon stop being the only mark). Without a main audio, or without an AV1/H.264 quality up to 1080p, nothing is marked and `--video-formats` has no `(default)`. Tests check the choice through `planned()` in `test_about.py` (the `(default)` line and the audio of the image caption). Later, with `--video`, yellow will mark the actual choice (what was asked for or downloaded) and blue stays for the default.
- Sizes (`format_size()`): `filesize`, else `filesize_approx`, else `tbr` × duration; `human_size()`: `~X.X GB` from 1 GB, `~N MB`, below 1 MB `<1 MB` (Shorts); escaped on the page (`&lt;1 MB`), plain on the screen.

### --video-formats

`list_formats()` instead of making pages (`main()` hands over before the loop): for each source, `fetch_formats()` (yt-dlp with `quiet`, no comments, no watch page; the download settings note Deno and browser cookies as in `fetch_info()`), or the saved data with `--load-json`; playlists and channels (by the URL, or a playlist answer from yt-dlp) fail with a message, as does a failed fetch; the run goes on and ends with exit code 1. `format_list()` gives the lines, printed to stdout with a blank line between videos: the title and id (with `--load-json` also `saved data of DD.MM.YYYY`); `image (mp4, AV1 else H.264; sizes include the audio: en-US aac):` (the same words as the section's image caption; without a main audio only `image (mp4, AV1 else H.264):`) and one line per variant, in aligned columns (quality, parameter in brackets, codec, size with the main audio, `(default)` for the first when there is a main audio), or `image: nothing a download can take (…)`; one layout for the audio: a header, then indented lines: `in the video: en-US (original)` (the main audio; its role in brackets, none when unknown), then the tracks a download can add (those with an ordinary aac format), one line per role in role order (`auto-dubbed: ar, bn, …`; `tracks:` without roles). Both headers follow one pattern: container and codec of what goes into the video, then after a semicolon the rest. The audio header: `audio (mp4, aac):` (the codec of the main audio, from the data: `opus` when the original has no aac), and when there are tracks to add `audio (mp4, aac; extra tracks m4a, aac, ~69 MB each):` (one size or a range `~60–70 MB`, `~900 MB–1.1 GB`; none when unknown); no size for the track in the video, since the image sizes include it. `audio: none` without audio (then there is no ordinary track to add either). Then the subtitles (`subtitle_tracks()`, what `sub:` can take): `subtitles (srt):` with `  by the author: …` and `  auto-generated: …` (no line on machine translation, no `(default)`: subtitles are taken only when asked; no wrapping of long lists), or `subtitles: none`. Without any video or audio format one line instead: `no video or audio formats in the data: YouTube sometimes sends none for a while; try again later`, with `--load-json` `…: YouTube sent none when the data was saved; make the page again with --overwrite`. How to ask for a track (`audio:CODE`) belongs to README and `--help`, not to the list. `fetch_formats()`, like `fetch_info()` for pages, asks yt-dlp for one format (`NO_MERGE_FORMAT`, `bv*/b/ba`, no merging), so yt-dlp does not warn about a missing ffmpeg, which only matters for a download; the formats in the data are the same either way. A note follows when Deno was missing for a fetch. `parse_args()` refuses the options that shape a page (`--overwrite`, `--index`, `--index-only`, `--write-json`, `--no-comments`, `--max-comments`, `--no-cards`, `--no-avatars`, `--transcript`, `--theme`, `--no-snapshot`); sources, `-a`, `-o`, `--load-json` and `--cookies-from-browser` stay.

### --video

`parse_args()`: `--video` with `nargs="?"` and `const=""`, parsed by `video_spec()` into `{height, fps, again, audio, subs, text}`: a quality from `QUALITY_LADDER` up to `DEFAULT_MAX_HEIGHT` as an upper limit (`720p`: any frame rate; `720p30`: at most 30 fps), `again` (download the files that are there again; named so as not to be mixed up with `--overwrite`, which makes the page again), any case; `audio:` and `sub:` items with their codes checked at once (`check_code()`), each once (`add_once()`: the same code and role or kind twice, or a code both alone and with a role or kind, is an error, since what was meant is not clear; two roles of one code are two tracks); anything else (also an address after a bare `--video`) is an argparse error that ends with "the video's address goes before --video" (README documents one form: `yt2html URL --video [PARAMETERS]`). Refused with `--load-json` (needs YouTube; the saved data are a snapshot, and `--load-json` never downloads), `--index-only` and `--video-formats`.

`main()`: `archive()` fills an `outcome` (the page's path; for a page made now also its data and `rebuild()`, which saves the JSON with `--write-json` and the page again with the images already downloaded); then `take_video()` calls `download_video()`:

1. a video file next to the page (`video_files_for()`, which leaves out yt-dlp's one-format part files `Title [id].f399.mp4`) → `Video skipped (file exists)` unless `again`, and the file goes into the result as found (`described()`, see 6); with no track or subtitles asked for, the result is returned at once, without asking YouTube for formats;
2. ffmpeg (`shutil.which`) → else `VideoSkipped` with `install_hint()` for the system; Deno and the age of yt-dlp (`yt_dlp_age()`, over `YT_DLP_MAX_AGE_DAYS`) → notes, once per run;
3. `fetch_formats()` (fresh: format addresses expire after hours) → `video_choice()` → `choose_variant()` (the first of `FormatChoice.variants` within the limit) and the main audio; nothing → `VideoSkipped`;
4. `yt_download()`: yt-dlp's `process_ie_result()` on the fresh data (as `--load-info-json` does, no second extraction) with `format` `VIDEO+AUDIO`, `merge_output_format` mp4, `outtmpl` the page's name, or with `again` the name of the mp4 that is there (`%` doubled, it is a template), `quiet` with `noprogress` off (only the progress bar, which yt-dlp erases when done), `overwrites` from `overwrite`;
5. extra audio (`audio:` in `video_spec()`: `(code written by standard_code(), role or None, text)`): `resolve_audio()` against `FormatChoice` (`tracks` in `track_order()`, `in_video`, `extra` = tracks with an ordinary aac format): the exact code, else a bare language finds its regional code (a code with a region never equals a bare language, so `de-AT` does not reach `de-DE`); without a role `AUDIO_PRIORITY` (dubbed, auto-dubbed), then other kinds, never `descriptive`, regional variants by code; with a role exactly it (the four `AUDIO_ROLES` or a kind of this video, else not recognised); codes come checked from `video_spec()` (`check_code()`: yt-dlp's ISO 639-1 table, `ISO639Utils.short2long`, `iw` yes, `jp` no, or three letters); a role neither among the four nor of this video is `not recognised`. Two items that give one track (`de` finding `de-DE` next to `de-DE`) are taken once, with `gives the same track as …; taken once`. Messages (`not recognised`, `not available`, `is already in the video`, `taken once`) in one line, then `Tracks to add:` (`extra_track_lines()`, the lines of `--video-formats`); the rest goes on. Each track: a file with the video's id and the track's ending (`file_by_suffix()` with `audio_suffix()`, so a renamed file counts) is kept and goes into the result as found, unless `again`, which downloads into it; else `audio_name()` (`Title [id].pl.dubbed.m4a`; without a role only the code) and `yt_download()` with the single format id (yt-dlp keeps its m4a; ffmpeg fixes the DASH container). The image is not needed for tracks: with a video file there and `audio:` given, the list is fetched anyway, and no image within the limit does not stop the tracks;
6. subtitles (`sub:` in `video_spec()`: `(code by standard_code(), kind or None, text)`, the kind checked at once against `SUB_KINDS`): `subtitle_tracks()` from the fresh data (the author's from `subtitles`, the automatic ones from yt-dlp's `-orig` tracks; only addresses on YouTube's subtitles service, `timedtext_url()`, so HLS playlists that yt-dlp lists as automatic captions and live chat drop out); `resolve_subs()` with the page's `CAPTION_KEY` and `TRANSLATIONS_KEY` (when the page was made now): `sub:CODE` tries author, auto-generated, translated (`SUB_KINDS`); codes as for audio; a translation is the transcript's track (`choose_caption_track()`) with `tlang`, not into its own language, and into a language in YouTube's list when the list is known; `not available` and `gives the same subtitles as …; taken once` messages with `subs_offer()`. Each file: as for tracks, a file with the id and the ending (`sub_suffix()`) is kept and described, else `sub_name()` (`Title [id].pl.translated.srt`), `download_srt()`: the track's json3 through `caption_data()` (shared with the transcript; `fetch_subtitles()` through yt-dlp's connection, since a bare request is refused as automated; a translation waits until `not_before`, `translation_wait()` after the list was fetched, and is asked for once), made into SRT by `json3_to_srt()`; an empty answer saves nothing; a failure is reported per file (`Subtitles FAILED: …`, a 429 with `TRANSLATION_HINT`; the run's exit code 1, and the next run with the same `--video` downloads the missing file) and the rest goes on. ffmpeg is checked only when the video or a track is to be downloaded. `json3_to_srt()` makes the SRT as YouTube does (`fmt=srt`): one cue per event with text (the `utf8` pieces joined, the ends trimmed, inner line breaks kept; events with only a line break skipped), from `tStartMs` for `dDurationMs`, numbered from 1, blocks separated by a blank line. Checked in November 2026 against YouTube's own SRT: the same cues (an automatic track with 1823 cues, two overlapping lines like on YouTube, without the repeated lines of its VTT; an author's track with 256); `test_online.py` compares them again;
6. the result (`VIDEO_KEY` `yt2html_video`: `date` of the run, `parameters`; `video`: file, size, and for a download its date, quality, codec, format ids, audio language and codec; `extra_audio`: language, role, file, size, and for a download its date and format id; `subtitles`: code, kind, file, size, and for a download its date and `source` for a translation). A file kept because it is there is an entry without a date, unless the saved data describe it: `archive()` reads the `.info.json` with the video's id before `--write-json` replaces it (`previous_video()`, kept in `outcome["previous"]`), and `described()` takes an earlier entry of the same kind with a date, the same size and the same code and role (kind) as the description, with the file's current name. `download_video()` returns the result, the fresh list (None when none was fetched) and whether anything was downloaded (else the video counts as skipped). For a page made now, `rebuild()` → `Updated page`, also when nothing was downloaded, so that `--overwrite --video audio:pl` keeps the switch of a track that is there; the fresh list replaces the formats when there is one. A page that existed before is not made again (the player finds the video by its name). The Video file row (`about_video_file()`): the entries with a date, grouped by day, `downloaded 12.11.2026: 1080p, 30 fps av1 + en-US aac, mp4, 293 MB; extra audio m4a: pl (dubbed), 69 MB; subtitles srt: en (author), pl (translated from en)` (no sizes for subtitles), then those without, `next to the page: video NAME, SIZE; extra audio m4a: …; subtitles srt: pl (translated)` (the video found when the page is built counts here when the data has no video with a date), else `not downloaded`. Yellow: the image cell and audio cell by the video's format ids, the tracks by their format id, or, when only found, the aac cell of their track (code and role are certain, the format is not); the subtitles' codes by code and kind; translations, which have no cell, follow the line on machine translation: `; downloaded: pl (from en)` (one source: the transcript's track; without a known source no `from`); a video only found has no yellow.

`VideoSkipped` and yt-dlp's errors are reported (`Video skipped: …`, `Video FAILED: … The page is saved; …`) and counted (`Videos: N downloaded, N skipped, N failed` after `Done:`; a failure gives exit code 1); `Ctrl+C` stops the run as usual (yt-dlp resumes its `.part` files). Between videos: `random.uniform(*PAUSE_SECONDS)` (5–15 s) before a video that follows one which asked YouTube for formats (`notes` "requested"), so a run over archived videos does not wait. Marks: `formats_table()` gets `chosen` cells (class `chosen`, `--chosen` yellow `#ffd54a` / `#9a6700`), from `VIDEO_KEY`'s format ids; yellow wins over blue in one cell. The Command row of *About this copy* gives `--video` with its parameters, without `again` (see *About this copy*).

## About this copy

The folded `<details class="copy-info">` at the bottom of every page (it replaced the footer). Folded, it shows `About this copy · Snapshot DD.MM.YYYY · made with yt2html`, the same for every copy; opened, only `About this copy` stays (CSS rule for `details[open]`, no script). Built by `render_about()` from one function per row (`about_*()`).

Rows describe the page as it is, as if it had been made in one go with the Command row's command: a rebuild shows up only in *Page built* (and in Command), never as "downloaded N, shown M". Rules: it describes what makes **this** copy differ from another copy of the same video (settings, moment, failures), and only failures that did not stop the page; **every row is always there**, in a fixed order, one line each, with a short comment when there is nothing to report. Fixed words for states: *left out* (by an option), *none* (the source has none), *could not be read / downloaded* (an error), *may lack* (unknown whether it existed). The Command row is the one deliberate exception to "no option names on the page".

## Page metadata and the index (`--index`, `--index-only`)

**Metadata.** Every video page has invisible `<meta name="yt2html:...">` tags in its `<head>`, before the large `<style>` (`page_metadata()`): `video-id`, `title` (the original title), `archived` (ISO date), `comments-status`, `comments-downloaded`, `comments-youtube` (the text of the Comments tile). `comment_status()`: `not-downloaded` (no `comments` key: `--no-comments`), `turned-off` (`comments` is `None` and the watch page had YouTube's message in place of the comments, `yt2html_comments_message`), `unavailable` (`comments` is `None` without such a message), `interrupted` (`comments_interrupted()`), `limited` (`--max-comments` reached while YouTube shows more), otherwise `complete`. A failed comment download fails the whole video, so it never produces a page. `read_page_metadata()` reads only the first 16 KB of a page.

**Building an index.** `write_indexes()` runs at the end of `main()` (also after `Ctrl+C`; with `--index-only` instead of archiving) for each playlist URL given in the command and each `-a` file (`args.command_sources`, `args.batch_lines`, kept by `collect_sources()`). Nothing is taken from a log; an index is built from:

- the list: a playlist's flat entries read in this run (`Run.playlists`, filled by `read_playlist()`), else the list kept in the earlier index; for a list file its lines (`list_file_sections()`: one section per playlist line, one per run of other lines; a video listed twice appears once);
- the pages in the output folder, found by `existing_page()`, and their metadata (title, date, comments);
- `Run.attempted` and `Run.failures` (video id → `failure_reason()`, e.g. `Sign in to confirm your age`).

`entry_status()`: `archived` (a page exists), `not-a-video` (no video id), `unavailable` (playlist entry titled `[Private video]` / `[Deleted video]` or `availability: private`), `failed` (failed in this run), else the earlier index's `failed`/`unavailable` with its reason if the video was not tried in this run (`with_earlier_status()` merges them into freshly read lists), else `pending` (`Not archived yet`).

**Keeping the list.** The index stores what `--index-only` needs as `data-*` attributes (no JavaScript): `<section data-section data-playlist-id data-title data-url data-fetched data-unread>` and `<tr data-id data-url data-title data-status data-reason>`. `read_index()` (an `html.parser.HTMLParser`) reads them back. With `--index-only` a playlist without an earlier index is read with `fetch_playlist()` (only the list); an unreadable playlist in a list file becomes a section marked `not read yet`.

**Page.** `render_index()`: `<main class="page index">` (max. 960 px), title (playlist title linking to YouTube, or the list file's name), grey `N of M videos archived · Updated DATE`, one `<table class="index-table">` per section without visible lines: position (playlist rows by position in the playlist, other rows numbered across the list file), title (link `urllib.parse.quote(page.name)`, so `#`, spaces and Unicode work; grey without a page) with the comments line (`comments_summary()`), date or grey reason (`title` attribute with the failure message), YouTube link. Same CSS and themes as video pages. File names: playlist `output_path({"title", "id": PLAYLIST_ID})`, i.e. `Title [PLAYLIST_ID].html`, or the existing file ending with `[PLAYLIST_ID].html`; list file `STEM.html`. Written atomically.

## Testing

**Run the tests after every change**, in the project folder:

```powershell
uv run pytest
```

The first run installs pytest into the project's `.venv` (the `dev` dependency group in `pyproject.toml`; it is not part of the installed program). The offline tests use only synthetic data shaped like the real structures (`conftest.py`): builders such as `marker_panel()`, `player_bar()`, `people_item()`, a full `info` fixture, and `FakeYDL`, which answers caption and translation requests (also with HTTP 429 or empty answers).
