# Development notes

How `yt2html` works, where it takes its data from, and how to test and release it. For using the program see [README.md](../README.md); for the history of versions see [CHANGELOG.md](../CHANGELOG.md).

YouTube does not document the page data the program reads. The paths below were checked on real pages (reference videos in the sections and in `tests/test_online.py`); when YouTube changes something, this document says where to look.

## Working on the project

Requirements: [uv](https://docs.astral.sh/uv/) and git.

```powershell
git clone https://github.com/mwislowski/yt-video-archiver
cd yt-video-archiver
uv sync                                   # creates .venv with the project and pytest
uv run yt2html.py --version               # run from the source folder
uv run pytest                             # tests
```

To use the source folder as the `yt2html` command everywhere, install it *editable* (changes to `yt2html.py` work at once):

```powershell
uv tool install --editable PATH\TO\yt-video-archiver
```

An editable install changes the everyday command with every edit, experiments included. For a stable everyday command, install a release instead and work on the code with `uv run yt2html` in the project folder:

```powershell
uv tool install git+https://github.com/mwislowski/yt-video-archiver@v0.11.0         # a tested release
uv tool install --force git+https://github.com/mwislowski/yt-video-archiver@v1.0.0  # later: switch to a newer one
```

After a change in `pyproject.toml` (dependencies, command) add `--reinstall`. To update yt-dlp in the project: `uv lock --upgrade-package yt-dlp`, then `uv sync`, and commit the updated `uv.lock`.

`.gitignore` excludes `.venv`, the test cache (`.pytest_cache/`), build output (`build/`, `dist/`), `*.html`, `*.html.part` and `*.info.json` (pages created when the command is run in the project folder), and `*.local.md` (private notes, kept only on this computer, so without a copy on GitHub). The repository contains only code, configuration and documentation, never archived pages.

## Version, packaging, releases

- **One source of the version:** `__version__` in `yt2html.py`. `pyproject.toml` has `dynamic = ["version"]` and `[tool.hatch.version] path = "yt2html.py"`, so the package version and `yt2html --version` always agree. `--version` prints it together with the yt-dlp version (most problems come from an outdated yt-dlp).
- **Versioning:** the second number for new features or visible changes (0.2.0, 0.3.0), the third for fixes (0.2.1). What changed in each version is in [CHANGELOG.md](../CHANGELOG.md).
- **Command:** `[project.scripts] yt2html = "yt2html:main"`; the wheel contains only `yt2html.py` (`[tool.hatch.build.targets.wheel] only-include`). `main()` returns the exit code, which the generated command passes on.
- **Release:** run the tests (also `--online`), change `__version__`, move the *Unreleased* entries in `CHANGELOG.md` under the new version with its date (and update the compare links at the bottom), commit, then `git tag -a vX.Y.Z -m "..."`, `git push` and `git push origin vX.Y.Z`. The changelog entries can serve as the GitHub release notes.

## Conventions

- **English everywhere in code:** identifiers, comments, CLI options, program messages, fixed page labels and invisible HTML (classes, ids, meta tags). Only the archived content itself is in its original language.
- **Configuration in constants at the top of `yt2html.py`** (`DEFAULT_OUTPUT_DIR`, `OUTPUT_TEMPLATE`, `DATE_FORMAT`, `THOUSANDS_SEPARATOR`, `AVATAR_SIZE`, `IMAGE_WORKERS`, ...); per-run choices are CLI options.
- **One output file, works without JavaScript.** Static HTML + CSS; every image is a `data:` URI. The page must work when opened from disk with no network. The only script is the built-in player (`PLAYER_JS`), which adds something and never replaces content; the index has its own player script (`yt2html_index.PLAYER_JS`), likewise: without it the index is a plain list.
- Program messages are prefixed with `[yt2html]`; yt-dlp prints its own `[youtube]` progress lines.
- A failure for one URL does not stop the others; the exit code is 1 if anything failed.

## The command line

`parse_args()` turns the command into the attributes the rest of the program reads; the rules are the user's (24.11.2026, his notes 5.8), and README's *How the options work* states them for users.

- **One option per kind of file:** `--page` (the page), `--transcript` (the transcript and its SRT files), `--video` (the video and its audio tracks), `--json` (the saved data). Each takes one value with comma-separated parameters, any case, and may be given once: `Once` (an `argparse.Action`) makes a second one an error (`--page is given more than once; put all its parameters in one, comma-separated`), where argparse would silently keep the last. The old options are gone without other names, so an old command ends with argparse's `unrecognized arguments` (the user: clean changes, nothing old interpreted).
- **`--page`** (`nargs="?"`, `const=""`): `page_spec()` gives `{ovr, comments, snap, cards, avatars, theme, given}` (`comments`: `None` for the default, `"no"`, `"all"` or a number, `0` too; `yes|no` for the switches, `ovr` without a value; each parameter once); `apply_page_spec()` sets the old internal attributes from it: `overwrite`, `no_comments`, `max_comments` (a limit given on purpose, which also narrows saved comments), `comment_limit` (the download's: `DEFAULT_COMMENTS` = 1000 when not given, `None` for all), `no_snapshot`, `no_cards`, `no_avatars`, `theme`. `comments:0` and `comments:no` both ask YouTube for no comments (yt-dlp's `islice(…, 0, 0)` never starts the comment requests), but `0` keeps the section with YouTube's count and the status `limited`, `no` leaves the `comments` key out (`not-downloaded`).
- **`--json`** (one parameter, `json_parameter()`): `apply_json_parameter()` sets `write_json` (`write`), `update_json` (`write` without `ovr`: add to saved data where there are any), `refresh_json`, `load_json`, `merge_json`.
- **`--transcript`** (`transcript_spec()`, below in *Transcript*): a list of `(version, token)`; `ovr` and `srt` come out of it as `transcript_ovr` and `transcript_srt` (`srt` stays in the list, the versions use it); **`--olang`** (`olang_code()`).
- **`--video`** (`video_spec()`, *--video* below); **`--take`** (`take_value()`, *Playlists* below); **`--cookies`** (`cookies_argument()`, the only name since the options' change; the data key `cookies_from_browser` stays).
- **Contradictions** are `parser.error()` before any request: `--page ovr` with `--json load` or `refresh` (everything from YouTube against the saved data; `merge` refuses `--page` anyway), `--transcript ovr` without `--json write` or `refresh`, `--olang` with `load` or `merge`, `--take` with `load` or `merge`, `--video` with `load`, `--json merge` with `--video`, `--page`, `--transcript` (with the `--json load` command that shows the translation), `--index` or `--index-only`, `--video-formats` with anything that makes a page, `--index-only` with `INDEX_ONLY_REFUSES` (`--video`, `--transcript`, `--json`, `--page`, `--olang`, `--take`). A request without effect is no error (`ovr` with nothing there). `--cookies` with `load` or `merge` gets a note.
- **One folder** (`placed_source()`, in `collect_sources()`): a source that names a file (not an address, a video or playlist id, a channel) is taken in `-o` when it is a bare name, and is an error when its folder is another (`same_folder()`: `os.path.samefile()`, or for a folder not there yet the resolved paths through `os.path.normcase()`, so case, `.\` and `..` do not matter): `… is not in the output folder (…); the pages, their data and files stay in one folder: add -o "…" or give the name only`. Before, a page given with a path was read there while the new page went to `-o`, so a second page could appear. Saved data are only names ending in `.json` (`saved_data_path()`), so a page's name is never read as data.

## How the data is obtained

`yt_dlp.YoutubeDL(...).extract_info(url, download=False)` with:

- `skip_download`, `noplaylist`, `getcomments`;
- `extract_flat: "in_playlist"`: a safety net. `noplaylist` only turns watch URLs with `&list=` into the video; an unrecognised URL that leads to a playlist or channel would otherwise be extracted video by video, comments included. With it, yt-dlp returns only the flat list, and `archive()` fails with `this URL leads to a playlist or channel`. Playlist URLs never get here (see *Playlists*), channel URLs fail before any request (`is_channel_url()`);
- `ignore_no_formats_error: True` — the video is not downloaded, so missing formats (e.g. when no JavaScript runtime is installed for YouTube's player challenges) must not abort the run;
- `extractor_args = {"youtube": {"comment_sort": ["new"], "max_comments": [N or "all", "all", "all", "all"]}}`.

Then, in the same `YoutubeDL` instance (same cookies and consent), the watch page is fetched once more with `ydl.urlopen()` for the timestamp lists and the description extras (see below). The program adds keys of its own to the info dict (constants `*_KEY` at the top of `yt2html.py`), all kept by `--json write`, among them: `yt2html_archived` (ISO date of fetching), `yt2html_marker_lists`, `yt2html_description_extras`, `yt2html_channel_avatar` (the avatar URL, see *The page, part by part*), `yt2html_youtube_comment_count` (the comment count text from the comments panel header, `engagementPanels[]` with `panelIdentifier` `engagement-panel-comments-section` → `header.engagementPanelTitleHeaderRenderer.contextualInfo`), `like_count` when yt-dlp has none (`like_count()`, below), `yt2html_comments_message` (YouTube's message in place of the comments: `contents.twoColumnWatchNextResults.results.results.contents[]` → `itemSectionRenderer` with `sectionIdentifier` `comment-item-section` → `contents[].messageRenderer.text`, the runs without a link, so `Comments are turned off.` without *Learn more*; seen on `okT1dSP6gQQ`, 13.11.2026, where the comments panel and its count are missing; `null` when the section holds comments) and `yt2html_max_comments` (the download's comment limit, `comment_limit`: 1000 by default, `null` for `comments:all`).

**Likes.** yt-dlp reads `like_count` only from the like button's spoken label (`like this video along with 1,234 other people`), which has no number when nobody has liked the video yet, so it gives `None` for zero likes, the same as for a count the author hid. `add_watch_page_data()` fills it, only when yt-dlp left it `None`, from the player data: `like_count()` takes `microformat.playerMicroformatRenderer.likeCount` (a string of digits, `"0"`). With a hidden count the field is absent (`videoDetails.allowRatings` is `false`, the button's `likeCountEntity` is empty), so `None` stays and the tile shows `—`. Seen on two pages saved from a browser on 20.11.2026: `vNCutsX1MgQ` (0 likes: `likeCount` `"0"`, `allowRatings` `true`) and `KmcZktECUYQ` (likes hidden). The value goes into the saved data like yt-dlp's, so `--json refresh` takes a fresh `0` too; a count hidden after the download leaves the saved one (as any count YouTube does not send).

**A video YouTube refuses** (removed, its account terminated, private): with `ignore_no_formats_error` yt-dlp only warns and returns an empty shell (title `youtube video #ID`, nothing else), which used to become an empty page. The refusal is in the watch page's player data: `playability_refusal()` takes `ytInitialPlayerResponse.playabilityStatus` when its `status` is not `OK` and there is no `videoDetails`, and `add_watch_page_data()` raises it as `VideoUnavailable(status, reason)` right after reading the player data, before anything else. The text joins `reason` and the error screen's description (`errorScreen.playerInterstitialRenderer.content.interstitialViewModel.description.content`) when they differ, which gives the texts yt-dlp prints: `Private video. If the owner of this video has granted you access, please sign in.` (`LOGIN_REQUIRED`), `Video unavailable. This video is no longer available because the YouTube account associated with this video has been terminated.` (`ERROR`), `This video has been removed for violating YouTube's Terms of Service` (`ERROR`, the description repeats the reason). These real responses (17.11.2026) are the test data in `tests/data/gone_playability.json`. `VideoUnavailable.gone`: `ERROR` except a reason with `try again later`, and `LOGIN_REQUIRED` with `Private video` (user's decision 17.11.2026, variant a: YouTube's own class, so also kinds not seen yet; `status` is read silently, the user sees only the text); other refusals (`not a bot`, sign in for the age, try again later) may not last. On a download or `--page ovr` any refusal fails the video (`FAILED: SOURCE: TEXT`), nothing written; `--json refresh` handles it (see *Sources with …*). A watch page that cannot be read at all hides a refusal (the shell is then saved as before). An age-restricted video without cookies is no refusal: its watch page has `LOGIN_REQUIRED` *Sign in to confirm your age* but keeps `videoDetails` (no `streamingData`, no `captions`), and yt-dlp gets its formats through its `web_embedded` client (seen 19.11.2026 on `6Ib4MxtHFFM`, the test data `tests/data/agegate_playability.json`; the page is made as by 0.9.3, `--json refresh` refreshes it as usual).

Why the program reads the comment count itself: when yt-dlp downloads comments, it **replaces** `comment_count` with the number of comments it downloaded (and sets it to `null` after `Ctrl+C`). So with `--page comments:50` yt-dlp's `comment_count` is 50. `youtube_comment_count()` therefore uses the page's count; without it, yt-dlp's `comment_count` is used only when it can be trusted (comments not downloaded, or downloaded completely without a limit).

Used fields: `id`, `title`, `webpage_url`, `uploader`, `uploader_url`, `channel_is_verified`, `channel_follower_count`, `view_count`, `like_count`, `comment_count`, `duration`, `release_timestamp` / `timestamp` / `upload_date`, `thumbnail`, `thumbnails`, `description`, `chapters` (fallback only), `comments`.

Each comment: `id`, `parent` (`"root"` or the parent's id), `text`, `author`, `author_url`, `author_thumbnail`, `author_is_uploader`, `author_is_verified`, `like_count`, `is_pinned`, `is_favorited`, `timestamp`, `_time_text`.

## Comment order

- yt-dlp emits comments depth-first: a top-level comment, then its replies, then the next top-level comment.
- With `comment_sort=new` the top level comes **newest first** in YouTube's exact order; the program reverses it. The pinned comment arrives first regardless of its age.
- Replies come in YouTube's thread order, which is oldest first.
- YouTube gives only relative times (`2 years ago`), so `timestamp` is a coarse estimate. `chronological()` does a **stable** sort by it: the exact order from YouTube is kept within equal estimates, and only items whose estimate clearly disagrees (the pinned comment) move. Missing timestamps inherit the previous item's value.
- Then `build_comment_tree()` puts the pinned comment (`is_pinned`, only top level) first, as YouTube shows it and as its author means it (the user, 20.11.2026; before, it stood in its place in time, often last). One YouTube no longer sends (`MISSING_SINCE_KEY`, after `--json refresh`, e.g. when the creator pinned another one) stays in its place in time with its *Pinned by* mark, a trace of the past, so two pinned comments are never both on top. No data change: a page made again from saved data gets the new order.
- Comments whose parent is missing are shown at the top level. Deeper nesting (if YouTube ever returns it) is rendered recursively.

## License

- On YouTube the license is a row of the video's metadata (`videoSecondaryInfoRenderer.metadataRowContainer.metadataRowContainerRenderer.rows[].metadataRowRenderer` with `title` `License`), not part of the expanded description's *Video details* list. It exists only for non-standard licenses. Reference video `KZtvWKpXPro`: `Creative Commons Attribution license (reuse allowed)` → `https://www.youtube.com/t/creative_commons`.
- `parse_license()` keeps the text runs and their web links (`navigationEndpoint.urlEndpoint.url`; YouTube `/redirect?q=` links are unwrapped by `unwrap_redirect()`). Stored in `info["yt2html_license"]` as `{title, runs: [{text, url}]}`, `None` when the video has none.
- `license_of()`: if the watch page could not be read (or for an older JSON file), yt-dlp's plain-text `license` field is used instead, without the link.
- Rendered after the transcript, before the comments, as `<section class="desc-extra license">`.

## Chapters and other timestamp lists

Everything is read from `ytInitialData` of the watch page, downloaded once more by `add_watch_page_data()` (`/watch?v=ID&hl=en`), which also reads the description extras above; the JSON after `ytInitialData =` is parsed with `json.JSONDecoder().raw_decode()`, which stops exactly at the end of the object. yt-dlp is not used for this: it keeps only one list as `chapters`, without its name or origin, and when the progress bar has no chapters it takes the first panel, which can be *Walkthroughs*.

Two places in `ytInitialData` hold timestamp lists:

| Place | Path | What it says |
|---|---|---|
| Progress bar | `playerOverlays.playerOverlayRenderer.decoratedPlayerBarRenderer.decoratedPlayerBarRenderer.playerBar.multiMarkersPlayerBarRenderer.markersMap[]` | `key` = `DESCRIPTION_CHAPTERS` or `AUTO_CHAPTERS`; `value.chapters[].chapterRenderer` with `title` and `timeRangeStartMillis`. The older `chapteredPlayerBarRenderer.chapters` (no key) is read too. |
| Engagement panels | `engagementPanels[].engagementPanelSectionListRenderer` with `content.macroMarkersListRenderer` | `panelIdentifier` and header title; items `macroMarkersListItemRenderer` with `title`, `timeDescription` and `onTap.watchEndpoint.startTimeSeconds`. Info rows (`macroMarkersInfoItemRenderer`, e.g. "These chapters are auto-generated") are skipped. |

Panel identifiers seen so far (04.11.2026): `engagement-panel-macro-markers-description-chapters`, `engagement-panel-macro-markers-auto-chapters` (both titled `Chapters`) and `engagement-panel-macro-markers-problem-walkthroughs` (`Walkthroughs`; the progress bar has no markers for it). Reference videos: `Z8lf5oWKfj0` (description chapters), `qyqCTMirNWg` (auto chapters), `hz6-3-7GGyI` (Walkthroughs only).

`parse_marker_lists()` builds the lists:

- **Chapters** (panels whose id contains `chapters`, plus the progress bar): the progress bar defines the chapters and their times (a chapter panel is used only when the bar has none); the panel gives the heading. Shown first, as one list.
- **Origin** (`decide_chapter_source()`): YouTube's own markings (progress-bar key and panel id) are combined with an independent check of the description (`description_chapter_starts()`: the run of consecutive timestamped lines beginning with the first `0:00` line, at least three, ascending, each chapter at least 10 s — YouTube's rules).
  - YouTube says *description* and the description has a valid list with the same start times → `description`.
  - YouTube says *auto* and the description has no valid list → `auto`.
  - Anything else — markings that disagree with each other or with the description, or an unknown key/panel id → `uncertain`: neutral heading, warning `Chapter source unclear: ...` on screen, the reason kept in `source_problem`. The program never guesses an origin.
- **Other panels** (e.g. Walkthroughs): as they are, `source: null`, in page order after the chapters.

Stored in `info["yt2html_marker_lists"]` as `[{id, title, source, source_problem?, items: [{start_time, time_text, title}]}]`. `None` means the extra request failed: the page then falls back to yt-dlp's `chapters` under a neutral `Chapters` heading (it may even be a Walkthroughs list). An empty list means the video has none.

Rendered after the description as `<section class="markers">` with an `<ol>`, one row per item; the origin note is `<span class="source">` (grey) in the heading, using the labels in `SOURCE_NOTES`.

## Transcript

- YouTube's own transcript panel loads its text from `/youtubei/v1/get_transcript` (parameters in `engagement-panel-searchable-transcript`). Checked on 05.11.2026: a request built outside the browser is refused (`400 Precondition check failed`); the browser sends extra integrity data that only YouTube's own JavaScript produces. So the program does not use it.
- The panel shows the text of a caption track, so `fetch_transcript()` downloads that track instead, from the URLs yt-dlp has already extracted (`info["subtitles"]`, `info["automatic_captions"]`; yt-dlp also deals with tokens YouTube may require for captions). Format `json3`, read with `ydl.urlopen()`.
- Track choice: the panel opens with the caption track of the **original audio**, which matters for auto-dubbed videos. They have one audio track per dubbed language and automatic captions for each of them, and yt-dlp marks every one of those with `-orig` (reference video `Z8lf5oWKfj0`: English original, 20 dubs; taking the first `-orig` track gave Arabic).
  - `default_caption_track()` reads `ytInitialPlayerResponse` from the watch page: `captions.playerCaptionsTracklistRenderer.audioTracks[defaultAudioTrackIndex]` is the audio the player starts with, usually the original (not always: below); its `defaultCaptionTrackIndex` points into `captionTracks` (language and `kind: "asr"` for automatic captions). Without that index, the language of the audio stream whose `audioTrack.displayName` contains `original` (`page_original_language()`, below) is used, else the audio track's id, else its first caption track. Stored as `info["yt2html_default_caption_track"]` = `{language, kind: "asr" | "manual" | null}`.
  - **The original audio as the page marks it** (`page_original_language()`, stored as `info["yt2html_original_audio_language"]`, `ORIGINAL_AUDIO_KEY`, one of `PAGE_KEYS`: `None` when the page was not read or had no player data): `streamingData.adaptiveFormats[].audioTrack` whose `displayName` contains `original` and not `descriptive` (the page is asked for with `hl=en`: `Polish original`), its language the part of its `id` before the dot (`pl.4` → `pl`). This is yt-dlp's own rule for `language_preference` 10 (`get_language_code_and_preference` in `yt_dlp/extractor/youtube/_video.py`), kept apart because yt-dlp's formats can come without any audio track: when YouTube asks to confirm one is not a bot, yt-dlp may get only format `18` and storyboards (`imRB4Y2ShoM`, 23.11.2026; the page saved in a browser has both tracks, `tests/data/dubbed_player_response.json`). The end of the id (`.4` original, `.10` auto-dub, seen on two videos) is undocumented and not used. `None` also for a video in one language (no track is called original).
  - **The page's default can follow a dub** (`8etkFuBLGZ0`, 20.11.2026: Polish original, an English auto-dub; for yt-dlp's English request the page started with the dub and named its English automatic captions default, so the transcript, its *original language* label and `yt2html:language` were English). `transcript_language()` therefore takes the audio marked as the original (`marked_original_language()`: in yt-dlp's formats `language_preference` 10, or `acont=original` in the format address, `audio_kind()`; else the page's mark, `ORIGINAL_AUDIO_KEY`) when the page's default names another language; the default stands when it agrees (`en` with an `en-US` original) or nothing is marked (one audio language). Everything that uses this choice follows: the transcript and its *original language* label when downloaded, the page metadata, the source of the translations. A transcript already in saved data stays as it is (`--json load` does not download it again; `--json write` and `--json refresh` do not judge its language again); `--page ovr --transcript` downloads it again, and so does `--transcript ovr` with `--json write`. Fresh yt-dlp data (`--json write` downloading a whole transcript, `--video`) get the page's `CAPTION_KEY`, `ORIGINAL_AUDIO_KEY` and `TRANSLATIONS_KEY` from the saved data or the page made now (`with_page_choices()`, `PAGE_CHOICE_KEYS`).
  - **When the original stays unknown** (`original_uncertain()`: nothing marked, neither in the formats nor on the page, and more than one `-orig` automatic track, i.e. the video has dubs and YouTube recognised speech in each): the choice is made as before (the page's default captions, possibly a dub's), but not silently. `archive()` logs `uncertain_warning()` after saving the page (`Warning: the original language is uncertain: YouTube sent no audio tracks to tell it from the dubs, so the transcript and the page's language are taken as 'en' (…). Make the page again later; if YouTube asked you to confirm you're not a bot, try with --cookies.`; "the page's language" alone without a transcript; the advice does not promise cookies help); the page shows `uncertain_note()` (class `note uncertain`, `--muted`) under the first transcript heading only, without option names; the transcript is not called original: `fetch_transcript()` saves `original: false`, and the *Transcript* row says `original language unknown` also for data saved before (it checks `original_uncertain()` at render time). A single `-orig` track (no dubs) gives no warning. The page metadata (`yt2html:language`) keeps the guess (the user's decision 23.11.2026: the page is made as before); the index can override it with `= !lang:`. Rejected: no page at all for data without audio tracks (premieres and unavailable videos have none by nature).
  - `choose_caption_track()` then picks from yt-dlp's tracks in that language: automatic captions first if the page says `asr` for that language (not when the original won over a dub's default), otherwise author subtitles first (`en`, `en-US`, ...), then automatic captions (`<lang>-orig`, `<lang>`). Without page data the original language comes from yt-dlp's formats (`language_preference` 10 = original), then `info["language"]`, then a single `-orig` track; with none of these, any author subtitles. `live_chat` is ignored; translated tracks are never used.
- `parse_json3_captions()`: one cue per json3 event with `segs`; the `utf8` pieces are joined, line breaks and repeated spaces become single spaces; events holding only a line break (automatic captions add them) are skipped. Cue start = `tStartMs` / 1000, end = start + `dDurationMs` / 1000 when the event has one (zero too, as YouTube's own SRT; data saved before have no end: the next cue's start, the last cue 5 s).
- Stored in `info["yt2html_transcript"]` as `{language, name, kind: "manual" | "auto", original, cues: [{start, end?, text}], translations?: {LANG: {language, name, cues}}, own?: {LANG: {language, name, cues, own: {file, date}}}, tracks?: {"LANG.author" | "LANG.auto-generated": {language, name, kind, cues}}}` (`translations` are YouTube's, `own` the translations of one's own from `--json merge`, below, so one language can have both since 25.11.2026; data saved before keep one's own among `translations`, marked `own`: `translations_of()` leaves them out, `own_of()` takes them, `set_own()` moves one to `own` when it is written, and `add_translations()` before YouTube's goes into its place; `tracks` are subtitles of their own in other languages, below); `missing?: {KEY: {reason, refused, date}}` (a translation `LANG` or subtitles `LANG.author` YouTube did not have, `refused: false`, or did not send, `refused: true`, which `--json write` asks for again; `date` of that attempt, shown in *About this copy* for a refusal: `(YouTube refused to send it (…), 20.11.2026)`, `missing_text()`); `None` if the video has no transcript (the reason in `yt2html_transcript_missing`); absent without `--transcript` (nothing is downloaded). The cues are kept, so `--json load` can rebuild the page with any versions (without `--transcript` there a saved transcript is left out; a version needs its source in the data, or a reason in `missing`, else `TranscriptError` and nothing is written).
- **Versions** (`transcript_spec()`): `--transcript [VERSIONS]`, like `--video`: `nargs="?"`, `const=""` (the option alone: `[("plain", None)]`), default `[]` (no transcript: `fetch_info()` downloads none); one comma-separated argument, parsed into an ordered list of `(version, token)` pairs: `plain`, `timed`, `dual` with a token `None` (the original) or `CODE` or `CODE.KIND` (`SOURCE_KINDS`: `author`, `auto-generated`, `translated`, `own`; `split_code()`), plus `("ovr", None)` and `("srt", None)` (`ovr` or `srt` alone also mean `plain`). `dual` needs a code and takes only `translated` or `own` (it puts the translation of the same lines beside the original); `plain` and `timed` without one are the original. The value being optional, an address after a bare `--transcript` would be taken as versions: README documents `yt2html URL --transcript [VERSIONS]`, and an unknown item ends with "the video's address goes before --transcript". Any case of letters: the items are lowered, the language code goes through `standard_code()` (language lower case, a two-letter region upper case, a script capitalised: `PT-br` → `pt-BR`, `zh-hans` → `zh-Hans`; YouTube's codes are written this way, checked on 164 codes in the test data), so no comparison against the data has to ignore case. A mutant `len(part) <= 3` survives on purpose: three-character regions are digits (`es-419`). Errors (argparse, before anything is fetched): empty item, unknown version (also `none`, and the old `timestamps` and `bilingual`), `dual` without a code or with `author`/`auto-generated`, an unknown kind, a code that is no language code (`check_code()`: `LANGUAGE_CODE` and yt-dlp's ISO 639-1 table or three letters, as `recognised_code()`; `jp` is not one), a repeated item (also `plain:pl` twice in another case); with `--olang`, a `dual` into that language or a version both with and without it. `format_transcript_spec()` writes the list back for the Command row.
- **Resolving** (`resolve_versions(spec, transcript)` at every page build, from the data): each version becomes `(shown version, source)`: the source `None` for the original, `CODE.own` for one's own translation, `CODE` for YouTube's, `CODE.author` or `CODE.auto-generated` for subtitles of their own (`version_source()`: without a kind the first the data have of one's own, YouTube's, the author's, a dub's, the user's order of 25.11.2026, `dual` only the first two; with a kind that one, `translated` named `CODE` in the data), else the token as written (`available()` says no: *not available*). A code in the original's language (`base_language()`) is the original: `dual` into it becomes `timed`; a version that turns out the same as an earlier one is shown once; both give a note for the console and the *Transcript* row (`dual:en: the original is English; shown as timed`, `timed:pl.author: the same as timed:pl.author; shown once`).
- **What is asked of YouTube** (`source_keys(spec, info, original, own)`): `CODE` for a translation, `CODE.author` / `CODE.auto-generated` for subtitles of their own (by their kind), and for `plain` and `timed` without a kind `CODE|CODE.author` (or `.auto-generated`, the first the video's own tracks have: `subtitles_in()`: `subtitles`, or `automatic_captions` `CODE-orig`; `live_chat` is no subtitles): the translation, and the subtitles only when it does not come (`split_keys()`, `key_code()`); nothing without a kind for a language of one's own translation (`own`: it comes first), nothing for `.own`, nothing in the original's language. `add_sources()` fetches a fallback after `add_translations()` when the translation is not in the data (refused or not offered), logging `  Instead: subtitles by the author in 'pl'.`; `missing_for_update()` asks for the translation again while it is missing with `refused: true` (the pair while the subtitles are missing too), and for the subtitles alone when YouTube has no translation into that language. `fetch_transcript()` downloads the transcript, then `add_sources()`: translations by `add_translations()` (below), subtitles of their own by `add_tracks()` (the json3 of that track through `caption_data()`, `parse_json3_captions()`, stored in `tracks`; not there: `missing[KEY]`, `YouTube has no subtitles by the author in 'pl'`).
- **Translations** (`dual:CODE`, `plain:CODE`, `timed:CODE`, `CODE.translated`): `fetch_translation()` downloads the same caption track with `tlang=CODE` added (`with_query()`), i.e. YouTube's auto-translate, which keeps the original timing; several languages are downloaded one after another. The languages YouTube offers are read from the watch page (`ytInitialPlayerResponse` → `captions.playerCaptionsTracklistRenderer.translationLanguages`) into `info["yt2html_translation_languages"]` (`{code: name}`). YouTube answers `HTTP 429 Too Many Requests` to auto-translated captions requested soon after the video data was fetched; original captions and author subtitles are not affected. Until early November 2026 about a minute was enough (yt-dlp issue #13831, where a maintainer confirmed that waiting at least 60 s works); since about 12.11.2026 the refusal often lasts for days, from other networks, for other videos, also for yt-dlp alone, with curl_cffi impersonation, the `mweb` client and browser cookies, while the browser shows the translations (probably a PO token for subtitles is needed; not tried yet: a PO token provider plugin such as bgutil). So a translation is requested once, `translation_wait()` (a random 70–100 s, `TRANSLATION_WAIT`; a fixed delay looks automated) after fetching started (comments downloaded meanwhile count towards it), and not retried. What YouTube does not have (`TranslationUnavailable`: a language not offered, the message listing the available codes; a language equal to the transcript's own; an empty translation) or does not send (`TranslationRefused`, a subclass: 429 or any failed download, the reason from `refusal_reason()`, e.g. `YouTube refused to send it (HTTP 429 Too Many Requests)`) is logged (`No translation into 'fi': …`; a refusal adds that the page counts as finished and that `--json write` (keeping the comments) or `--page ovr` adds it later) and kept in `missing`; the page leaves that version out and *About this copy* names it (`not available: dual:fi (reason)`). A video without captions is logged as `No transcript: …`. Only a failed download of the transcript itself raises `TranscriptError` during fetching, so nothing is written, not even `--json write`, and the next run tries again (a page that is there counts as finished).
- **One download per caption track and run** (`caption_data()`): every caption track, for the transcript, its translations and subtitles of their own alike, is fetched as json3 (`fmt=json3` set on any address) through `caption_cache`, keyed by `caption_key()`: the address's `v`, `lang`, `kind`, `name` and `tlang`, so the same track from another fetch (other signature and expiry) is the same entry. A failure is kept too and raised again, so a refused translation is asked for once per run. The wait until `not_before` happens only on a real download. `main()` empties the cache at the start of a run (and `conftest.py` for each test). `align_translation()` gives each original cue the translated cues starting at the same time (or before the next original cue); `render_bilingual_transcript()` draws rows as a 3-column CSS grid (time, original, translation; on narrow screens the translation goes under the original, in grey).
- **Rendering** (`render_transcripts()`): one section per resolved version, in order: `render_transcript()` (class `transcript original`, or `with-timestamps`), `render_bilingual_transcript()` (class `transcript bilingual`), a translation alone through `translated_transcript()` (the translation's cues with the original's times, `data-lang`; one's own also `data-own`, as its `dual` section, so the player tells the two apart), subtitles of their own through `track_transcript()` (their own cues and times, heading `Polish, by the author` / `Polish, auto-generated`, `data-track`). `translated_texts()` carries the original's change of speaker (`>>`) into every translation that lost it, one line for one line (only for translations: subtitles of their own keep what their author wrote; at build time, never in the data: the data keep what YouTube sent). When no version shows the original, a hidden original section (`hidden`, class `original`) is added for the player (subtitles, ↺, the language buttons). The player takes its lines from the original and adds one language button per `data-lang` section, each language once; `data-track` sections get none (other lines).
- **SRT files** (`--transcript srt`, `srt_tracks()`, `write_srt_files()` in `write_page()`): one file per track the page shows, `(code, kind)` once: the original (`.en.auto-generated.srt` or `.en.author.srt`, also for `dual`), YouTube's translations (`.pl.translated.srt`), subtitles of their own (`.pl.author.srt`); never a translation of one's own (its `.own.srt` is the source). `sub_suffix()` gives the ending, `file_by_suffix()` a file there (renamed too), else the page's name with the ending. `cues_srt()`: numbered blocks, `start --> end` (the cue's end, else the next start, the last 5 s), the cue's text on one line. A file is written over only when its bytes differ (its date stays otherwise). Made with the page and from its data, so `--json load` makes them; a page skipped makes none (the skip message says so); with `--json write` a missing SRT file counts as missing. The *Transcript* row names them (`SRT files next to the page: en (auto-generated), pl (translated)`).
- **`--olang CODE`** (`olang_code()`, `OLANG_KEY` in the data, one of `PAGE_CHOICE_KEYS`): `transcript_language()` and `original_uncertain()` take it first, `choose_caption_track()` looks only in that language (none there: no transcript, `no captions in 'CODE', the original language set with --olang`), `FormatChoice` takes it as the original audio's language, and the *Transcript* row adds `the original set in the command`. With saved data: recorded, and a saved transcript in another language stays (a warning naming `--transcript ovr`).
- `render_transcript()` puts each cue under the last chapter that starts at or before it (chapters from the chapter list described above; `<h3>` per chapter, empty chapters skipped). Without timestamps one `<p>` per part; with timestamps `<div class="cue">` rows.
- The cues are the caption lines, which is also how the panel divides the text; tiny differences to the panel are possible.

**Speaker changes.** YouTube's automatic captions start a new speaker's words with `>>` (`>>>` for a new topic), a convention of TV captions; translations do not have it. `speaker_html()` replaces each mark (`SPEAKER_RE`) with ours: in the timed and dual transcripts an empty `<span class="speaker" aria-hidden="true">` whose icon comes from CSS (`.speaker::before`: a speech bubble outline as an SVG `mask`, painted with `currentColor`, i.e. the grey `--muted`), and the translation of a cue with a mark gets one at its start too (`translated_texts()`, in every version showing a translation); in the continuous transcript a grey `<span class="speaker">|</span>` between spaces, left out at the start of a part (`at_start=False`). The cue data (and `--json write`) keep YouTube's text. The lines under the video remove the marks (`textOf()` in `PLAYER_JS`).

## Images

- `fetch_image()` downloads with `urllib` (browser User-Agent, timeout, retries) and returns a `data:` URI; the MIME type comes from the response header or is sniffed from the bytes.
- Avatars are requested small: `=s88-...` in the URL is replaced by `=s{AVATAR_SIZE}`. They are downloaded in parallel (`ThreadPoolExecutor`).
- Each avatar is embedded **once** as a CSS class (`.av12{background-image:url(data:...)}`) and referenced by every comment of that author. The `<style>` in `<head>` is generated after the body, when all classes are known.
- A failed or missing avatar becomes a coloured circle with the first letter of the name (hue from a CRC32 of the name, so it is stable).
- The thumbnail falls back through `thumbnails` from best to worst if `thumbnail` fails.

## Text to HTML

`linkify()` escapes everything and recognises, in one regex pass: URLs (`http(s)://...`, `www....`; trailing punctuation and unbalanced `)`/`]` are cut off), timestamps `M:SS` / `H:MM:SS` (only valid values not longer than the video), `#hashtags` (not purely numeric), `@handles` (not inside e-mail addresses). Newlines are kept via `white-space: pre-wrap`.

## Theme

- All colours are CSS variables on `:root` (`--bg`, `--text`, `--muted`, `--panel`, `--line`, `--link`, `--chip`, `--media-bg`); the dark values are in `CSS`, the light ones (YouTube's light theme) in `LIGHT_VARIABLES`. New styles must use these variables, not fixed colours, or they break one of the themes. Exceptions that work on both: the red heart, the white letter on the coloured avatar circles.
- `theme_css()` adds, after `CSS`: nothing for `dark`; `:root{light variables}` for `light`; the same inside `@media (prefers-color-scheme: light)` for `auto`, so the page follows the device setting and changes with it, without JavaScript. `color-scheme` (CSS property and `<meta name="color-scheme">`) makes the browser draw scrollbars and the like in the matching colours.
- `--page theme:auto|dark|light` (any case), default `auto`: the page itself follows the light/dark setting of whatever device or browser opens it, each time it is opened (in most browsers "device" means the system setting unless the browser's own appearance setting overrides it). Works with `--json load` too (the theme is not stored in the data). The index takes its theme from the list file (`!theme:`), never from `--page`.

## Snapshot date

`render_page()` receives the date from `info["yt2html_archived"]` (today for older JSON files without it), so a page rebuilt with `--json load` keeps the date of the original fetch. The `Snapshot` tile uses the class `fact extra` (grey value); `show_snapshot=False` (`--page snap:no`) omits it, and the `Refreshed` tile too. *About this copy* and the comments note always show the date. `--json write` and `--json refresh` keep `yt2html_archived`; what they did is in `yt2html_updates`.

## File names

`ydl.prepare_filename({**info, "ext": "html"}, outtmpl=OUTPUT_TEMPLATE)` — yt-dlp's own sanitizer, so characters forbidden on Windows are replaced exactly as in the video file name (e.g. `:` → `：`).

## Existing files, `ovr`

- **One rule for files with an id** (`files_with_id()` / `file_with_id()`, since 0.7.0): in the output folder (not its subfolders), a file whose name contains `[ID]` anywhere (with the brackets, the whole id) and ends with the right extension, in any case; the rest of the name does not matter. Pages: `.html` (`existing_page()`), saved data: `.info.json` (`saved_data_path()`), videos: `VIDEO_EXTENSIONS` without the one-format parts of an unfinished `--video` (`Title [id].f399.mp4`, `.f251.webm`; `video_files()`, used by the page (`video_files_for()`) and the index alike), audio tracks and SRT files by the id and their ending (`file_by_suffix()`: `.pl.dubbed.m4a`, `.pl.translated.srt`). Several matches: the first by name, with a note printed once per folder, id and kind (`first_of()`, `_SEVERAL_NOTED`). Before 0.7.0 the names had to end with `[ID].html` or `[ID].info.json`, and videos were only tried by exact names.
- **A file that is there is skipped**, each kind by its own option, so the same command again only does what is missing: a video counts as archived when the output folder holds its page (pages may be renamed); `--page ovr` makes the page again, `--video ovr` the video and its tracks, `--transcript ovr` the saved transcript (with `--json`). `--json load` always makes the page (no requests, and re-rendering is its purpose), and so does `--json write` or `refresh` when it changed the data. A replaced page keeps its existing (possibly renamed) file name. The index is the one file always written anew (a view of the folder that holds nothing that cannot be made again).
- The id is read from the URL without any request (`video_id_from_url()`: yt-dlp's `YoutubeIE.suitable()` / `extract_id()` for `watch?v=`, `youtu.be/`, `shorts/` and bare ids; the `v=` parameter for watch URLs with `&list=`, which yt-dlp gives to its playlist extractor). So a skipped video costs nothing. If the URL shows no id, the check is repeated after fetching, with `info["id"]`.
- Default: skip (`Skipped (page exists): ...`), and `archive()` returns `None`; `main()` counts saved, skipped and failed.
- Pages, saved data (`.info.json`) and SRT files are written by `write_atomically()`: first `NAME.part`, then renamed (`os.replace`), as bytes (UTF-8), so the line ends are the same on every system. An interrupted run leaves at most a `.part` file, which never counts as a finished page or subtitles file, and the earlier saved data stay whole (with `--json write` and `refresh` they are the only copy); a video that failed has no page and is tried again on the next run.
- **Console output:** `main()` first calls `readable_output()`, which sets the standard output to replace what its encoding cannot show (`?`) instead of raising. ## Video formats

The folded `<details class="formats-info">` just above *About this copy* (`render_video_formats()`), on every page. Without video and audio formats (`video_overview()` is None: no list, or only storyboards, the thumbnail grids for the seek bar's preview; YouTube sometimes sends nothing else for a while, seen on a Short fetched several times in a row) the summary is `none in the data` and the open section one line, `NO_FORMATS` + `NO_FORMATS_WHY` + `; make the page again later` (`<div class="none">`); a missing section would look like a fault of the page. No exception for data without a list. It shares the look of *About this copy* (CSS `.formats-info, .copy-info`; when both are there, *About this copy* follows closer). Folded, it shows `Video formats` and a summary (`video_overview()["summary"]`): short on purpose, only the top quality (`up to 2160p, 24 fps`, HLS counted) and the original audio's language (`original audio: en-US`, the code as in the table; left out when the original or its language is unknown); the tables tell the rest (tracks by role and subtitles were in the summary before, and machine translation after a `+` read as more languages); nothing at all leaves `Video formats` alone, without a separator; no date (the snapshot date in *About this copy* covers the whole page). Opened, two small tables (`formats_table()`), image and languages, and a line on machine translation; program matters (Deno, signed in) are in the *Video file* row of *About this copy*. No option: the data comes with every download (the formats are part of what yt-dlp fetches anyway) and with `--json load`.

- **Tables:** size columns are right-aligned and never wrap (`class="size"`), the rest wraps; a table wider than the page scrolls sideways (`.formats`); an empty cell is a dash. From `formats` (`video_formats()`): video-only and audio-only formats without DRC variants (YouTube's *Stable volume*: a compressed copy of the same track); combined formats only when there is nothing else (storyboards drop out, having neither codec).
- **image:** one row per quality, i.e. YouTube's quality name and the frame rate, descending (`youtube_qualities()`: the number in yt-dlp's format note, `1080p`, `720p60`, `1080p Premium`; else the name of another format of the same size, since HLS formats have no note; else `quality_from_size()`: the shorter side, or 9/16 of the longer one when that is more, to the nearest step of `QUALITY_LADDER`, so a frame wider than 16:9 is named after its width as YouTube does, 1920×804 and 1080×1920 both `1080p`; else the height). A column `resolution` after it gives the real size (`1920×1080`; several sizes in one row joined by commas; an HLS-only row the HLS size). `quality_label()`: `1080p, 30 fps`; two rows when YouTube offers two frame rates at one height; a height only in HLS shows alone). A quality a download can take (up to `DEFAULT_MAX_HEIGHT`, with an ordinary AV1 or H.264 format: `RULE`) gets its parameter in brackets (`quality_parameter()`: `1080p, 30 fps (1080p30)`); higher qualities, vp9-only and Premium-only ones have none, since the download never takes them; × codecs (`codec_name()`: avc1→h264, av01→av1, vp9/vp09→vp9, hev1/hvc1→h265); the best format of each (the largest of alike formats), a dynamic range other than SDR, size with the main audio. Formats for Premium accounts (`is_premium()`: "Premium" in yt-dlp's format note) get their own columns after the ordinary column of the same codec (also in the audio table); kept on purpose, since sometimes they are the whole difference between data fetched signed in and not; never in the planned default. **HLS** formats (`is_hls()`: protocol `m3u8…`) have no size, only a declared bitrate, which proved far too high (3262 kbit/s against 276 kbit/s for the same 1080p h264 as one DASH file); they are only named, per height, in a last column *HLS (sizes unknown)*, and never used for sizes, the main audio (unless there is no other audio) or the planned default. Signed in, yt-dlp gets no HLS formats at all.
- **audio rows:** one row per track, i.e. language and role: columns `code` (first: the rows are in its order, and it is what `audio:CODE` will take), `language`, `role`, then aac and opus sizes; no caption hint (the table informs, it does not instruct). The language name (`language_name()`): yt-dlp's English format note of a single-file format of the track, its first part without ` original (default)` / ` descriptive` (`English (US) original (default), medium` → `English (US)`; a note that is only a quality word, such as `medium` for videos without dubs, gives no name); HLS notes are in the track's own language (`العربية - dubbed-auto`), so not used; else the name of the author's subtitles in that code (`Portuguese (Brazil)`, `Chinese (China)`; also for rows of subtitles alone); else YouTube's list of translation languages from the watch page (`yt2html_translation_languages`, full code, then the language alone); else the code. Audio formats without any language (seen on a TED talk: one track, no language in the data): `FormatChoice` takes `transcript_language()` (the watch page's default subtitles for the track, the same guess the *Transcript* row shows as "original language"), so the track's code joins the author's subtitles in one row; with nothing to go by it stays `UNKNOWN_LANGUAGE`. `download_video()` builds its `FormatChoice` with the page's `CAPTION_KEY`, `ORIGINAL_AUDIO_KEY` and `TRANSLATIONS_KEY` (`with_page_choices()`) for the same guess. `subtitle_tracks()` lists codes alphabetically (console and `--video-formats`); a refused translation (429) ends with `TRANSLATION_HINT`, as for the transcript's translations. The role is YouTube's kind of track (`audio_kind()`), which yt-dlp does not pass on but every format address carries in its `xtags` (`…&xtags=acont%3Ddubbed-auto%3Alang%3Dpl&…`, in HLS addresses a path part `/xtags/…/`): `acont=original` → *original*, `dubbed` → *dubbed* (by the author: YouTube's multi-language audio), `dubbed-auto` → *auto-dubbed* (YouTube's automatic dubbing), `descriptive` → *descriptive* (audio description); another value is shown as it is (`AUDIO_KINDS`). `xtags` is undocumented, so without it the role comes from yt-dlp's `language_preference`: 10 original, -10 descriptive; a video with a single language has nothing to mark it by, so that track is the original; otherwise *dubbed* when an original is known, else no role. In the console list (`--video-formats`) the tracks are grouped by role (original, dubbed, auto-dubbed, descriptive, other kinds by name, no role), then by language code; on the page they are ordered by language (see *languages*); one language may have two rows. A track without a language in the data (`UNKNOWN_LANGUAGE`, e.g. Shorts) has no code (`–`) and the name `unknown`; texts leave the language out (`sizes include the audio: aac`, `… av1 + aac, mp4`, `audio: original` in the summary), `--video-formats` says `unknown language`, and the player tile shows the quality alone. YouTube names some Shorts formats of 608×1080 `480p` (vp9 `779`/`780`, av1 `787`/`788`), so a row may have two resolutions (`480×854, 608×1080`). The main audio is the original's aac, else its other codec; without an ordinary (non-Premium) original, the largest ordinary track, an audio description only when there is nothing else.
- **languages** (one table for audio and subtitles, caption `languages`): the audio rows above, plus columns `subtitles by the author` (`subtitles` without `live_chat`) and `auto-generated subtitles` (yt-dlp's `-orig` tracks: made from one audio track's speech, so a dub has its own). Joining (`joined()`): the author's subtitles belong to the video, so they go to the row of the same code, else the only row of the same language (an audio description only when it is the only one); automatic ones go to their audio's row by language, or to the only audio track when its language is unknown; anything else gets a row of its own (code from the subtitles, name from the translation list, `–` for audio and sizes). A cell may list several codes (`es, es-ES`), each the code its parameter will take. Order (`language_order()`): languages with audio first, the original's language first, then the others alphabetically by language; within a language, audio rows by role (then code), then the subtitles' own rows; languages without audio at the end, alphabetically. The subtitles the transcript takes are not marked (the *Transcript* row names them). Under the table, one line in four versions, always `machine-translated subtitles: …` (the label says subtitles, since an auto-dubbed track is a machine translation too): `possible in N other languages for each row with subtitles` (N: YouTube's list of target languages from the watch page, `yt2html_translation_languages`, given only for videos with subtitles, else yt-dlp's translation entries, minus the source; "for each row" so that it does not read as N more languages; YouTube translates any subtitles on request with `tlang`, nothing is stored per language); `none (no subtitles to translate)` (no subtitles at all); `unknown (YouTube listed no translation languages)` (subtitles, list read but empty: YouTube's side, trying again will not help); `unknown (not read from YouTube; make the page again later)` (subtitles, no list in the data: the watch page could not be read, or older data; technical, may pass). yt-dlp's own translation entries take the first automatic track as the source (for auto-dubbed videos a dub), so yt2html never uses them: translations are built from the original track, as for the transcript.
- **Choice and presentation are apart:** `FormatChoice` (made by `video_choice()`, None without video or audio formats) holds what a download can take, with no HTML: DASH and HLS formats, audio tracks (`track()`: language and `role_of()`), `original`, `main_audio`, `audio_for()`, `best()`, `quality()` (YouTube's names), `with_audio()` (size with the main audio) and `variants` (up to `DEFAULT_MAX_HEIGHT`, best first, each with height, fps, format, codec, quality label, parameter and size). `video_overview()` builds the tables, the summary and the console lines from it and adds each variant's place in the image table (`row`, `column`). `--video` is meant to take from `FormatChoice` directly (on a fresh list of formats).
- **The planned default** (what the download will take without parameters): the first of `video_overview()["variants"]`, i.e. the best quality up to `DEFAULT_MAX_HEIGHT` (1080p; highest frame rate first) that has AV1 or H.264, then AV1 there, else H.264 (never vp9 or Premium: the file is mp4 and plays everywhere), with the main audio, mp4. The quality comes first: 1080p only in H.264 beats 720p in AV1. Its cell is marked with `class="planned"` (text in `--planned`: light blue `#9cc3e8` in the dark theme, blue `#2f6a9e` in the light one; softer than links; yellow is reserved for what the user actually chose, once `--video` downloads), as is the main audio in the languages table; the captions carry no colour legend (README explains the colours; with `--video` blue would soon stop being the only mark). Without a main audio, or without an AV1/H.264 quality up to 1080p, nothing is marked and `--video-formats` has no `(default)`. Tests check the choice through `planned()` in `test_about.py` (the `(default)` line and the audio of the image caption). Later, with `--video`, yellow will mark the actual choice (what was asked for or downloaded) and blue stays for the default.
- Sizes (`format_size()`): `filesize`, else `filesize_approx`, else `tbr` × duration; `human_size()`: `~X.X GB` from 1 GB, `~N MB`, below 1 MB `<1 MB` (Shorts); escaped on the page (`&lt;1 MB`), plain on the screen.

### --video-formats

`list_formats()` instead of making pages (`main()` hands over before the loop): for each source, `fetch_formats()` (yt-dlp with `quiet`, no comments, no watch page; the download settings note Deno and browser cookies as in `fetch_info()`), or the saved data with `--json load`; playlists and channels (by the URL, or a playlist answer from yt-dlp) fail with a message, as does a failed fetch; the run goes on and ends with exit code 1. Each video that asks YouTube counts towards `--take` (`taking()` before the fetch; past the limit it is left, and the run ends with `take_note()`). `format_list()` gives the lines, printed to stdout with a blank line between videos: the title and id (with `--json load` also `saved data of DD.MM.YYYY`); `image (mp4, AV1 else H.264; sizes include the audio: en-US aac):` (the same words as the section's image caption; without a main audio only `image (mp4, AV1 else H.264):`) and one line per variant, in aligned columns (quality, parameter in brackets, codec, size with the main audio, `(default)` for the first when there is a main audio), or `image: nothing a download can take (…)`; one layout for the audio: a header, then indented lines: `in the video: en-US (original)` (the main audio; its role in brackets, none when unknown), then the tracks a download can add (those with an ordinary aac format), one line per role in role order (`auto-dubbed: ar, bn, …`; `tracks:` without roles). Both headers follow one pattern: container and codec of what goes into the video, then after a semicolon the rest. The audio header: `audio (mp4, aac):` (the codec of the main audio, from the data: `opus` when the original has no aac), and when there are tracks to add `audio (mp4, aac; extra tracks m4a, aac, ~69 MB each):` (one size or a range `~60–70 MB`, `~900 MB–1.1 GB`; none when unknown); no size for the track in the video, since the image sizes include it. `audio: none` without audio (then there is no ordinary track to add either). Then the video's own subtitles (`subtitle_tracks()`): `subtitles (srt):` with `  by the author: …` and `  auto-generated: …` (`SUB_KIND_TEXT`; what `--transcript CODE.author` and `CODE.auto-generated` take; no line on machine translation, no wrapping of long lists), or `subtitles: none`. Without any video or audio format one line instead: `no video or audio formats in the data: YouTube sometimes sends none for a while; try again later`, with `--json load` `…: YouTube sent none when the data was saved; make the page again with --page ovr`. How to ask for a track (`audio:CODE`) belongs to README and `--help`, not to the list. `fetch_formats()`, like `fetch_info()` for pages, asks yt-dlp for one format (`NO_MERGE_FORMAT`, `bv*/b/ba`, no merging), so yt-dlp does not warn about a missing ffmpeg, which only matters for a download; the formats in the data are the same either way. A note follows when Deno was missing for a fetch. `parse_args()` refuses `--page`, `--index`, `--index-only`, `--json` other than `load`, `--transcript` and `--video` (nothing to make); sources, `-o`, `--json load`, `--take` and `--cookies` stay.

### --video

`parse_args()`: `--video` with `nargs="?"` and `const=""`, parsed by `video_spec()` into `{height, fps, ovr, audio, text}`: a quality from `QUALITY_LADDER` up to `DEFAULT_MAX_HEIGHT` as an upper limit (`720p`: any frame rate; `720p30`: at most 30 fps), `ovr` (download the files that are there again; `again` until the options' change), any case; `audio:` items with their codes checked at once (`check_code()`), each once (`add_once()`: the same code and role twice, or a code both alone and with a role, is an error, since what was meant is not clear; two roles of one code are two tracks); anything else (also an address after a bare `--video`, and the old `sub:`) is an argparse error that ends with "the video's address goes before --video" (README documents one form: `yt2html URL --video [PARAMETERS]`). Subtitles are SRT files of the transcript (`--transcript srt`, *Transcript* above). Refused with `--json load` and `merge` (needs YouTube; the saved data are a snapshot, and `load` never downloads), `--index-only` and `--video-formats`.

## Page metadata and the index (`--index`, `--index-only`)

**Metadata.** Every video page has invisible `<meta name="yt2html:...">` tags in its `<head>`, before `<title>` and the large `<style>` (`page_metadata()`). They are the index's only source about a page (it never reads the page's content). **The contract (user's decision 18.11.2026: unambiguous for later use):** a page with `metadata` = `2` (`METADATA_VERSION`) has every tag whose value is known; **an absent tag means the value is unknown** (for `refreshed` and `unavailable`: it did not happen); a tag is never written with an empty value. A page without `metadata` was made by an older version and has to be made again (no backward compatibility before 1.0). Times are local, of the computer that downloaded or refreshed, `YYYY-MM-DDTHH:MM`.

The row playing has the class `now`: a 2 px accent ring round its thumbnail (the round button turns accent) and its title in `--accent-text`; no background for the whole row, which would light up its notes too (the user, 19.11.2026). State: `items` (every `[data-file]` in order), `current` (−1 before the first play), `failed` (indexes, in memory until reload), `playOn` (what previous / next carry, user's decision 19.11.2026: `load(i, play)`; previous / next pass `!video.paused` of the current file, so playing goes on and stopped (paused, `|◀`, ended) waits; from a failed file the `playOn` of its own load, i.e. the state before it; a thumbnail and Autoplay pass `true`). `load()` sets `preload` to `metadata`, so a waiting file shows its duration and first frame (the panel starts with `preload="none"`: nothing is read before the first play). A failed file needs no label change: the browser fires `pause`. `setState()`: before the first play everything is disabled (also `A`, the speeds and the bar); a failed file disables the controls and the bar, not previous/next, `A` or the speeds; previous/next by `playableFrom()` (skipping failed files; rows without a file have no `data-file`). A video `error` marks the file failed (row `failed`, thumbnail dimmed, `.ix-failed` with the title); the browser gives the same error for a missing file and an unplayable format (Chrome: code 4), so the reasons are only in README. `ended` with `A` on: the next playable file; a new error stops there. `reveal()`: a row out of sight comes into view by the shortest `scrollBy` with a 48 px margin (smooth unless `prefers-reduced-motion`), the visible part starting below the panel when it is sticky; Autoplay reveals only if the row that ended was visible. Keys on `document` (not in form controls or on buttons; the thumbnails stop only `Enter`/`Space`): the page's keys plus `Shift+P` / `Shift+N`, each only when its button is enabled. `mediaSession`: seek ±10 s, previous and next track. `pip` as on the page.

## Testing

**Run the tests after every change**, in the project folder:

```powershell
uv run pytest
```

The first run installs pytest into the project's `.venv` (the `dev` dependency group in `pyproject.toml`; it is not part of the installed program). A run takes about a second, needs no network and ends with a line such as `349 passed, 7 skipped`. `uv run pytest -q` prints less, `uv run pytest -x` stops at the first failure, `uv run pytest tests/test_chapters.py` or `-k bilingual` runs a part.
