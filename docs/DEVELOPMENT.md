# Development notes

How `yt2html` works, where it takes its data from, and how to test and release it. For using the program see [README.md](../README.md); for the history of versions see [CHANGELOG.md](../CHANGELOG.md).

YouTube does not document the page data the program reads. The paths below were checked on real pages (reference videos in the sections and in `tests/test_online.py`); when YouTube changes something, this document says where to look.

## Working on the project

Requirements: [uv](https://docs.astral.sh/uv/) and git.

```powershell
git clone https://github.com/mwislowski/yt-video-archiver
cd yt-video-archiver
uv sync                                   # creates .venv with the project and pytest
uv run yt2html.py --version               # run from the source folder
uv run pytest                             # tests
```

To use the source folder as the `yt2html` command everywhere, install it *editable* (changes to `yt2html.py` work at once):

```powershell
uv tool install --editable PATH\TO\yt-video-archiver
```

An editable install changes the everyday command with every edit, experiments included. For a stable everyday command, install a release instead and work on the code with `uv run yt2html` in the project folder:

```powershell
uv tool install git+https://github.com/mwislowski/yt-video-archiver@v0.10.6         # a tested release
uv tool install --force git+https://github.com/mwislowski/yt-video-archiver@v1.0.0  # later: switch to a newer one
```

After a change in `pyproject.toml` (dependencies, command) add `--reinstall`. To update yt-dlp in the project: `uv lock --upgrade-package yt-dlp`, then `uv sync`, and commit the updated `uv.lock`.

`.gitignore` excludes `.venv`, the test cache (`.pytest_cache/`), build output (`build/`, `dist/`), `*.html`, `*.html.part` and `*.info.json` (pages created when the command is run in the project folder), and `*.local.md` (private notes, kept only on this computer, so without a copy on GitHub). The repository contains only code, configuration and documentation, never archived pages.

## Version, packaging, releases

- **One source of the version:** `__version__` in `yt2html.py`. `pyproject.toml` has `dynamic = ["version"]` and `[tool.hatch.version] path = "yt2html.py"`, so the package version and `yt2html --version` always agree. `--version` prints it together with the yt-dlp version (most problems come from an outdated yt-dlp).
- **Versioning:** the second number for new features or visible changes (0.2.0, 0.3.0), the third for fixes (0.2.1). What changed in each version is in [CHANGELOG.md](../CHANGELOG.md).
- **Command:** `[project.scripts] yt2html = "yt2html:main"`; the wheel contains only `yt2html.py` (`[tool.hatch.build.targets.wheel] only-include`). `main()` returns the exit code, which the generated command passes on.
- **Release:** run the tests (also `--online`), change `__version__`, move the *Unreleased* entries in `CHANGELOG.md` under the new version with its date (and update the compare links at the bottom), commit, then `git tag -a vX.Y.Z -m "..."`, `git push` and `git push origin vX.Y.Z`. The changelog entries can serve as the GitHub release notes.

## Conventions

- **English everywhere in code:** identifiers, comments, CLI options, program messages, fixed page labels and invisible HTML (classes, ids, meta tags). Only the archived content itself is in its original language.
- **Configuration in constants at the top of `yt2html.py`** (`DEFAULT_OUTPUT_DIR`, `OUTPUT_TEMPLATE`, `DATE_FORMAT`, `THOUSANDS_SEPARATOR`, `AVATAR_SIZE`, `IMAGE_WORKERS`, ...); per-run choices are CLI options.
- **One output file, works without JavaScript.** Static HTML + CSS; every image is a `data:` URI. The page must work when opened from disk with no network. The only script is the built-in player (`PLAYER_JS`), which adds something and never replaces content; the index has its own player script (`yt2html_index.PLAYER_JS`), likewise: without it the index is a plain list.
- Program messages are prefixed with `[yt2html]`; yt-dlp prints its own `[youtube]` progress lines.
- A failure for one URL does not stop the others; the exit code is 1 if anything failed.

## How the data is obtained

`yt_dlp.YoutubeDL(...).extract_info(url, download=False)` with:

- `skip_download`, `noplaylist`, `getcomments`;
- `extract_flat: "in_playlist"`: a safety net. `noplaylist` only turns watch URLs with `&list=` into the video; an unrecognised URL that leads to a playlist or channel would otherwise be extracted video by video, comments included. With it, yt-dlp returns only the flat list, and `archive()` fails with `this URL leads to a playlist or channel`. Playlist URLs never get here (see *Playlists*), channel URLs fail before any request (`is_channel_url()`);
- `ignore_no_formats_error: True` — the video is not downloaded, so missing formats (e.g. when no JavaScript runtime is installed for YouTube's player challenges) must not abort the run;
- `extractor_args = {"youtube": {"comment_sort": ["new"], "max_comments": [N or "all", "all", "all", "all"]}}`.

Then, in the same `YoutubeDL` instance (same cookies and consent), the watch page is fetched once more with `ydl.urlopen()` for the timestamp lists and the description extras (see below). The program adds keys of its own to the info dict (constants `*_KEY` at the top of `yt2html.py`), all kept by `--write-json`, among them: `yt2html_archived` (ISO date of fetching), `yt2html_marker_lists`, `yt2html_description_extras`, `yt2html_channel_avatar` (the avatar URL, see *The page, part by part*), `yt2html_youtube_comment_count` (the comment count text from the comments panel header, `engagementPanels[]` with `panelIdentifier` `engagement-panel-comments-section` → `header.engagementPanelTitleHeaderRenderer.contextualInfo`), `like_count` when yt-dlp has none (`like_count()`, below), `yt2html_comments_message` (YouTube's message in place of the comments: `contents.twoColumnWatchNextResults.results.results.contents[]` → `itemSectionRenderer` with `sectionIdentifier` `comment-item-section` → `contents[].messageRenderer.text`, the runs without a link, so `Comments are turned off.` without *Learn more*; seen on `okT1dSP6gQQ`, 13.11.2026, where the comments panel and its count are missing; `null` when the section holds comments) and `yt2html_max_comments` (the `--max-comments` value, `null` for no limit).

**Likes.** yt-dlp reads `like_count` only from the like button's spoken label (`like this video along with 1,234 other people`), which has no number when nobody has liked the video yet, so it gives `None` for zero likes, the same as for a count the author hid. `add_watch_page_data()` fills it, only when yt-dlp left it `None`, from the player data: `like_count()` takes `microformat.playerMicroformatRenderer.likeCount` (a string of digits, `"0"`). With a hidden count the field is absent (`videoDetails.allowRatings` is `false`, the button's `likeCountEntity` is empty), so `None` stays and the tile shows `—`. Seen on two pages saved from a browser on 20.11.2026: `vNCutsX1MgQ` (0 likes: `likeCount` `"0"`, `allowRatings` `true`) and `KmcZktECUYQ` (likes hidden). The value goes into the saved data like yt-dlp's, so `--refresh-json` takes a fresh `0` too; a count hidden after the download leaves the saved one (as any count YouTube does not send).

**A video YouTube refuses** (removed, its account terminated, private): with `ignore_no_formats_error` yt-dlp only warns and returns an empty shell (title `youtube video #ID`, nothing else), which used to become an empty page. The refusal is in the watch page's player data: `playability_refusal()` takes `ytInitialPlayerResponse.playabilityStatus` when its `status` is not `OK` and there is no `videoDetails`, and `add_watch_page_data()` raises it as `VideoUnavailable(status, reason)` right after reading the player data, before anything else. The text joins `reason` and the error screen's description (`errorScreen.playerInterstitialRenderer.content.interstitialViewModel.description.content`) when they differ, which gives the texts yt-dlp prints: `Private video. If the owner of this video has granted you access, please sign in.` (`LOGIN_REQUIRED`), `Video unavailable. This video is no longer available because the YouTube account associated with this video has been terminated.` (`ERROR`), `This video has been removed for violating YouTube's Terms of Service` (`ERROR`, the description repeats the reason). These real responses (17.11.2026) are the test data in `tests/data/gone_playability.json`. `VideoUnavailable.gone`: `ERROR` except a reason with `try again later`, and `LOGIN_REQUIRED` with `Private video` (user's decision 17.11.2026, variant a: YouTube's own class, so also kinds not seen yet; `status` is read silently, the user sees only the text); other refusals (`not a bot`, sign in for the age, try again later) may not last. On a download or `--overwrite` any refusal fails the video (`FAILED: SOURCE: TEXT`), nothing written; `--refresh-json` handles it (see *Sources with …*). A watch page that cannot be read at all hides a refusal (the shell is then saved as before). An age-restricted video without cookies is no refusal: its watch page has `LOGIN_REQUIRED` *Sign in to confirm your age* but keeps `videoDetails` (no `streamingData`, no `captions`), and yt-dlp gets its formats through its `web_embedded` client (seen 19.11.2026 on `6Ib4MxtHFFM`, the test data `tests/data/agegate_playability.json`; the page is made as by 0.9.3, `--refresh-json` refreshes it as usual).

Why the program reads the comment count itself: when yt-dlp downloads comments, it **replaces** `comment_count` with the number of comments it downloaded (and sets it to `null` after `Ctrl+C`). So with `--max-comments 50` yt-dlp's `comment_count` is 50. `youtube_comment_count()` therefore uses the page's count; without it, yt-dlp's `comment_count` is used only when it can be trusted (comments not downloaded, or downloaded completely without a limit).

Used fields: `id`, `title`, `webpage_url`, `uploader`, `uploader_url`, `channel_is_verified`, `channel_follower_count`, `view_count`, `like_count`, `comment_count`, `duration`, `release_timestamp` / `timestamp` / `upload_date`, `thumbnail`, `thumbnails`, `description`, `chapters` (fallback only), `comments`.

Each comment: `id`, `parent` (`"root"` or the parent's id), `text`, `author`, `author_url`, `author_thumbnail`, `author_is_uploader`, `author_is_verified`, `like_count`, `is_pinned`, `is_favorited`, `timestamp`, `_time_text`.

## Comment order

- yt-dlp emits comments depth-first: a top-level comment, then its replies, then the next top-level comment.
- With `comment_sort=new` the top level comes **newest first** in YouTube's exact order; the program reverses it. The pinned comment arrives first regardless of its age.
- Replies come in YouTube's thread order, which is oldest first.
- YouTube gives only relative times (`2 years ago`), so `timestamp` is a coarse estimate. `chronological()` does a **stable** sort by it: the exact order from YouTube is kept within equal estimates, and only items whose estimate clearly disagrees (the pinned comment) move. Missing timestamps inherit the previous item's value.
- Then `build_comment_tree()` puts the pinned comment (`is_pinned`, only top level) first, as YouTube shows it and as its author means it (the user, 20.11.2026; before, it stood in its place in time, often last). One YouTube no longer sends (`MISSING_SINCE_KEY`, after `--refresh-json`, e.g. when the creator pinned another one) stays in its place in time with its *Pinned by* mark, a trace of the past, so two pinned comments are never both on top. No data change: a page made again from saved data gets the new order.
- Comments whose parent is missing are shown at the top level. Deeper nesting (if YouTube ever returns it) is rendered recursively.

## Description extras (AI-generated video summary, People mentioned, Explore the podcast)

The collapsed teaser, the disclaimer subtitle and the feedback button are left out. | Before the chapters: `<section class="desc-extra video-summary">`, one `<p>` per paragraph (with `linkify()`). |

Attributed text (`attributed_text()`, `render_attributed()`): YouTube text with `commandRuns`. CSS class names must not clash with existing ones: `description` (the description box) and `extra` (the grey Snapshot tile) are taken; hence `desc-extra`, `.about`, `.img-placeholder`.

Seen on reference video `9uSXOr-AdAU` (People mentioned + Explore the podcast) and `Z8lf5oWKfj0` (Explore the podcast). According to YouTube Help, *People mentioned* is generated automatically and being extended to more videos; *Explore the podcast* appears for videos in a playlist marked as a podcast in YouTube Studio.

## License

- On YouTube the license is a row of the video's metadata (`videoSecondaryInfoRenderer.metadataRowContainer.metadataRowContainerRenderer.rows[].metadataRowRenderer` with `title` `License`), not part of the expanded description's *Video details* list. It exists only for non-standard licenses. Reference video `KZtvWKpXPro`: `Creative Commons Attribution license (reuse allowed)` → `https://www.youtube.com/t/creative_commons`.
- `parse_license()` keeps the text runs and their web links (`navigationEndpoint.urlEndpoint.url`; YouTube `/redirect?q=` links are unwrapped by `unwrap_redirect()`). Stored in `info["yt2html_license"]` as `{title, runs: [{text, url}]}`, `None` when the video has none.
- `license_of()`: if the watch page could not be read (or for an older JSON file), yt-dlp's plain-text `license` field is used instead, without the link.
- Rendered after the transcript, before the comments, as `<section class="desc-extra license">`.

## Chapters and other timestamp lists

Everything is read from `ytInitialData` of the watch page, downloaded once more by `add_watch_page_data()` (`/watch?v=ID&hl=en`), which also reads the description extras above; the JSON after `ytInitialData =` is parsed with `json.JSONDecoder().raw_decode()`, which stops exactly at the end of the object. yt-dlp is not used for this: it keeps only one list as `chapters`, without its name or origin, and when the progress bar has no chapters it takes the first panel, which can be *Walkthroughs*.

Two places in `ytInitialData` hold timestamp lists:

| Place | Path | What it says |
|---|---|---|
| Progress bar | `playerOverlays.playerOverlayRenderer.decoratedPlayerBarRenderer.decoratedPlayerBarRenderer.playerBar.multiMarkersPlayerBarRenderer.markersMap[]` | `key` = `DESCRIPTION_CHAPTERS` or `AUTO_CHAPTERS`; `value.chapters[].chapterRenderer` with `title` and `timeRangeStartMillis`. The older `chapteredPlayerBarRenderer.chapters` (no key) is read too. |
| Engagement panels | `engagementPanels[].engagementPanelSectionListRenderer` with `content.macroMarkersListRenderer` | `panelIdentifier` and header title; items `macroMarkersListItemRenderer` with `title`, `timeDescription` and `onTap.watchEndpoint.startTimeSeconds`. Info rows (`macroMarkersInfoItemRenderer`, e.g. "These chapters are auto-generated") are skipped. |

Panel identifiers seen so far (04.11.2026): `engagement-panel-macro-markers-description-chapters`, `engagement-panel-macro-markers-auto-chapters` (both titled `Chapters`) and `engagement-panel-macro-markers-problem-walkthroughs` (`Walkthroughs`; the progress bar has no markers for it). Reference videos: `Z8lf5oWKfj0` (description chapters), `qyqCTMirNWg` (auto chapters), `hz6-3-7GGyI` (Walkthroughs only).

`parse_marker_lists()` builds the lists:

- **Chapters** (panels whose id contains `chapters`, plus the progress bar): the progress bar defines the chapters and their times (a chapter panel is used only when the bar has none); the panel gives the heading. Shown first, as one list.
- **Origin** (`decide_chapter_source()`): YouTube's own markings (progress-bar key and panel id) are combined with an independent check of the description (`description_chapter_starts()`: the run of consecutive timestamped lines beginning with the first `0:00` line, at least three, ascending, each chapter at least 10 s — YouTube's rules).
  - YouTube says *description* and the description has a valid list with the same start times → `description`.
  - YouTube says *auto* and the description has no valid list → `auto`.
  - Anything else — markings that disagree with each other or with the description, or an unknown key/panel id → `uncertain`: neutral heading, warning `Chapter source unclear: ...` on screen, the reason kept in `source_problem`. The program never guesses an origin.
- **Other panels** (e.g. Walkthroughs): as they are, `source: null`, in page order after the chapters.

Stored in `info["yt2html_marker_lists"]` as `[{id, title, source, source_problem?, items: [{start_time, time_text, title}]}]`. `None` means the extra request failed: the page then falls back to yt-dlp's `chapters` under a neutral `Chapters` heading (it may even be a Walkthroughs list). An empty list means the video has none.

Rendered after the description as `<section class="markers">` with an `<ol>`, one row per item; the origin note is `<span class="source">` (grey) in the heading, using the labels in `SOURCE_NOTES`.

## Transcript

- YouTube's own transcript panel loads its text from `/youtubei/v1/get_transcript` (parameters in `engagement-panel-searchable-transcript`). Checked on 05.11.2026: a request built outside the browser is refused (`400 Precondition check failed`); the browser sends extra integrity data that only YouTube's own JavaScript produces. So the program does not use it.
- The panel shows the text of a caption track, so `fetch_transcript()` downloads that track instead, from the URLs yt-dlp has already extracted (`info["subtitles"]`, `info["automatic_captions"]`; yt-dlp also deals with tokens YouTube may require for captions). Format `json3`, read with `ydl.urlopen()`.
- Track choice: the panel opens with the caption track of the **original audio**, which matters for auto-dubbed videos. They have one audio track per dubbed language and automatic captions for each of them, and yt-dlp marks every one of those with `-orig` (reference video `Z8lf5oWKfj0`: English original, 20 dubs; taking the first `-orig` track gave Arabic).
  - `default_caption_track()` reads `ytInitialPlayerResponse` from the watch page: `captions.playerCaptionsTracklistRenderer.audioTracks[defaultAudioTrackIndex]` is the audio the player starts with, usually the original (not always: below); its `defaultCaptionTrackIndex` points into `captionTracks` (language and `kind: "asr"` for automatic captions). Without that index, the language of the audio stream whose `audioTrack.displayName` contains `original` (e.g. `English (US) original`, id `en-US.4`) is used, else the audio track's id, else its first caption track. Stored as `info["yt2html_default_caption_track"]` = `{language, kind: "asr" | "manual" | null}`.
  - **The page's default can follow a dub** (`8etkFuBLGZ0`, 20.11.2026: Polish original, an English auto-dub; for yt-dlp's English request the page started with the dub and named its English automatic captions default, so the transcript, its *original language* label and `yt2html:language` were English). `transcript_language()` therefore takes the audio marked as the original (`marked_original_language()`: `language_preference` 10, or `acont=original` in the format address, `audio_kind()`) when the page's default names another language; the default stands when it agrees (`en` with an `en-US` original) or nothing is marked (one audio language). Everything that uses this choice follows: the transcript and its *original language* label when downloaded, the page metadata, the source of machine-translated `sub:` subtitles. A transcript already in saved data stays as it is (`--load-json` does not download it again); `--overwrite --transcript` downloads it again.
  - `choose_caption_track()` then picks from yt-dlp's tracks in that language: automatic captions first if the page says `asr` for that language (not when the original won over a dub's default), otherwise author subtitles first (`en`, `en-US`, ...), then automatic captions (`<lang>-orig`, `<lang>`). Without page data the original language comes from yt-dlp's formats (`language_preference` 10 = original), then `info["language"]`, then a single `-orig` track; with none of these, any author subtitles. `live_chat` is ignored; translated tracks are never used.
- `parse_json3_captions()`: one cue per json3 event with `segs`; the `utf8` pieces are joined, line breaks and repeated spaces become single spaces; events holding only a line break (automatic captions add them) are skipped. Cue start = `tStartMs` / 1000.
- Stored in `info["yt2html_transcript"]` as `{language, name, kind: "manual" | "auto", cues: [{start, text}], translations?: {LANG: {language, name, cues}}}`; `missing?: {LANG: {reason, refused, date}}` (the translations YouTube did not have, `refused: false`, or did not send, `refused: true`, which `--update-json` asks for again; `date` of that attempt, shown in *About this copy* for a refusal: `(YouTube refused to send it (…), 20.11.2026)`, `missing_text()`); `None` if the video has no transcript (the reason in `yt2html_transcript_missing`); absent without `--transcript` (nothing is downloaded). The cues are kept, so `--load-json` can rebuild the page with any versions (without `--transcript` there a saved transcript is left out; a `bilingual:CODE` needs that translation in the file, or a reason in `missing`, else `TranscriptError` and nothing is written).
- Bilingual (`bilingual:CODE`): `fetch_translation()` downloads the same caption track with `tlang=CODE` added (`with_query()`), i.e. YouTube's auto-translate, which keeps the original timing; several languages are downloaded one after another. The languages YouTube offers are read from the watch page (`ytInitialPlayerResponse` → `captions.playerCaptionsTracklistRenderer.translationLanguages`) into `info["yt2html_translation_languages"]` (`{code: name}`). YouTube answers `HTTP 429 Too Many Requests` to auto-translated captions requested soon after the video data was fetched; original captions and author subtitles are not affected. Until early November 2026 about a minute was enough (yt-dlp issue #13831, where a maintainer confirmed that waiting at least 60 s works); since about 12.11.2026 the refusal often lasts for days, from other networks, for other videos, also for yt-dlp alone, with curl_cffi impersonation, the `mweb` client and browser cookies, while the browser shows the translations (probably a PO token for subtitles is needed; not tried yet: a PO token provider plugin such as bgutil). So a translation is requested once, `translation_wait()` (a random 70–100 s, `TRANSLATION_WAIT`; a fixed delay looks automated) after fetching started (comments downloaded meanwhile count towards it), and not retried. What YouTube does not have (`TranslationUnavailable`: a language not offered, the message listing the available codes; a language equal to the transcript's own; an empty translation) or does not send (`TranslationRefused`, a subclass: 429 or any failed download, the reason from `refusal_reason()`, e.g. `YouTube refused to send it (HTTP 429 Too Many Requests)`) is logged (`No translation into 'fi': …`; a refusal adds that the page counts as finished and `--overwrite` adds it later) and kept in `missing`; the page leaves that version out and *About this copy* names it (`not available: bilingual:fi (reason)`). A video without captions is logged as `No transcript: …`. Only a failed download of the transcript itself raises `TranscriptError` during fetching, so nothing is written, not even `--write-json`, and the next run tries again (a page that is there counts as finished).
- **One download per caption track and run** (`caption_data()`): every caption track, for the transcript and for `--video sub:` files alike, is fetched as json3 (`fmt=json3` set on any address) through `caption_cache`, keyed by `caption_key()`: the address's `v`, `lang`, `kind`, `name` and `tlang`, so the same track from another fetch (other signature and expiry) is the same entry. A failure is kept too and raised again, so a refused translation is asked for once per run. The wait until `not_before` happens only on a real download. `main()` empties the cache at the start of a run (and `conftest.py` for each test). `align_translation()` gives each original cue the translated cues starting at the same time (or before the next original cue); `render_bilingual_transcript()` draws rows as a 3-column CSS grid (time, original, translation; on narrow screens the translation goes under the original, in grey).
- Option: `--transcript [VERSIONS]`, like `--video`: `nargs="?"`, `const=""` (the option alone: `[("plain", None)]`), default `[]` (no transcript: `fetch_info()` downloads none); one comma-separated argument, parsed by `transcript_spec()` into an ordered list of `(version, language)` pairs: `plain`, `timestamps`, `bilingual:CODE`. The value being optional, an address after a bare `--transcript` would be taken as versions: README documents `yt2html URL --transcript [VERSIONS]`, and an unknown item ends with "the video's address goes before --transcript". Anything unknown, `none` too, gets one message, `'none' is not a parameter (use plain, timestamps or bilingual:CODE); …`, worded like that of `--video`. Any case of letters: the items are lowered, the language code goes through `standard_code()` (language lower case, a two-letter region upper case, a script capitalised: `PT-br` → `pt-BR`, `zh-hans` → `zh-Hans`; YouTube's codes are written this way, checked on 164 codes in the test data), so no comparison against the data has to ignore case. A mutant `len(part) <= 3` survives on purpose: three-character regions are digits (`es-419`). Errors (argparse, before anything is fetched): empty item, unknown version (also `none`), `bilingual` without a language code, a code that is no language code (`check_code()`: `LANGUAGE_CODE` and yt-dlp's ISO 639-1 table or three letters, as `recognised_code()`; `jp` is not one), a language after `plain`/`timestamps`, a repeated item. The Command row of *About this copy* gives `--transcript` alone for `plain`, the versions otherwise, nothing without a transcript. `render_transcripts()` makes one section per item, in order (`render_transcript()`, class `transcript` or `transcript with-timestamps`; `render_bilingual_transcript()`, class `transcript bilingual`).
- `render_transcript()` puts each cue under the last chapter that starts at or before it (chapters from the chapter list described above; `<h3>` per chapter, empty chapters skipped). Without timestamps one `<p>` per part; with timestamps `<div class="cue">` rows.
- The cues are the caption lines, which is also how the panel divides the text; tiny differences to the panel are possible.

**Speaker changes.** YouTube's automatic captions start a new speaker's words with `>>` (`>>>` for a new topic), a convention of TV captions; translations do not have it. `speaker_html()` replaces each mark (`SPEAKER_RE`) with ours: in the timestamped and bilingual transcripts an empty `<span class="speaker" aria-hidden="true">` whose icon comes from CSS (`.speaker::before`: a speech bubble outline as an SVG `mask`, painted with `currentColor`, i.e. the grey `--muted`), and the translation of a cue with a mark gets one at its start too; in the continuous transcript a grey `<span class="speaker">|</span>` between spaces, left out at the start of a part (`at_start=False`). The cue data (and `--write-json`) keep YouTube's text. The lines under the video remove the marks (`textOf()` in `PLAYER_JS`).

## Images

- `fetch_image()` downloads with `urllib` (browser User-Agent, timeout, retries) and returns a `data:` URI; the MIME type comes from the response header or is sniffed from the bytes.
- Avatars are requested small: `=s88-...` in the URL is replaced by `=s{AVATAR_SIZE}`. They are downloaded in parallel (`ThreadPoolExecutor`).
- Each avatar is embedded **once** as a CSS class (`.av12{background-image:url(data:...)}`) and referenced by every comment of that author. The `<style>` in `<head>` is generated after the body, when all classes are known.
- A failed or missing avatar becomes a coloured circle with the first letter of the name (hue from a CRC32 of the name, so it is stable).
- The thumbnail falls back through `thumbnails` from best to worst if `thumbnail` fails.

## Text to HTML

`linkify()` escapes everything and recognises, in one regex pass: URLs (`http(s)://...`, `www....`; trailing punctuation and unbalanced `)`/`]` are cut off), timestamps `M:SS` / `H:MM:SS` (only valid values not longer than the video), `#hashtags` (not purely numeric), `@handles` (not inside e-mail addresses). Newlines are kept via `white-space: pre-wrap`.

## Theme

- All colours are CSS variables on `:root` (`--bg`, `--text`, `--muted`, `--panel`, `--line`, `--link`, `--chip`, `--media-bg`); the dark values are in `CSS`, the light ones (YouTube's light theme) in `LIGHT_VARIABLES`. New styles must use these variables, not fixed colours, or they break one of the themes. Exceptions that work on both: the red heart, the white letter on the coloured avatar circles.
- `theme_css()` adds, after `CSS`: nothing for `dark`; `:root{light variables}` for `light`; the same inside `@media (prefers-color-scheme: light)` for `auto`, so the page follows the device setting and changes with it, without JavaScript. `color-scheme` (CSS property and `<meta name="color-scheme">`) makes the browser draw scrollbars and the like in the matching colours.
- `--theme {auto,dark,light}` (any case: `type=str.lower`), default `auto`: the page itself follows the light/dark setting of whatever device or browser opens it, each time it is opened (in most browsers "device" means the system setting unless the browser's own appearance setting overrides it). Works with `--load-json` too (the theme is not stored in the data).

## Snapshot date

`render_page()` receives the date from `info["yt2html_archived"]` (today for older JSON files without it), so a page rebuilt with `--load-json` keeps the date of the original fetch. The `Snapshot` tile uses the class `fact extra` (grey value); `show_snapshot=False` (`--no-snapshot`) omits it, and the `Refreshed` tile too. *About this copy* and the comments note always show the date. `--update-json` and `--refresh-json` keep `yt2html_archived`; what they did is in `yt2html_updates`.

## File names

`ydl.prepare_filename({**info, "ext": "html"}, outtmpl=OUTPUT_TEMPLATE)` — yt-dlp's own sanitizer, so characters forbidden on Windows are replaced exactly as in the video file name (e.g. `:` → `：`).

## Existing pages, `--overwrite`

- **One rule for files with an id** (`files_with_id()` / `file_with_id()`, since 0.7.0): in the output folder (not its subfolders), a file whose name contains `[ID]` anywhere (with the brackets, the whole id) and ends with the right extension, in any case; the rest of the name does not matter. Pages: `.html` (`existing_page()`), saved data: `.info.json` (`saved_data_path()`), videos: `VIDEO_EXTENSIONS` without the one-format parts of an unfinished `--video` (`Title [id].f399.mp4`, `.f251.webm`; `video_files()`, used by the page (`video_files_for()`) and the index alike). Several matches: the first by name, with a note printed once per folder, id and kind (`first_of()`, `_SEVERAL_NOTED`). Before 0.7.0 the names had to end with `[ID].html` or `[ID].info.json`, and videos were only tried by exact names.
- A video counts as archived when the output folder holds such a page; pages may be renamed.
- The id is read from the URL without any request (`video_id_from_url()`: yt-dlp's `YoutubeIE.suitable()` / `extract_id()` for `watch?v=`, `youtu.be/`, `shorts/` and bare ids; the `v=` parameter for watch URLs with `&list=`, which yt-dlp gives to its playlist extractor). So a skipped video costs nothing. If the URL shows no id, the check is repeated after fetching, with `info["id"]`.
- Default: skip (`Skipped (page exists): ...`), and `archive()` returns `None`; `main()` counts saved, skipped and failed. `--overwrite` makes the page again; `--load-json` always does (no requests, and re-rendering is its purpose). A replaced page keeps its existing (possibly renamed) file name.
- Pages, saved data (`.info.json`) and SRT files are written by `write_atomically()`: first `NAME.part`, then renamed (`os.replace`), as bytes (UTF-8), so the line ends are the same on every system. An interrupted run leaves at most a `.part` file, which never counts as a finished page or subtitles file, and the earlier saved data stay whole (with `--update-json` and `--refresh-json` they are the only copy); a video that failed has no page and is tried again on the next run.

## Sources given by page names

`source_from_page_name()` turns a file name with an id in square brackets (`id_in_name()`: only the last path part counts, any extension, the last bracketed part that is an 11-character video id or a playlist id, so `Song [Remix] [ID] (copy).mp4` works and `[Remix]` is never taken for an id; not a URL) into the watch URL or the playlist URL; anything else stays as it is. `collect_sources()` applies it to the command line before removing duplicates, except with `--load-json` (see below). List files recognise such names themselves (`link_line()`, *The index* below).

## Sources with `--load-json`, `--update-json` and `--refresh-json`

- **Patterns:** `expand_pattern()` expands a source with `*` or `?` itself (Windows shells pass patterns on unchanged), sorted, in the command line. Square brackets are made literal (`[` → `[[]`), since every page and JSON name ends with `[VIDEO_ID]`. A pattern without matches stays and fails as `no file matches ...`.
- **`saved_data_path()`**, in `archive()`: an existing file is used as it is (so nothing that worked before changes); otherwise a video id, or any file name with a video id in square brackets (`id_in_name(…, playlists=False)`), is looked up in the output folder (`-o`) as a `.info.json` file with `[ID]` in its name, where `--write-json` writes it. Failures say what was looked for: `no saved data for ID in FOLDER (looked for *[ID]*.info.json)`, `no such file: ...`.
- An id starting with `-` would be taken for an option; then give the file or page name.
- **One JSON option at a time:** `parse_args()` refuses any two of `--write-json`, `--update-json`, `--load-json`, and `--update-json` with `--overwrite` (one keeps the data, the other downloads everything again). `--write-json` itself saves after a normal download (`rebuild()` in `archive()`), replacing an older file of the same name.
- **`--update-json`**, in `archive()`:
  - Sources: `collect_sources()` expands `*`/`?` patterns (not in URLs, whose `?` is no pattern) and keeps an existing `.json` file as it is (`update_source()`); other names with an id become URLs (`source_from_page_name()`), so playlists work as for a download. `update_data_path()` gives the saved data: the file itself, else `*[ID]*.info.json` in `-o` (`file_with_id()`), else None; a `.json` name that leads nowhere or an unmatched pattern fails that source. `source_video_id()` gives a data file the id in its name, so it is one video with its address everywhere: duplicates in `collect_sources()` and in `main()` (also after a playlist). With `--index FILE` the sources are the list's video ids (*The index* below).
  - With data (`updating`): `missing_for_update()` compares `--transcript` with them: the whole transcript when `TRANSCRIPT_KEY` is absent (None, i.e. no captions then, is not asked for again), else the bilingual languages neither in `translations` nor in `missing` with `refused: false`. Only then `update_transcript()` asks YouTube: fresh player data with yt-dlp (`skip_download`, no comments, no watch page), merged with the saved `CAPTION_KEY` and `TRANSLATIONS_KEY` (the track and the languages as the data know them), then `fetch_transcript()` or, for translations only, `choose_caption_track()` on that, checked against the saved transcript's kind and language (another track cannot be aligned: the targets are noted as refused, `the transcript's captions (…) are not in YouTube's data now`), and `add_translations()` (shared with `fetch_transcript()`: success removes the language from `missing`, an empty `missing` is removed). The same `caption_data()` cache and `translation_wait()` as a download. Nothing missing (and no `--video`): `Nothing to add from YouTube`, no request.
  - `note_update()` records the run in `UPDATES_KEY` (`yt2html_updates`: `[{date, time, yt2html, added, refreshed?, comments?, unavailable?}]`): one entry per run, `outcome["record"]`, made at the first thing that happens (nothing happened: no entry); `take_video()` adds the files this run downloaded (`video_added()`: dated today and not so in the saved data already) when `outcome["updating"]`. `about_downloaded()` names only the runs: `; updated 20.11.2026 10:12; refreshed 03.12.2026 18:40` (user's decision 15.11.2026: the row is for the date, address and programs; what a run added shows in the other rows, the details stay in the data). `ARCHIVED_KEY` and everything else stay.
  - The data go back to the file they came from (`save_json()` with `data_path`), first after the transcript, again in `rebuild()` after `--video`. The page is made from `shown()`: a copy narrowed by `--max-comments`/`--no-comments` (`narrow_saved_comments(view, args, note)`, the note once) and without the cards with `--no-cards` (their images are not fetched either), so the file keeps all comments and cards; the same for `--load-json`. `from_json` (the *Page built* row) is true for both. Interrupted comments in saved data do not stop the run (`CommentsInterrupted` only after a download).
  - Without data: no page (by the URL's id, or by the fetched data's id) means a full download with `write_json` on and a message; a page without data is skipped (`Skipped (page exists, no saved data to update): …`), no hidden `--overwrite`.
- **`--refresh-json`** is `--update-json` (`adding` in `archive()`: the same sources, data path, skip and save) plus a refresh before the missing parts are fetched:
  - `fetch_info()` for `watch?v=ID` with the run's options but `transcript=[]` (the saved transcript stays; `missing_for_update()` and `update_transcript()` then use this same fresh data and its start time for the wait, so no second extraction).
  - `refresh_saved()`: `REFRESHED_KEYS` (views, likes, subscribers, YouTube's comment count) where the fresh value is known; the title and description when changed, the earlier one in `yt2html_previous` (`[{until, title}]` / `[{until, description}]`; the page shows the current ones, no note, user's decision), and `MARKERS_KEY` when the watch page was read now (the chapters follow the description). Comments only when a list came: `"comments": None` in the fresh data (turned off or not shown, YouTube's message telling which) with saved comments opens an entry in `yt2html_comments_closed` (`[{from, until?, turned_off}]`, kept while it lasts; a list again closes it with `until`); no key at all (`--no-comments`) leaves everything. `comments_closed()` / `closed_note()`: the note above the comments (class `note closed`), `As of DD.MM.YYYY, comments on this video are turned off on YouTube; the ones below can no longer be seen there.` (or `YouTube no longer shows comments on this video; …`), and in the *Comments* row `; turned off on YouTube as of …` / `; no longer shown on YouTube as of …`. A comment a refresh adds gets `yt2html_first_seen` (the day; kept on later refreshes; not shown yet, backlog). `merge_comments()` by id: a fresh comment replaces its saved self, keeping `yt2html_edits` (`[{text, until}]`, a changed text) and `yt2html_missing` (`[{from, until}]`, the times it was missing and came back, which removes `yt2html_missing_since`); a new one is added; a saved one not sent stays, marked `yt2html_missing_since` (the day, kept on later refreshes) only when `comment_status(fresh)` is `complete` (with a limit or after `Ctrl+C` nothing is marked, silently). The saved ones not sent keep their place after the fresh neighbour that preceded them, so yt-dlp's order still breaks the ties of the coarse times in `build_comment_tree()`. `comment_count` becomes the merged number (`None` after `Ctrl+C`, so `CommentsInterrupted` stops the run after the page as with a download), `LIMIT_KEY` the fresh limit.
  - `note_update(…, refreshed=True, comments=stats)`: the record gets `refreshed: true` and `comments: {new, gone, back}` (absent when the comments were not refreshed); the page shows `refreshed DD.MM.YYYY HH:MM` only.
  - Not refreshed (on purpose, for now): info cards, the description extras and the rest of the watch page.
  - **The video no longer on YouTube:** `fetch_info()` raises `VideoUnavailable`. When `gone`, `archive()` sets `UNAVAILABLE_KEY` (`yt2html_unavailable: {status, reason}`, the state now, no history: user's decision), `note_update(…, unavailable=True)` (the record has `unavailable: true` and no `refreshed`, since nothing was refreshed), logs `No longer on YouTube: TEXT (recorded)`, skips `refresh_saved()` and `missing_for_update()` and goes on to save the data and make the page; the run counts as saved. Any other refusal propagates (`FAILED`, nothing saved, as a network error). A successful refresh removes `UNAVAILABLE_KEY`. On the page: `refreshed_tile()` shows the day of the last check (`unavailable_checks()`) as `fact extra warn` (`--warn-bg`/`--warn-fg`, red emerging from grey, both themes), also on the copy's day; `about_downloaded()` names each check `no longer on YouTube DD.MM.YYYY HH:MM` and, while `UNAVAILABLE_KEY` is there, YouTube's text in “ ” after the last one (user's decision 17.11.2026: the history lives in this one row; no note at the top of the page, no colour in the row); `page_metadata()` adds `yt2html:unavailable` (`YYYY-MM-DDTHH:MM` of the last check). `--update-json` and `--video` do not read the watch page, so for such a video they fail as before.
  - **Images of a gone video:** every page build downloads its images again, and YouTube's image server no longer gave any of the 38 thumbnails yt-dlp listed for a private video (17.11.2026, `U93QRMcQU5Y`). So when the thumbnail cannot be downloaded, `archive()` takes it from the page being replaced (`images_of_page(found)`: the `<img class="thumbnail" src="data:…">` of that page) and logs `Thumbnail could not be downloaded; kept from the existing page.`; a downloaded one always wins. Avatars and other images are not kept this way (their CSS classes do not record the address).
- **Comments at a rebuild** (`narrow_saved_comments()`): `--no-comments` leaves out the saved comments; `--max-comments N` keeps the first N in the saved order (yt-dlp's, replies counted), i.e. the comments a download with that limit gets, and sets the limit, so a cut after `Ctrl+C` counts as limited. A larger limit cannot widen the data: when the saved comments are limited or interrupted, a note says that `--refresh-json` without `--max-comments` adds the rest (it fetches all comments, merges them and takes the fresh limit, `None`). `--cookies-from-browser` has no effect and gets a note.

## Playlists

- `playlist_id_from_url()` recognises `/playlist?list=ID` (also `m.youtube.com`, a trailing `/`) and bare playlist ids (yt-dlp's `YoutubePlaylistIE.suitable()`), without a request; watch URLs with `&list=` stay videos. `is_channel_url()`: anything else that yt-dlp's `YoutubeTabIE` handles (`@handle`, `/channel/`, `/c/`, their tabs); these fail with a hint to use a playlist.
- `fetch_playlist()`: `extract_info(url, download=False, process=False)` with `extract_flat: "in_playlist"` (and the cookies): only the list, no video is extracted; `process=False` avoids yt-dlp's `Downloading item N of M` line per entry. A `url` / `url_transparent` result is followed (up to 3 times); anything but `_type: playlist` is an error. It returns the playlist's data with its entries as a list; the entries are read inside the `YoutubeDL` block, because yt-dlp fetches further pages (about 100 videos each) lazily. The tab extractor itself gives `title`, `description`, `channel`, `uploader_url` (`/@handle`), `channel_url` (`/channel/UC…`) and `playlist_count` (YouTube's "16 videos", unavailable videos included), also with `process=False` (yt-dlp's code; the real data in `tests/data/playlist_kurs.json` were saved with `-J --flat-playlist`).
- `read_playlist()` keeps a playlist in `Run.playlists`: id, title, address, channel with the link the video pages use (`channel_url`, by id, else `uploader_url`), count, description and the videos (`{id, url}`, in order, twice if listed twice). The entries' titles are not kept: YouTube sends them translated into the language of the request.
- `entry_video_id()`: the entry's `id` if it is a video id, else the id in its `url`; nested playlists and channels give `None` and are left out. Private and deleted videos are entries too: they fail when fetched (`FAILED: URL`) and are retried on every run.
- `main()` expands each playlist where it stands among the sources into watch URLs and archives them one by one, exactly like separate URLs (skipping, failures, summary). `seen` holds the video ids handled in this run: a video twice in a playlist, in two playlists or also given separately is archived once (`Playlist "TITLE": N videos (M duplicates ignored).`, or `Ignored duplicate: URL` for a separate URL after the playlist). A playlist that cannot be read counts as one failure. The summary counts videos and is printed whenever a playlist was given.
- Nothing about the run is stored: the next run reads the list again (new episodes are found), skips the videos with a page and tries the rest again.

**Ctrl+C.** yt-dlp catches `Ctrl+C` while it downloads comments: it ends only the comments, keeps those fetched so far and sets `comment_count` to `None` (`comments_interrupted()`; with comments disabled there is no list). `archive()` still makes the page and then raises `CommentsInterrupted` (a `KeyboardInterrupt`), so a run with several videos does not go on with the next one. `main()` catches any `KeyboardInterrupt` between and during videos, prints the summary without a traceback and returns 130. The page made from interrupted comments counts as finished on later runs (`--overwrite` remakes it).

## Info cards

The author's info cards (the "i" teasers during the video) are read from the watch page that `add_watch_page_data()` fetches anyway; the only further requests are their images and one per link card (below). With `--no-cards`, `add_watch_page_data(..., cards=False)` does not touch them (`CARDS_KEY` stays absent), and `archive()` also drops cards kept in a `--load-json` file before images are fetched.

- **Content:** the description panel's `videoDescriptionInfocardsSectionRenderer.infocards[].compactInfocardRenderer.content`, one lockup per card (`CARD_TYPES`, `parse_card()`):
  - `structuredDescriptionVideoLockupRenderer` (video): `title`, `shortBylineText` ("by …", the "by " is removed), `lengthText`, `metadataDetails`, `navigationEndpoint.watchEndpoint.videoId`;

## Local video player

The page plays a downloaded copy of the video lying next to it. Parts: `PLAYER_TILE` (a `<button class="fact play">`, first in `.facts`, same size as the other tiles: value `▶ Play` / `✕ Close`, label `Player` until the script knows the file: then `labelTile()` writes YouTube's quality name and the language of the audio in the video, `1080p · en-US`. The quality comes from `data-qualities` (`player_qualities()`: `{"1920x804": "1080p"}` from the data, by the file's `videoWidth` × `videoHeight`), else from the size by the same rule as `quality_from_size()`; the language from `data-language` (the main audio's code). The full code is kept only if the reference `1080p · CODE` fits the label (measured: `scrollWidth` against `clientWidth`), else the language alone (`en`), so a code looks the same at any quality; what still does not fit is cut off (`.fact.play .label{width:0;min-width:100%;overflow:hidden;white-space:nowrap}`: the label fills the tile but never widens it, so the tile stays as wide as the others)), `render_player()` (`<aside class="player">` before `<main>`: `<video preload="metadata">`, a range input with times, buttons `|◀ −10 s ↺ ▶ +10 s ▶|`, speeds `PLAYER_SPEEDS` 0.25–2×, 48 px each so that the eight fit one row in a 520 px panel; buttons with symbols or codes have an `aria-label` in English, the page's language: the name screen readers and voice control use, invisible; the play button's follows its symbol (`Play` / `Pause`), the audio switches' are the language as in the languages table plus the role, found by code and role since one language may have two tracks; an extra audio track is never set slower than 0.25×, below which Firefox mutes sound), `PLAYER_JS` (one inline `<script>` at the end of `<body>`), and the CSS block *Local video player* (colours `--accent`, `--on-accent`; width `--player-w: clamp(320px, 40vw, 720px)`).

**Other audio** (a working version, the interface to be refined): `render_page()` passes `audio_tracks` (`[(code, file, spoken name, file found, ending)]` from `yt2html_video.extra_audio`, i.e. only the tracks in the data: no other files are looked for, which would be fragile) to `render_player()`, which adds a last row `<div class="buttons audio">`: the original (`class="original"`, `data-audio=""`, the main audio's code or `orig`, 72 px, pressed) and one button per track (`data-audio` = the file name in the data, `data-found` = the file `audio_files_for()` found when the page was built: the video's id and the track's ending `audio_suffix()`, `.pl.dubbed.m4a`, by the rule of `files_with_id()`, any case; `data-suffix` = that ending). The script tries, in this order and each name once, `data-found`, the page's own name + `data-suffix` (renamed together with the page), `data-audio` (the name it was saved under); an `error` moves to the next name, and only when none is left the button is disabled. In `PLAYER_JS` `setAudio()` makes one pressed: a track → `new Audio(file)` (kept in `dub`), the video `muted`, the track set to the video's time and speed; the original → the track paused, the video's sound back. The track follows the video's events (`play`/`playing`: its time, then play; `pause`/`waiting`/`ended`: pause; `seeking`: its time; `ratechange`: the speed) and every 250 ms: the gap is averaged over the last four measurements (Firefox reports the time coarsely); more than 1 s → set to the video's time; a correction (3 % faster or slower, pitch kept by the browser) starts above 80 ms and ends below 20 ms (hysteresis); the speed is set only when it changes. A first version (jump above 0.3 s, threshold 40 ms, the speed set every 250 ms) clicked every few seconds in Firefox: jumps and speed changes can be heard. Simulated in Chromium with the time rounded to 50 ms: at most one speed change in 20 s, no jump; right after switching on a track the gap takes 2–3 s to close (up to ~140 ms at first). As soon as the video is found (its first `loadedmetadata`), `findTrack()` tries the same names for every track with a metadata-only `Audio`: the first that loads is kept in `data-file` (then the only name `setAudio()` tries), a track none of them reads is disabled at once, without a click; the switch stays in the HTML, so a file put back works the next time the page is opened. A track whose names all fail later, on a click, disables its button and switches back to the original (an `error` of a name tried meanwhile for another track is ignored). Not handled yet: media keys acting on the track itself, two versions of one language (both buttons show the code).

- **Finding the file (in the browser, every time the page opens):** a browser cannot list a folder, only try names. First the video files with `[id]` in their name found next to the page when it was built (`video_files_for()`, stored as exact names in `data-files`; so renamed videos work), then the page's own file name without `.html` (from `location.pathname`), then `video_names()` (yt-dlp's default name `Title [id]`, stored in `data-names`, for renamed pages), each with `VIDEO_EXTENSIONS` (`data-extensions`). A video added later is found only under the page's name or yt-dlp's name, otherwise after a rebuild. The candidates are tried one by one as the `<video>` source (`encodeURIComponent`, so `#`, spaces and Unicode work); the first whose metadata loads wins and adds `has-video` to `<body>`, which shows the tile. No file, or no script: the page looks as before.
- **States** (classes on `<body>`): `player-open` (panel `position:fixed` on the left, `.page` gets `margin-left: var(--player-w)` and no max-width, the thumbnail is hidden), `pip` (the video is in the browser's own picture-in-picture window, opened from its context menu or button: panel hidden, page and thumbnail as without the player; there is no button of our own since 0.7.0). Below 900 px the panel is `position:sticky` at the top.
- **Controls:** clicks blur the button, so the keys (handled on `document` only while the player is open and the focus is not in a form control or on a button) act on the video: `Space` play/pause, `←` / `→` ±10 s, `Shift+←` ↺, `Ctrl+←` / `Ctrl+→` start / end (a key map built from `Ctrl+`, `Shift+` and the key). **↺** (`actions.repeat`): the start of the cue before the current one of the *source* transcript; since the jump lands on that cue's start, the next click goes one cue further back without any timer. More than 20 s back, before the second cue, or without a transcript: 5 s back. Media Session `seekbackward` / `seekforward` give ±10 s in the browser's picture-in-picture window. Closing pauses and exits picture-in-picture; the position is kept. *Pop out* was removed in 0.7.0 (unused, took much room); the `pip` state stays for the browser's own window.
- **Timestamps:** every link to a moment of the video is made by `time_link()` (also the times `linkify()` finds in the description, the AI summary and comments): `<a class="t" data-t="SECONDS" href="…&t=…s">`. Transcript cues carry their start as `data-c` (`cue_start()`): `.cue` rows, `.bi-row` rows, and in the continuous transcript one `<span data-c>` per cue (invisible). While the player is open, one click handler on `document` intercepts plain left clicks on `a.t[data-t]` and on continuous-transcript spans (not while text is being selected) and plays the local copy from there; nothing in the page is rewritten, so closing the player needs no restore. Modifier clicks keep the YouTube link. Open adds `title="Play from …"` to the links (removed on close) and CSS turns them `--accent-text`.
- **Lines under the video** (`.now-playing`, hidden while both *Subtitles* and *Chapters* are off): current chapter (from `#chapters li`, shown by *Chapters*), and by *Subtitles* the current cue of the *source* transcript with 0, 1 or 2 cues before and after (`subtitles` 1–3, cycled 0→1→2→3→0; the mode is shown as CSS dots in `.dots`, hollow for 1, filled for 2 and 3, drawn with borders so hollow and filled have the same size; lines `prev2`, `prev`, `current`, `translation`, `next`, `next2`) (the first `.with-timestamps` or `.bilingual` section, else the continuous one), and the translation chosen with the language buttons: the script adds one `button.lang` per bilingual section (`data-lang`, set by `render_bilingual_transcript()`), in page order, into `.langs` next to *Subtitles*. They are `disabled` while *Subtitles* is off; `setLanguage()` is a switch (another language replaces the active one, the active one turns it off); `setSubtitles(0)` resets the language. The translation is the second `.text` of that section at the same time. All lines are 18 px: current bold in the text colour, translation bold grey with a faint touch of the accent (`color-mix()` of 30 % `--accent-text` into `--muted`, weaker than the chapter, so the eye switches easily between original and translation; browsers without `color-mix()` keep the grey), the others grey; the chapter above them is small, in `--accent-text` at 75 % opacity, one line with an ellipsis, and keeps its line (`visibility:hidden`, class `off`) while *Chapters* is off, so the sentences never move; 16 px above it, 7 px below; no line separates them from the buttons. The current chapter gets `now` in the chapter list while the player is open.
- **Follow:** `follow` is the index of the followed transcript section (−1 = off); the button cycles through them and shows `Follow N/M` when there are several; after the last one it is off (and starts again with the first). `lastFollow` keeps the one used last (in memory, until the page is reloaded), so after a scroll *Follow* starts there again. ## Video formats

The folded `<details class="formats-info">` just above *About this copy* (`render_video_formats()`), on every page. Without video and audio formats (`video_overview()` is None: no list, or only storyboards, the thumbnail grids for the seek bar's preview; YouTube sometimes sends nothing else for a while, seen on a Short fetched several times in a row) the summary is `none in the data` and the open section one line, `NO_FORMATS` + `NO_FORMATS_WHY` + `; make the page again later` (`<div class="none">`); a missing section would look like a fault of the page. No exception for data without a list. It shares the look of *About this copy* (CSS `.formats-info, .copy-info`; when both are there, *About this copy* follows closer). Folded, it shows `Video formats` and a summary (`video_overview()["summary"]`): short on purpose, only the top quality (`up to 2160p, 24 fps`, HLS counted) and the original audio's language (`original audio: en-US`, the code as in the table; left out when the original or its language is unknown); the tables tell the rest (tracks by role and subtitles were in the summary before, and machine translation after a `+` read as more languages); nothing at all leaves `Video formats` alone, without a separator; no date (the snapshot date in *About this copy* covers the whole page). Opened, two small tables (`formats_table()`), image and languages, and a line on machine translation; program matters (Deno, signed in) are in the *Video file* row of *About this copy*. No option: the data comes with every download (the formats are part of what yt-dlp fetches anyway) and with `--load-json`.

- **Tables:** size columns are right-aligned and never wrap (`class="size"`), the rest wraps; a table wider than the page scrolls sideways (`.formats`); an empty cell is a dash. From `formats` (`video_formats()`): video-only and audio-only formats without DRC variants (YouTube's *Stable volume*: a compressed copy of the same track); combined formats only when there is nothing else (storyboards drop out, having neither codec).
- **image:** one row per quality, i.e. YouTube's quality name and the frame rate, descending (`youtube_qualities()`: the number in yt-dlp's format note, `1080p`, `720p60`, `1080p Premium`; else the name of another format of the same size, since HLS formats have no note; else `quality_from_size()`: the shorter side, or 9/16 of the longer one when that is more, to the nearest step of `QUALITY_LADDER`, so a frame wider than 16:9 is named after its width as YouTube does, 1920×804 and 1080×1920 both `1080p`; else the height). A column `resolution` after it gives the real size (`1920×1080`; several sizes in one row joined by commas; an HLS-only row the HLS size). `quality_label()`: `1080p, 30 fps`; two rows when YouTube offers two frame rates at one height; a height only in HLS shows alone). A quality a download can take (up to `DEFAULT_MAX_HEIGHT`, with an ordinary AV1 or H.264 format: `RULE`) gets its parameter in brackets (`quality_parameter()`: `1080p, 30 fps (1080p30)`); higher qualities, vp9-only and Premium-only ones have none, since the download never takes them; × codecs (`codec_name()`: avc1→h264, av01→av1, vp9/vp09→vp9, hev1/hvc1→h265); the best format of each (the largest of alike formats), a dynamic range other than SDR, size with the main audio. Formats for Premium accounts (`is_premium()`: "Premium" in yt-dlp's format note) get their own columns after the ordinary column of the same codec (also in the audio table); kept on purpose, since sometimes they are the whole difference between data fetched signed in and not; never in the planned default. **HLS** formats (`is_hls()`: protocol `m3u8…`) have no size, only a declared bitrate, which proved far too high (3262 kbit/s against 276 kbit/s for the same 1080p h264 as one DASH file); they are only named, per height, in a last column *HLS (sizes unknown)*, and never used for sizes, the main audio (unless there is no other audio) or the planned default. Signed in, yt-dlp gets no HLS formats at all.
- **audio rows:** one row per track, i.e. language and role: columns `code` (first: the rows are in its order, and it is what `audio:CODE` will take), `language`, `role`, then aac and opus sizes; no caption hint (the table informs, it does not instruct). The language name (`language_name()`): yt-dlp's English format note of a single-file format of the track, its first part without ` original (default)` / ` descriptive` (`English (US) original (default), medium` → `English (US)`; a note that is only a quality word, such as `medium` for videos without dubs, gives no name); HLS notes are in the track's own language (`العربية - dubbed-auto`), so not used; else the name of the author's subtitles in that code (`Portuguese (Brazil)`, `Chinese (China)`; also for rows of subtitles alone); else YouTube's list of translation languages from the watch page (`yt2html_translation_languages`, full code, then the language alone); else the code. Audio formats without any language (seen on a TED talk: one track, no language in the data): `FormatChoice` takes `transcript_language()` (the watch page's default subtitles for the track, the same guess the *Transcript* row shows as "original language"), so the track's code joins the author's subtitles in one row; with nothing to go by it stays `UNKNOWN_LANGUAGE`. `download_video()` builds its `FormatChoice` with the page's `CAPTION_KEY` and `TRANSLATIONS_KEY` for the same guess. `subtitle_tracks()` lists codes alphabetically (console and `--video-formats`); a refused translation (429) ends with `TRANSLATION_HINT`, as for bilingual transcripts. The role is YouTube's kind of track (`audio_kind()`), which yt-dlp does not pass on but every format address carries in its `xtags` (`…&xtags=acont%3Ddubbed-auto%3Alang%3Dpl&…`, in HLS addresses a path part `/xtags/…/`): `acont=original` → *original*, `dubbed` → *dubbed* (by the author: YouTube's multi-language audio), `dubbed-auto` → *auto-dubbed* (YouTube's automatic dubbing), `descriptive` → *descriptive* (audio description); another value is shown as it is (`AUDIO_KINDS`). `xtags` is undocumented, so without it the role comes from yt-dlp's `language_preference`: 10 original, -10 descriptive; a video with a single language has nothing to mark it by, so that track is the original; otherwise *dubbed* when an original is known, else no role. In the console list (`--video-formats`) the tracks are grouped by role (original, dubbed, auto-dubbed, descriptive, other kinds by name, no role), then by language code; on the page they are ordered by language (see *languages*); one language may have two rows. A track without a language in the data (`UNKNOWN_LANGUAGE`, e.g. Shorts) has no code (`–`) and the name `unknown`; texts leave the language out (`sizes include the audio: aac`, `… av1 + aac, mp4`, `audio: original` in the summary), `--video-formats` says `unknown language`, and the player tile shows the quality alone. YouTube names some Shorts formats of 608×1080 `480p` (vp9 `779`/`780`, av1 `787`/`788`), so a row may have two resolutions (`480×854, 608×1080`). The main audio is the original's aac, else its other codec; without an ordinary (non-Premium) original, the largest ordinary track, an audio description only when there is nothing else.
- **languages** (one table for audio and subtitles, caption `languages`): the audio rows above, plus columns `subtitles by the author` (`subtitles` without `live_chat`) and `auto-generated subtitles` (yt-dlp's `-orig` tracks: made from one audio track's speech, so a dub has its own). Joining (`joined()`): the author's subtitles belong to the video, so they go to the row of the same code, else the only row of the same language (an audio description only when it is the only one); automatic ones go to their audio's row by language, or to the only audio track when its language is unknown; anything else gets a row of its own (code from the subtitles, name from the translation list, `–` for audio and sizes). A cell may list several codes (`es, es-ES`), each the code its parameter will take. Order (`language_order()`): languages with audio first, the original's language first, then the others alphabetically by language; within a language, audio rows by role (then code), then the subtitles' own rows; languages without audio at the end, alphabetically. The subtitles the transcript takes are not marked: no subtitles file is downloaded by default, and a mark will show only an actual choice (`sub:` with `--video`, yellow). Under the table, one line in four versions, always `machine-translated subtitles: …` (the label says subtitles, since an auto-dubbed track is a machine translation too): `possible in N other languages for each row with subtitles` (N: YouTube's list of target languages from the watch page, `yt2html_translation_languages`, given only for videos with subtitles, else yt-dlp's translation entries, minus the source; "for each row" so that it does not read as N more languages; YouTube translates any subtitles on request with `tlang`, nothing is stored per language); `none (no subtitles to translate)` (no subtitles at all); `unknown (YouTube listed no translation languages)` (subtitles, list read but empty: YouTube's side, trying again will not help); `unknown (not read from YouTube; make the page again later)` (subtitles, no list in the data: the watch page could not be read, or older data; technical, may pass). yt-dlp's own translation entries take the first automatic track as the source (for auto-dubbed videos a dub), so yt2html never uses them: translations are built from the original track, as for the transcript.
- **Choice and presentation are apart:** `FormatChoice` (made by `video_choice()`, None without video or audio formats) holds what a download can take, with no HTML: DASH and HLS formats, audio tracks (`track()`: language and `role_of()`), `original`, `main_audio`, `audio_for()`, `best()`, `quality()` (YouTube's names), `with_audio()` (size with the main audio) and `variants` (up to `DEFAULT_MAX_HEIGHT`, best first, each with height, fps, format, codec, quality label, parameter and size). `video_overview()` builds the tables, the summary and the console lines from it and adds each variant's place in the image table (`row`, `column`). `--video` is meant to take from `FormatChoice` directly (on a fresh list of formats).
- **The planned default** (what the download will take without parameters): the first of `video_overview()["variants"]`, i.e. the best quality up to `DEFAULT_MAX_HEIGHT` (1080p; highest frame rate first) that has AV1 or H.264, then AV1 there, else H.264 (never vp9 or Premium: the file is mp4 and plays everywhere), with the main audio, mp4. The quality comes first: 1080p only in H.264 beats 720p in AV1. Its cell is marked with `class="planned"` (text in `--planned`: light blue `#9cc3e8` in the dark theme, blue `#2f6a9e` in the light one; softer than links; yellow is reserved for what the user actually chose, once `--video` downloads), as is the main audio in the languages table; the captions carry no colour legend (README explains the colours; with `--video` blue would soon stop being the only mark). Without a main audio, or without an AV1/H.264 quality up to 1080p, nothing is marked and `--video-formats` has no `(default)`. Tests check the choice through `planned()` in `test_about.py` (the `(default)` line and the audio of the image caption). Later, with `--video`, yellow will mark the actual choice (what was asked for or downloaded) and blue stays for the default.
- Sizes (`format_size()`): `filesize`, else `filesize_approx`, else `tbr` × duration; `human_size()`: `~X.X GB` from 1 GB, `~N MB`, below 1 MB `<1 MB` (Shorts); escaped on the page (`&lt;1 MB`), plain on the screen.

### --video-formats

## Page metadata and the index (`--index`, `--index-only`)

**Metadata.** Every video page has invisible `<meta name="yt2html:...">` tags in its `<head>`, before `<title>` and the large `<style>` (`page_metadata()`). They are the index's only source about a page (it never reads the page's content). **The contract (user's decision 18.11.2026: unambiguous for later use):** a page with `metadata` = `2` (`METADATA_VERSION`) has every tag whose value is known; **an absent tag means the value is unknown** (for `refreshed` and `unavailable`: it did not happen); a tag is never written with an empty value. A page without `metadata` was made by an older version and has to be made again (no backward compatibility before 1.0). Times are local, of the computer that downloaded or refreshed, `YYYY-MM-DDTHH:MM`.

- **Notes**: the user's notes go through `note_html()`: escaped text, links in simplified Markdown, `[text](https://address)` only (`NOTE_LINK_RE`: an `http(s)://` address up to the first `)` or space; empty brackets show the address; a bare address, a space before `(`, another scheme or an unclosed link stay text; the user, 20.11.2026: before, bare addresses became links), and `**bold**`, `*italic*`, `_italic_` (not inside words, not across spaces at the edges; unclosed marks stay; round a link too, never inside its text). Links are taken out first and held as `\0N\0` marks (NUL characters in the text are dropped, so text cannot pose as a mark), so escaping and emphasis leave them alone. YouTube's own texts (a playlist's description) go through `links_only()`: escaped, bare `http(s)://` addresses as links (`trim_url()`), nothing else. A playlist's notes (`playlist_notes()`; the user's order, 21.11.2026): `Playlist` + title link · `N videos` (YouTube's count) + the span of the videos' publication days in grey (`<span class="days">`, `--muted`) · `Channel` + channel link (its name alone without a link); then the description as written (`white-space: pre-wrap`, class `about`, links only). The span (`published_range()`): oldest to newest (not first to last), `DD.MM.YYYY–DD.MM.YYYY`, one day alone; `known range …` / `known …` when a listed video has no page, no `yt2html:published` or an unreadable one (counted against the videos YouTube listed, not its count, which includes hidden ones; a video listed twice changes nothing); nothing when no day is known; after the title when there is no count. The days come from the pages' metadata (`Builder.published()`), read once per video with the row (`Builder.page_of()`, cached): YouTube's flat playlist has no dates, and asking per video would cost a request each.
- **Page** (`render_index()`): the page CSS plus `INDEX_CSS` (colours only through the variables; `--badge-bg`/`--badge-fg` for the duration on the image, the same in both themes; weights 600 and 700, never 500: Segoe UI on Windows has no 500 and shows it as regular, user's remark 19.11.2026 about the video titles), `.page` width as the video pages, `<meta name="yt2html:index" content="list">`, title, the blocks, the footer `Index made with yt2html on DD.MM.YYYY.`, the kept playlists, the player panel (`render_player()`, first in `<body>`) and its script (`PLAYER_JS`, last). `write_index()` writes it atomically to `index_path()` (`-o`, the list's name without its last extension + `.html`), making the folder.
- **Player** (spec: the user's notes, 5.4 *Panel odtwarzacza spisu*, 18.11.2026): the page player's look (`core.CSS`: `.player`, shown only with `player-open` on `<body>`, which the script sets, so without JavaScript the panel stays hidden; below 900 px sticky above the list) with its own markup and script, separate from the page player's (user's decision 19.11.2026: a shared core later, when the player moves into a module). Rows with a video file give their thumbnail (or round button) `data-file` (the file's address relative to the index, `urllib.parse.quote`); the script makes those buttons (`role`, `tabindex`, `aria-label` *Play: title*; `Enter`/`Space`). The panel: `<video preload="none">` in `.ix-screen` with `.ix-failed` over it, the position bar, one row `.ix-controls` of eight buttons all 50 px (`previous`, `start`, `back`, `toggle` (`main`, accent), `forward`, `end`, `next`, `autoplay` with `aria-pressed`), the speeds as on the page (`defaultPlaybackRate`, so the speed survives a new `src`), `.ix-playing` (the row's `.name` text: `=`, the page title or the file's name). The row playing has the class `now`: a 2 px accent ring round its thumbnail (the round button turns accent) and its title in `--accent-text`; no background for the whole row, which would light up its notes too (the user, 19.11.2026). State: `items` (every `[data-file]` in order), `current` (−1 before the first play), `failed` (indexes, in memory until reload), `playOn` (what previous / next carry, user's decision 19.11.2026: `load(i, play)`; previous / next pass `!video.paused` of the current file, so playing goes on and stopped (paused, `|◀`, ended) waits; from a failed file the `playOn` of its own load, i.e. the state before it; a thumbnail and Autoplay pass `true`). `load()` sets `preload` to `metadata`, so a waiting file shows its duration and first frame (the panel starts with `preload="none"`: nothing is read before the first play). A failed file needs no label change: the browser fires `pause`. `setState()`: before the first play everything is disabled (also `A`, the speeds and the bar); a failed file disables the controls and the bar, not previous/next, `A` or the speeds; previous/next by `playableFrom()` (skipping failed files; rows without a file have no `data-file`). A video `error` marks the file failed (row `failed`, thumbnail dimmed, `.ix-failed` with the title); the browser gives the same error for a missing file and an unplayable format (Chrome: code 4), so the reasons are only in README. `ended` with `A` on: the next playable file; a new error stops there. `reveal()`: a row out of sight comes into view by the shortest `scrollBy` with a 48 px margin (smooth unless `prefers-reduced-motion`), the visible part starting below the panel when it is sticky; Autoplay reveals only if the row that ended was visible. Keys on `document` (not in form controls or on buttons; the thumbnails stop only `Enter`/`Space`): the page's keys plus `Shift+P` / `Shift+N`, each only when its button is enabled. `mediaSession`: seek ±10 s, previous and next track. `pip` as on the page.

## Testing

**Run the tests after every change**, in the project folder:

```powershell
uv run pytest
```

The first run installs pytest into the project's `.venv` (the `dev` dependency group in `pyproject.toml`; it is not part of the installed program). A run takes about a second, needs no network and ends with a line such as `349 passed, 7 skipped`. `uv run pytest -q` prints less, `uv run pytest -x` stops at the first failure, `uv run pytest tests/test_chapters.py` or `-k bilingual` runs a part.
