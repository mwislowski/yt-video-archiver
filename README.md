# yt-video-archiver

`yt2html` saves a YouTube video page as **one self-contained HTML file** for offline use, in the spirit of the SingleFile browser extension: description, chapters, transcript and all comments, readable without YouTube and without an internet connection. It uses [yt-dlp](https://github.com/yt-dlp/yt-dlp); no AI, no browser, no API key.

The video itself and its subtitles are **not** downloaded; download them separately (e.g. with yt-dlp). The page gets the same base name as yt-dlp's default video file name, `Title [video id].html`, so both can sit side by side.

## What the page contains

- **Thumbnail, title, channel** with its avatar and subscriber count.
- **Facts:** duration, publication date, views, likes, comment count, and in grey the *Snapshot* date (when the data was downloaded; added by the program, not by YouTube).
- **Full description** (what YouTube hides behind *Show more*) with clickable links, timestamps, `#hashtags` and `@handles`.
- **AI-generated video summary**, if YouTube offers one.
- **Chapters**, with a grey note saying whether they come from the description or were generated by YouTube, and other timestamp lists such as **Walkthroughs**, as plain vertical lists.
- **Info cards** the author placed in the video (the small "i" teasers linking to another video, a playlist, a channel or a website), with the time they appear, an image and the author's message.
- **People mentioned** (photos, names, descriptions) and **Explore the podcast**, if YouTube shows them.
- **Transcript**, already open, split by chapters; as continuous text, with timestamps, or side by side with a translation.
- **License**, if it is not the standard YouTube one (e.g. Creative Commons).
- **All comments**, oldest first, every thread fully expanded, with likes, pinned and creator marks.
- **A player for your downloaded copy of the video**, if it lies next to the page (see below).
- **Video formats**, folded near the bottom: the qualities, codecs and approximate sizes YouTube offers for the video, its audio tracks (original, dubbed, auto-dubbed, audio description) and subtitles (see below).
- **About this copy**, folded at the bottom: how this copy was made and what it lacks (see below).

Images are embedded in the file. The page works without JavaScript; a small built-in script only adds the player. It shows in light or dark colours according to the device it is opened on. Not included: YouTube's own video player, recommendations, YouTube's *Video details* (it repeats the facts).

## Installation

Requires [uv](https://docs.astral.sh/uv/) (it also installs a suitable Python by itself).

```powershell
uv tool install git+https://github.com/mwislowski/yt-video-archiver
uv tool update-shell
```

`uv tool update-shell` adds uv's command folder to `PATH` (once; open a new terminal afterwards). Check with `yt2html --version`.

| Task | Command |
|---|---|
| Update the program and yt-dlp | `uv tool upgrade yt-video-archiver` |
| Remove the program | `uv tool uninstall yt-video-archiver` |

Optional: a JavaScript runtime recommended by yt-dlp for YouTube, e.g. Deno (`winget install DenoLand.Deno`; macOS `brew install deno`). Without it yt-dlp prints warnings about video formats; they are harmless for the page, but YouTube may then offer fewer video formats (the *Video formats* section then lists fewer).

### macOS and Linux

The program and its commands are the same; only uv is installed differently (then run the two commands above):

```sh
brew install uv                                    # macOS with Homebrew
curl -LsSf https://astral.sh/uv/install.sh | sh    # Linux, or macOS without Homebrew
```

Differences from Windows: put page names in quotes (`'Title [ID].html'`: square brackets are pattern characters in bash and zsh); a colon in a title stays `:` in file names (Windows gets `：`), so the same video has a slightly different file name on each system; browser cookies work with Chrome and other Chromium-based browsers too (macOS asks for Keychain access; Safari needs Full Disk Access for the terminal). The program is tested on Linux; macOS has not been tried yet.

## Usage

```powershell
yt2html "https://www.youtube.com/watch?v=..."
```

The page is saved in the current folder (e.g. the folder with your downloaded videos); `-o FOLDER` saves it elsewhere. Always put the URL in quotes: in PowerShell `&` in a URL would otherwise be treated as an operator.

Instead of a URL you can also give a video or playlist id (`Z8lf5oWKfj0`, `PLeBgIYTbh-CzUlJnPXenyingrNSXQgFoa`) or any file name with the id in square brackets, wherever it stands and whatever the extension (a page, an index, a downloaded video): `"My title [Z8lf5oWKfj0].html"` or `"My title [Z8lf5oWKfj0].mp4"` stands for that video, `"Python course [PLeBgIYTbh-CzUlJnPXenyingrNSXQgFoa]"` for that playlist. Handy with `--overwrite` and `--index-only`. This also works in list files.

**What to archive**

| Task | Command |
|---|---|
| One video | `yt2html "URL"` |
| Several videos at once | `yt2html "URL1" "URL2" "URL3"` |
| All videos of a playlist (see below) | `yt2html "https://www.youtube.com/playlist?list=..."` |
| Videos listed in a text file (see below) | `yt2html -a list.txt` |
| Save into another folder | `yt2html "URL" -o "D:\Videos\Channel"` |
| Make a page again although the video already has one (e.g. for newer comments); also works for a whole playlist or list | `yt2html "URL" --overwrite` |
| When YouTube asks to sign in or to confirm you are not a bot (`--cookies` is short for `--cookies-from-browser`; the browser need not be open; without a profile, the one used most recently) | `yt2html "URL" --cookies firefox` |
| The same with a given browser profile: its folder name (Firefox: `about:support`, *Profile Folder*) or path | `yt2html "URL" --cookies "firefox:fTW1hk7Y.Profile 1"` |

**Index page** (see below)

| Task | Command |
|---|---|
| Archive a playlist and make its index | `yt2html "PLAYLIST URL" --index` |
| Archive a list file and make its index | `yt2html -a list.txt --index` |
| Only rebuild the index, e.g. after renaming pages (no download) | `yt2html "Index name [PLAYLIST_ID].html" --index-only` / `yt2html -a list.txt --index-only` |
| Make all pages of a playlist again, with the index | `yt2html "PLAYLIST URL" --overwrite --index` |

**What the page contains and how it looks**

| Task | Command |
|---|---|
| Without comments | `yt2html "URL" --no-comments` |
| Only the first N comments (quick test) | `yt2html "URL" --max-comments 200` |
| Transcript versions (see below) | `yt2html "URL" --transcript plain,timestamps` |
| Without info cards | `yt2html "URL" --no-cards` |
| Without the avatars of comment authors (smaller file; the channel's avatar stays) | `yt2html "URL" --no-avatars` |
| Without the grey Snapshot date tile (the date stays in *About this copy*) | `yt2html "URL" --no-snapshot` |
| Page always dark / always light (default: follows the device) | `yt2html "URL" --theme dark` / `--theme light` |

**Other**

| Task | Command |
|---|---|
| Download the video so that the page can play it (mp4 that every browser plays) | `yt-dlp -f "bv*[vcodec^=avc1]+ba[ext=m4a]/b[ext=mp4]" --merge-output-format mp4 "URL"` |
| List the qualities a video download can take and the audio tracks it can add, without making a page | `yt2html "URL" --video-formats` |
| Also keep the raw data | `yt2html "URL" --save-json` |
| Rebuild a page from saved data (no download; keeps the snapshot date) | `yt2html --from-json "Title [id].info.json"` |
| The same, by the video id: the saved data is looked up in the folder given with `-o` (default: the current folder) | `yt2html --from-json VIDEO_ID -o "D:\Videos"` |
| Rebuild several pages; `*` and `?` work also in PowerShell and cmd, square brackets are part of the name | `yt2html --from-json "D:\Videos\*.info.json" -o "D:\Videos"` |
| Rebuild with fewer comments (only fewer: more need a new download) | `yt2html --from-json VIDEO_ID --max-comments 100` or `--no-comments` |
| Versions of the program and yt-dlp | `yt2html --version` |
| All options | `yt2html --help` |

Options can be combined, e.g. `yt2html -a list.txt -o "D:\Videos" --max-comments 500 --index`.

### Transcript versions

`--transcript` takes one or more versions, separated by commas without spaces; they appear on the page in that order.

| Value | Result |
|---|---|
| `plain` (default) | continuous text, without timestamps |
| `timestamps` | one line per caption, each with its timestamp |
| `bilingual:LANG` | like `timestamps`, with YouTube's machine translation into `LANG` (e.g. `bilingual:pl`) in a second column |
| `none` | no transcript |

Examples: `--transcript plain,timestamps`, `--transcript plain,bilingual:pl,bilingual:de`. Each version may appear only once and `none` cannot be combined with others. If a requested translation is not available, the program stops with an error, lists the languages that are, and saves nothing.

### Archiving many videos

For many videos, put their URLs into a text file, one per line, e.g. `list.txt` made in Notepad, and run `yt2html -a list.txt`. Blank lines and lines starting with `#` are ignored, so the list can have comments:

```text
# Season 1
https://www.youtube.com/watch?v=Z8lf5oWKfj0
https://youtu.be/qyqCTMirNWg
```

`-a` can be given several times and combined with URLs in the command; a video listed more than once (also in another URL form) is archived once. The file must be saved as UTF-8 (Notepad's default). The program only reads it, never changes it.

**Playlists:** a playlist URL (`https://www.youtube.com/playlist?list=...`), in the command or in a list file, archives all videos of the playlist in its order, e.g. all episodes of a podcast. A link to a video opened from a playlist (`watch?v=...&list=...`) archives only that video. Channel URLs (`@name`) are not supported: open the channel's playlist and use its URL.

**Videos that already have a page are skipped**, so running the same command again only archives what is missing, and an interrupted run continues where it stopped. A page is any `.html` file with the video id in square brackets in its name, e.g. `[Z8lf5oWKfj0]`: you may rename pages freely (`042 My title [Z8lf5oWKfj0] (copy).html`) as long as that part stays. If several files fit, the first by name is used and a note says so. Only the output folder itself is checked, not its subfolders. To make a page again, delete it or use `--overwrite` (the page keeps its current name). `--from-json` always replaces the page.

### Index page

With `--index`, a playlist URL and a list file each also get an **index page** in the output folder, in the same style and colours as the video pages:

- a playlist: `Playlist title [playlist id].html`, e.g. `Python course [PLeBgIYTbh-CzUlJnPXenyingrNSXQgFoa].html`;
- a list file: its name with `.html`, e.g. `list.html` for `list.txt`. Playlists in the file appear as sections with their own heading.

Single URLs given in the command get no index.

For each video the index shows its position, its original title linking to its page, the date the page was made, a link to the video on YouTube, and below the title a small line about the comments:

| Line | Meaning |
|---|---|
| `523 comments · complete (YouTube: 530)` | all comments were downloaded; YouTube's own count is usually a bit higher (deleted or hidden comments) |
| `200 of 1 204 comments · limited` | the download was limited (`--max-comments`) |
| `312 of 318 comments · interrupted` | the download was stopped with `Ctrl+C` |
| `Comments not downloaded` | made with `--no-comments` |
| `Comments turned off` | the author has turned comments off |

Videos without a page have a grey title without a link, and instead of the date the reason (hover over *Failed* to see YouTube's message):

| Reason | Meaning |
|---|---|
| `Unavailable` | YouTube marks the video as private or deleted |
| `Failed` | the last attempt to archive it failed, e.g. `Sign in to confirm your age` (then try `--cookies firefox`) |
| `Not archived yet` | not tried yet, e.g. because the run was stopped with `Ctrl+C`, or its page was deleted |
| `Not a video` | only in a list file: a line with a channel or an unknown URL |

Good to know about the index:

- **It always shows the current state of the folder.** It is made at the end of the run, also after `Ctrl+C` (then it lists the whole playlist, with the videos not reached yet in grey). If the program was stopped in any other way, the next run makes it again. Nothing about earlier runs is stored elsewhere: the index itself remembers the list and the reasons, and a reason stays until the video is tried again.
- **Renaming is safe.** Pages are found by `[video id]` in their names, so after renaming them the index links to the new names and still shows the original titles. The index of a playlist is found by `[playlist id]` and may be renamed the same way; the index of a list file must keep its name.
- **`--index-only` downloads nothing.** It only rebuilds the index from the pages in the folder, e.g. after renaming or deleting pages. It uses the list kept in the earlier index; only if there is none yet, it reads the playlist's list from YouTube (one request, no video). New videos added to the playlist on YouTube appear only after a normal run with `--index`.

### Watching a downloaded video on the page

If the downloaded video lies **next to the page**, the page shows a turquoise **▶ Play** tile first among the facts. A browser cannot look into a folder, it can only try names, so the page tries, each time it is opened:

1. video files with the video's id in square brackets in their name, found **when the page was made**, whatever the rest of the name (`042 renamed [id].mp4`);
2. the page's own name (`Title [id].mp4` next to `Title [id].html`; also after renaming both the same way);
3. yt-dlp's default name `Title [id]` (when only the page was renamed).

So a video downloaded later works without making the page again if it has the page's name or yt-dlp's default name; under any other name, make the page again (`--from-json` or `--overwrite`) and it is found by its id. The same after renaming a video. Formats: `.mp4`, `.webm`, `.m4v`, `.mkv`.

**▶ Play** opens a player pinned on the left, so you can watch (or listen to a podcast) while scrolling the description, chapters, transcript and comments on the right; the thumbnail is hidden meanwhile. **✕ Close** pauses the video and restores the page; *Play* continues where you stopped.

- Buttons: to the start (stops the video), 10 seconds back, **↺ previous sentence**, play/pause, 10 seconds forward, to the end, and the speeds 0.5×, 0.75×, 1×, 1.25×, 1.5×.
- **↺** goes back to the start of the previous sentence of the transcript, handy for repeating a phrase when learning a language; each further click goes one sentence further back. If that would be more than 20 seconds back (a long pause, music), or the page has no transcript, it goes 5 seconds back.
- Keys while the player is open: `Space` play/pause, `←` / `→` 10 seconds back/forward, `Shift`+`←` previous sentence, `Ctrl`+`←` / `Ctrl`+`→` to the start / to the end.
- A separate video window (picture in picture) is available through the browser itself: right-click the video in Chrome or Edge, or use Firefox's own button on the video; the page returns to its normal layout meanwhile.
- On narrow windows and phones the player stays at the top and the page scrolls below it.
- Browsers play mp4 with H.264 video and AAC audio everywhere (the yt-dlp command in the table above downloads it). Videos in HEVC/H.265 do not play in Firefox; `.mkv` plays only in some browsers.

**Timestamps play the local copy.** While the player is open, a click on a timestamp plays your copy from that moment instead of opening YouTube (the timestamps turn turquoise). This works everywhere the page has timestamps:

- chapters and other timestamp lists (e.g. Walkthroughs);
- info cards;
- the transcript with timestamps and the bilingual transcript;
- the description and the AI-generated summary (times written in the text, e.g. `12:30`);
- comments (e.g. `3:15 best part`);
- the continuous transcript: it shows no times, but each sentence knows its own, so a click on a sentence plays from there.

With the player closed, timestamps open YouTube as before; `Ctrl`+click always opens YouTube.

**Subtitles under the video.** *Subtitles* (off at first) shows the current sentence of the transcript under the video; each click adds context and then turns it off again: the sentence only (one hollow dot on the button), with one sentence before and after it in grey (one dot), with two (two dots), off. The sentences come from the first transcript with timestamps on the page (plain or bilingual), otherwise from the continuous one. Next to *Subtitles* there is a small button for each translation on the page (`pl`, `de`, … in the order of the bilingual transcripts; none without one). They work once *Subtitles* is on: a click shows that translation under the current sentence, another language replaces it, and a second click on the active one hides it. Turning *Subtitles* off also turns the translation off. A click on the subtitles shows the place in the transcript on the right: in the followed transcript while *Follow* is on, otherwise in the one the subtitles come from.

**Chapters** (off at first) shows the current chapter above the subtitles, on one line (a long title is cut with `…`); its place stays reserved, so turning it on or off never moves the subtitles. The current chapter is also marked in the chapter list. Buttons appear only when there is something to show: a page without a transcript has only *Chapters*, a page without chapters has no *Chapters*.

**Follow** marks the current sentence in the transcript on the right and keeps it in view as the video plays. With several transcripts on the page, pressing *Follow* again moves to the next one (*Follow 2/3*), and after the last one it turns off. Scrolling the page yourself also ends it; *Follow* then starts again with the transcript you followed last (as long as the page stays open).

### Video formats

Above *About this copy*, *Video formats* is folded to a grey line with a summary (`up to 1080p, 30 fps · audio: en original + 20 auto-dubbed · subtitles: …`). Opened, it lists what YouTube offered when the data was fetched: the image by quality (height and frame rate, e.g. `1080p, 30 fps`) and codec (h264, av1, vp9; formats for YouTube Premium accounts in their own columns; HLS formats only named, since YouTube gives no reliable size for them) with approximate sizes including the audio, the audio tracks (code, language, role: original, dubbed by the author, auto-dubbed by YouTube, audio description), and the subtitles. A quality a download of the video can take (up to 1080p, in AV1 or H.264) has its parameter in brackets, e.g. `1080p, 30 fps (1080p30)`. The marked cells show what a download would take by default: the best quality up to 1080p in AV1, else H.264, with the original audio, as mp4. The video itself is not downloaded by yt2html yet; the *Video file* row of *About this copy* names a video file found next to the page (or says `not downloaded`) and notes how the list came about (with or without Deno, signed in or not).

`--video-formats` prints the same choice on the screen without making a page (only the video's data is fetched, no comments; with `--from-json` from saved data, offline). It cannot be combined with the options that shape a page.

```
Give Me 1 Hour, I Will Make Artificial Intelligence Click Forever [fCEvvkAbJOs]
image (mp4; AV1, else H.264; sizes with the original audio):
  1080p, 30 fps  (1080p30)  av1  ~293 MB  (default)
  720p, 30 fps   (720p30)   av1  ~214 MB
  ...
audio (m4a, aac, ~69 MB each):
  in the video: en-US (original)
  auto-dubbed: ar, bn, de-DE, es-US, fr-FR, hi, id, it, iw, ja, ko, ml, nl-NL, pa, pl, pt-BR, ru, ta, te, uk
```

The audio lines show the track in the video and, by role, the dubs a download can add as separate m4a files (`audio:CODE`, e.g. `audio:pl`; an audio description as `audio:CODE.descriptive`). The parameters in brackets and `audio:CODE` are meant for a later version of yt2html that downloads the video itself.

### About this copy

At the bottom of every page, *About this copy* is folded to a single grey line with the snapshot date, which is there in any case, also with `--no-snapshot`. Opened, it describes this particular copy in rows that are always the same: *Downloaded*, *Page built*, *Playlist*, *Command*, *Video page*, *Markers* (chapters and other timestamp lists such as Walkthroughs), *Info cards*, *Transcript*, *Comments*, *Images*, *Video file*, *Software* and *Disclaimer*. They tell when and with which versions the copy was made, give the command that makes an equivalent copy again, and say what was left out or did not work, so two copies of the same video can be compared row by row.

## Good to know

- Comments take most of the time: YouTube serves about 20 per request, so 10,000 comments take a few minutes. `Ctrl+C` stops downloading them and still makes the page from the comments fetched so far; such a page counts as finished on the next run (use `--overwrite` for that video to get all comments). With several videos or a playlist the run stops there; run the same command again to continue with the videos that have no page yet.
- The number of downloaded comments is usually a bit lower than YouTube's count (deleted or hidden comments); the page shows both. A limited download (`--max-comments`) shows as fewer downloaded comments (*About this copy* says whether they were limited or interrupted); `No comments.` appears only when the video really has none.
- Comment times are as YouTube showed them on the download day (`3 years ago`); hover over one to see the estimated date. Subscriber counts are rounded by YouTube (`1.23M`); views and likes are exact.
- YouTube's automatic captions mark a change of speaker with `>>`; the page shows a grey mark instead (a grey ` | ` in the continuous transcript) and leaves it out in the lines under the video.
- The transcript is the one YouTube's *Show transcript* opens: the captions of the video's original language, also for auto-dubbed videos. The AI summary is in the language of the video.
- `bilingual:LANG` uses YouTube's machine translation, so its quality varies. YouTube refuses translations requested within about a minute of opening the video, so the program may wait up to a minute (shown on screen) and retries after `HTTP 429`.
- A chapter list in a video description becomes real chapters on YouTube only if it starts at `0:00`, has at least three timestamps in ascending order and each chapter is at least 10 seconds long.
- Typical page size: a few hundred KB up to a few MB for thousands of comments.
- Browser cookies on Windows: Firefox works reliably; Chrome and other Chromium-based browsers encrypt their cookies in a way yt-dlp usually cannot read there.

## Troubleshooting

- **Fetching fails after it used to work:** YouTube changes often and yt-dlp follows within days; update first with `uv tool upgrade yt-video-archiver`. `yt2html --version` shows the yt-dlp version in use.
- **`Sign in to confirm you're not a bot`, age-restricted video:** use `--cookies firefox`. Firefox works best on Windows; Chrome and Edge encrypt their cookies in a way yt-dlp often cannot read.
- **A translation keeps failing with `HTTP 429`:** try again later, or open the video in Firefox with auto-translated subtitles on and use `--cookies firefox`.
- **`No transcript: ...` although YouTube shows *Show transcript*:** look for a yt-dlp warning about subtitles and a missing PO token; updating yt-dlp usually helps.
- **`Could not read them ...; using yt-dlp chapters instead`:** the page is made, but without the AI summary, People mentioned and similar sections, and with chapters under a plain `Chapters` heading (*About this copy* says so in its *Video page* row). Usually temporary; run again with `--overwrite`.
- **`Chapter source unclear: ...`:** the chapters are on the page, only without the grey origin note. Please report the video: YouTube has probably changed something.
- **`FAILED: ... this is a channel URL`:** pass the URL of a video or of a playlist.
- **`FAILED: https://www.youtube.com/watch?v=...` in a playlist:** usually a private or deleted video (yt-dlp's `ERROR` line above says why). Each run tries it again; it does not stop the other videos.
- **Some avatars are letters:** those images could not be downloaded (or the author has none).
- **`Info card link ... kept as a YouTube redirect`:** the website behind a link card could not be read; the card links through YouTube instead, which may stop working later. Run again with `--overwrite`, or leave the cards out with `--no-cards` if this keeps failing.
