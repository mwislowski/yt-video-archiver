# yt-video-archiver

`yt2html` saves a YouTube video page as **one self-contained HTML file** for offline use, in the spirit of the SingleFile browser extension: description, chapters, all comments and, with `--transcript`, the transcript, readable without YouTube and without an internet connection. It uses [yt-dlp](https://github.com/yt-dlp/yt-dlp); no AI, no browser, no API key.

With `--video` it also downloads the video itself as an mp4 next to the page, and on request extra audio tracks and subtitles (needs ffmpeg; see *Downloading the video*). The page gets the same base name as yt-dlp's default video file name, `Title [video id].html`, so a video downloaded separately (e.g. with yt-dlp) can sit beside it too.

A **list file** of videos, playlists and video files of your own gets an **index page** with chapters, notes and its own player, for watching a whole series (see *List files and their index*).

## What the page contains

- **Thumbnail, title, channel** with its avatar and subscriber count.
- **Facts:** duration, publication date, views, likes, comment count, and in grey the *Snapshot* date (when the data was downloaded; added by the program, not by YouTube).
- **Full description** (what YouTube hides behind *Show more*) with clickable links, timestamps, `#hashtags` and `@handles`.
- **AI-generated video summary**, if YouTube offers one.
- **Chapters**, with a grey note saying whether they come from the description or were generated by YouTube, and other timestamp lists such as **Walkthroughs**, as plain vertical lists.
- **Info cards** the author placed in the video (the small "i" teasers linking to another video, a playlist, a channel or a website), with the time they appear, an image and the author's message.
- **People mentioned** (photos, names, descriptions) and **Explore the podcast**, if YouTube shows them.
- **Transcript** with `--transcript`, already open, split by chapters; as continuous text, with timestamps, or side by side with a translation.
- **License**, if it is not the standard YouTube one (e.g. Creative Commons).
- **All comments**, oldest first, every thread fully expanded, with likes, pinned and creator marks.
- **A player for your downloaded copy of the video**, if it lies next to the page (downloaded with `--video` or separately; see below).
- **Video formats**, folded near the bottom: the qualities, codecs and approximate sizes YouTube offers for the video, its audio tracks (original, dubbed, auto-dubbed, audio description) and subtitles (see below).
- **About this copy**, folded at the bottom: how this copy was made and what it lacks (see below).

Images are embedded in the file. The page works without JavaScript; a small built-in script only adds the player. It shows in light or dark colours according to the device it is opened on. Not included: YouTube's own video player, recommendations, YouTube's *Video details* (it repeats the facts).

## Installation

Requires [uv](https://docs.astral.sh/uv/) (it also installs a suitable Python by itself).

```powershell
uv tool install git+https://github.com/mwislowski/yt-video-archiver
uv tool update-shell
```

`uv tool update-shell` adds uv's command folder to `PATH` (once; open a new terminal afterwards). Check with `yt2html --version`.

| Task | Command |
|---|---|
| Update the program and yt-dlp | `uv tool upgrade yt-video-archiver` |
| Remove the program | `uv tool uninstall yt-video-archiver` |

For `--video` (downloading the video itself): [ffmpeg](https://ffmpeg.org/), which joins image and sound into one file (`winget install --id Gyan.FFmpeg -e`, then open a new terminal; macOS `brew install ffmpeg`; Linux: the package manager, e.g. `sudo apt install ffmpeg`). Pages need no ffmpeg.

Optional: a JavaScript runtime recommended by yt-dlp for YouTube, e.g. Deno (`winget install DenoLand.Deno`; macOS `brew install deno`). Without it yt-dlp prints warnings about video formats; they are harmless for the page, but YouTube may then offer fewer video formats (the *Video formats* section then lists fewer).

### macOS and Linux

The program and its commands are the same; only uv is installed differently (then run the two commands above):

```sh
brew install uv                                    # macOS with Homebrew
curl -LsSf https://astral.sh/uv/install.sh | sh    # Linux, or macOS without Homebrew
```

Differences from Windows: put page names in quotes (`'Title [ID].html'`: square brackets are pattern characters in bash and zsh); a colon in a title stays `:` in file names (Windows gets `：`), so the same video has a slightly different file name on each system; browser cookies work with Chrome and other Chromium-based browsers too (macOS asks for Keychain access; Safari needs Full Disk Access for the terminal). The program is tested on Linux; macOS has not been tried yet.

## Usage

```powershell
yt2html "https://www.youtube.com/watch?v=..."
```

The page is saved in the current folder (e.g. the folder with your downloaded videos); `-o FOLDER` saves it elsewhere. Always put the URL in quotes: in PowerShell `&` in a URL would otherwise be treated as an operator.

Instead of a URL you can also give a video or playlist id (`Z8lf5oWKfj0`, `PLeBgIYTbh-CzUlJnPXenyingrNSXQgFoa`) or any file name with the id in square brackets, wherever it stands and whatever the extension (a page, a downloaded video): `"My title [Z8lf5oWKfj0].html"` or `"My title [Z8lf5oWKfj0].mp4"` stands for that video, `"Python course [PLeBgIYTbh-CzUlJnPXenyingrNSXQgFoa]"` for that playlist. Handy with `--overwrite`. Video names work the same way in list files.

**What to archive**

| Task | Command |
|---|---|
| One video | `yt2html "URL"` |
| Several videos at once | `yt2html "URL1" "URL2" "URL3"` |
| All videos of a playlist (see below) | `yt2html "https://www.youtube.com/playlist?list=..."` |
| Videos and playlists listed in a list file, with its index page (see below) | `yt2html --index series.txt` |
| Save into another folder | `yt2html "URL" -o "D:\Videos\Channel"` |
| Make a page again although the video already has one (e.g. for newer comments); also works for a whole playlist or list | `yt2html "URL" --overwrite` |
| When YouTube asks to sign in or to confirm you are not a bot (`--cookies` is short for `--cookies-from-browser`; the browser need not be open; without a profile, the one used most recently) | `yt2html "URL" --cookies firefox` |
| The same with a given browser profile: its folder name (Firefox: `about:support`, *Profile Folder*) or path | `yt2html "URL" --cookies "firefox:fTW1hk7Y.Profile 1"` |

**Index page** (see below)

| Task | Command |
|---|---|
| Archive what a list file lists (what is missing) and make its index `series.html` | `yt2html --index series.txt` |
| Only make the index, downloading nothing, e.g. after renaming pages or adding a video file | `yt2html --index-only series.txt` |
| Make the pages of a list again from saved data, then the index (`--transcript` as when they were made: without it the pages lose the transcript) | `yt2html --index series.txt --load-json --transcript` |
| Add to the saved data of a list what is missing, then the index | `yt2html --index series.txt --update-json --transcript` |
| Refresh the counts and comments of a list's videos in their saved data, then the index | `yt2html --index series.txt --refresh-json --transcript` |
| Make all pages of a list again, with the index | `yt2html --index series.txt --overwrite` |

**What the page contains and how it looks**

| Task | Command |
|---|---|
| Without comments | `yt2html "URL" --no-comments` |
| Only the first N comments (quick test) | `yt2html "URL" --max-comments 200` |
| Also the transcript, as continuous text | `yt2html "URL" --transcript` |
| Transcript versions (see below) | `yt2html "URL" --transcript plain,timestamps` |
| Without info cards | `yt2html "URL" --no-cards` |
| Without the avatars of comment authors (smaller file; the channel's avatar stays) | `yt2html "URL" --no-avatars` |
| Without the grey Snapshot date tile (the date stays in *About this copy*) | `yt2html "URL" --no-snapshot` |
| Page always dark / always light (default: follows the device) | `yt2html "URL" --theme dark` / `--theme light` |

**Other**

| Task | Command |
|---|---|
| Also download the video, after its page (an mp4 that the page plays; needs ffmpeg) | `yt2html "URL" --video` |
| The same, at most 720p (or 720p at most 30 frames per second) | `yt2html "URL" --video 720p` / `--video 720p30` |
| List the qualities a video download can take and the audio tracks it can add, without making a page | `yt2html "URL" --video-formats` |
| Also save the data the page is made from, to make it again later without YouTube (see *Saved data*) | `yt2html "URL" --write-json` |
| Add to saved data only what is missing, e.g. a translation YouTube refused before, keeping the comments (see *Saved data*) | `yt2html VIDEO_ID -o "D:\Videos" --update-json --transcript bilingual:pl` |
| The same, and also refresh the counts and the comments: new ones added, those YouTube no longer has kept and marked (see *Saved data*) | `yt2html VIDEO_ID -o "D:\Videos" --refresh-json --transcript` |
| Make a page again from saved data only, offline (see *Saved data*) | `yt2html --load-json VIDEO_ID -o "D:\Videos" --transcript` |
| Versions of the program and yt-dlp | `yt2html --version` |
| All options | `yt2html --help` |

Options can be combined, e.g. `yt2html --index series.txt -o "D:\Videos" --max-comments 500`. In option values the case of letters does not matter (`--theme Dark`, `--transcript Plain,bilingual:PL`); paths, addresses and browser profile names stay as typed.

### Transcript versions

Without `--transcript` the page has no transcript (and none is downloaded). `--transcript` alone adds it as continuous text; with versions, separated by commas without spaces, they appear on the page in that order. Write the address first: `yt2html "URL" --transcript` (an address after a bare `--transcript` would be taken as versions).

| Value | Result |
|---|---|
| `plain` (also the option alone) | continuous text, without timestamps |
| `timestamps` | one line per caption, each with its timestamp |
| `bilingual:CODE` | like `timestamps`, with YouTube's machine translation into that language (e.g. `bilingual:pl`) in a second column |

Examples: `--transcript`, `--transcript plain,timestamps`, `--transcript plain,bilingual:pl,bilingual:de`. Each version may appear only once; a code that is no language code (`bilingual:jp`) stops the program before anything is downloaded. With `--load-json` the versions are made from the saved data: the order may change, `timestamps` works for any saved transcript, a translation needs to be in the data (or noted there as left out).

What YouTube does not have or does not send is left out with a note, the page is made and counts as finished (*About this copy* says what was left out and why, in its *Transcript* row):

- a video without captions at all;
- a translation YouTube does not offer (the message lists the languages it does);
- a translation YouTube refuses to send (`HTTP 429`, which in November 2026 happens often) or whose download fails. Each translation is asked for once, a random 70 to 100 seconds after the video's data was fetched (YouTube refuses translations asked for sooner; the wait is shown on screen), and not again in that run. To add it later: `--update-json` (only the translation is fetched; the comments and the copy's date stay, see *Saved data*), or `--overwrite` (everything downloaded again).

Only when the transcript itself cannot be downloaded is nothing saved for that video, so the next run tries again.

### Saved data

Four options work with the data a page is made from, saved next to it as `Title [id].info.json`: yt-dlp's data of the video (description, counts, formats, comments, …) together with what yt2html adds (the transcript and its translations, the chapters and other timestamp lists, info cards, the extras of the video page, what `--video` downloaded). Only one of them at a time; combining two is an error.

| Option | What it does | Asks YouTube for | Comments and counts | The copy's date |
|---|---|---|---|---|
| `--write-json` | also saves the data with a normal download | everything (a normal download) | downloaded now | today |
| `--update-json` | adds to saved data what the options ask for and they lack, saves them back, makes the page again | only what is missing; nothing if nothing is | as saved | as saved, with a note of the update |
| `--refresh-json` | as `--update-json`, and refreshes what changes over time | the video's data with the comments, then what is missing | refreshed; the comments merged with the saved ones | as saved, with a note and, from another day, a *Refreshed* tile |
| `--load-json` | makes the page from saved data only | nothing (images aside) | as saved | as saved |

Saving and reading are not symmetric: `--write-json` is an extra to a download (without it the download is the same), while `--update-json`, `--refresh-json` and `--load-json` change where the page comes from.

**`--write-json`** saves the file next to the page; an older file of the same name is replaced. Save the data with every download you care about: they let you make the page again later without YouTube (a newer look of the page after an update of yt2html), add what is missing, and they keep what was downloaded (*Video file* row, extra audio switches) when `--video` runs in the same command.

**`--update-json`** completes saved data without downloading them again:

- **What it adds:** the transcript, if the data have none and `--transcript` is given; translations (`bilingual:CODE`) that are not in the data, also those YouTube refused before (a translation YouTube does not offer, or a video without captions, is noted and not asked for again); the files of `--video` that are not next to the page yet, which are then recorded in the data, so the page gets its *Video file* row, yellow marks and extra audio switches.
- **What it asks YouTube for:** the video's data without the comments (caption addresses expire, so the saved ones cannot be used), then only what is missing, with the same 70–100 s wait before a translation. When nothing is missing it asks for nothing and the page is made from the saved data, as with `--load-json`.
- **What stays:** the comments, the counts (views, likes), the description, and the copy's date (Snapshot, *Downloaded*). *About this copy* adds the day and time of each such run to *Downloaded*: `…; updated 20.11.2026 10:12` (what it added shows in the other rows; the data keep the details). With `--video`, the *Video formats* section takes the list the files were chosen from, as with a download.
- **What it takes:** the same as `--load-json` (a file, `*` and `?` patterns, a video id or the name of the page or video, looked up in `-o`), and also addresses and playlists. The data go back into the file they came from, whatever its name; pages are saved in the `-o` folder.
- **Without saved data:** a full download, as with `--write-json` (with a message), when the video has no page yet; a page that exists without data is skipped (`Skipped (page exists, no saved data to update)`), since replacing it would download everything again: use `--overwrite --write-json` for that.
- **Options that shape the page** work as with `--load-json`; `--max-comments N`, `--no-comments` and `--no-cards` narrow only the page, the file keeps all comments and cards, so a later build without them shows all of them again. `--update-json` with `--overwrite` is an error (one keeps the data, the other downloads everything again).

**`--refresh-json`** does what `--update-json` does and also downloads the video's data again, with the comments, to refresh what changes over time:

- **Counts, title and description:** views, likes, subscribers and YouTube's comment count are taken anew, and so are the title, the description and the chapters and other timestamp lists made from them (the earlier title and description stay in the data; the page shows the current ones without a note). Info cards and the rest stay as saved.
- **Comments, merged by their id:** new ones are added; those still there are taken as they are now (text, likes, time; an earlier text stays in the data); those YouTube no longer sends stay on the page with a grey mark, `not on YouTube on 20.11.2026`, the day of the refresh that first missed them. A comment that is back later loses the mark (the data keep when it was missing). Comments turned off on YouTube since the download stay too, with a note above them, `As of 03.12.2026, comments on this video are turned off on YouTube; the ones below can no longer be seen there.` (gone again when they are on); with `--no-comments` the saved ones stay as they are; after a download with `--max-comments` or one stopped with `Ctrl+C` nothing is marked, since missing comments prove nothing then.
- **On the page:** the comments line and the *Comments* row of *About this copy* add how many are no longer on YouTube; *Downloaded* adds the day and time of each refresh, e.g. `…; refreshed 03.12.2026 18:40`; a *Refreshed* tile with the day of the last refresh stands next to *Snapshot* when it is another day (`--no-snapshot` leaves out both). The copy's date stays.
- **A video no longer on YouTube** (removed, its account terminated, made private): the refresh records it (`No longer on YouTube: <YouTube's words> (recorded)`) and changes nothing else in the data: the title, description, counts and comments stay as saved, nothing missing is added, and the page is made again from them. On the page the *Refreshed* tile shows the day of that check in a muted red, also on the copy's day, and *Downloaded* adds the check with YouTube's words after the last one: `…; no longer on YouTube 03.12.2026 14:05 “Video unavailable. This video is no longer available because the YouTube account associated with this video has been terminated.”`. Each later refresh checks again; when the video is back, the next refresh is an ordinary one, the tile is grey again and the earlier checks stay in *Downloaded* without YouTube's words. YouTube's thumbnails go with the video; the page keeps the one it had. Other refusals (`Sign in to confirm you're not a bot`, `try again later`) may not last: the video fails (`FAILED: …`) and the data stay as they were.
- Everything else as for `--update-json`: the sources, without saved data a full download or a skip, the page made again, the data saved back; `Ctrl+C` during the comments stops the run after the page, as with a download. `--refresh-json` with `--overwrite` is an error.

**`--load-json`** makes pages only from such files and asks YouTube for nothing:

- **What it takes:** the file (`yt2html --load-json "Title [id].info.json"`), several files with `*` and `?` (`"D:\Videos\*.info.json"`; this works also in PowerShell and cmd, and square brackets are part of the name), or the video id, also as the name of the page or of the video (`yt2html --load-json VIDEO_ID -o "D:\Videos"`): the file is then looked up by the id in square brackets in the folder given with `-o` (default: the current folder). Pages are saved in that folder, also when the file lies elsewhere.
- **What comes from the file:** everything except images. The thumbnail and avatars are downloaded again from their addresses in the data (YouTube may have removed them by then; missing avatars become letters). The snapshot date stays the day of the download.
- **Options:** those that shape the page work as with a download (the `--transcript` versions, `--theme`, `--no-cards`, `--no-avatars`, `--no-snapshot`, fewer comments with `--max-comments N` or `--no-comments`). What is not in the data cannot be added (that is what `--update-json` is for, and `--refresh-json` for more comments): more comments, a translation that was not downloaded (a `bilingual:CODE` neither in the data nor noted there as left out fails that video), the video (`--video` cannot be used with `--load-json`).
- **Existing pages are always replaced**, without `--overwrite`; the page keeps its current name. The file stays as it is.
- **A missing file:** that video fails (`FAILED: …`, the run ends with exit code 1); nothing is downloaded instead.

### Archiving many videos

**Playlists:** a playlist URL (`https://www.youtube.com/playlist?list=...`) or id archives all videos of the playlist in its order, e.g. all episodes of a podcast. A link to a video opened from a playlist (`watch?v=...&list=...`) archives only that video. Channel URLs (`@name`) are not supported: open the channel's playlist and use its URL.

**Videos that already have a page are skipped**, so running the same command again only archives what is missing, and an interrupted run continues where it stopped. A page is any `.html` file with the video id in square brackets in its name, e.g. `[Z8lf5oWKfj0]`: you may rename pages freely (`042 My title [Z8lf5oWKfj0] (copy).html`) as long as that part stays. If several files fit, the first by name is used and a note says so. Only the output folder itself is checked, not its subfolders. To make a page again, delete it or use `--overwrite` (the page keeps its current name). `--load-json` always replaces the page.

For a series of videos you want to keep together, write them into a **list file** and archive it with `--index` (next section): the list also gets an index page.

### List files and their index

A list file is a plain text file (UTF-8, Notepad's default; any extension: `series.txt`, `series.md`) with one video or playlist per line. `yt2html --index series.txt` archives what the list names and is not in the folder yet, then makes the **index page** `series.html` in the output folder (`-o`, next to the pages: its links are relative). `yt2html --index-only series.txt` only makes the index, from what is in the folder, and downloads nothing. The program only reads the list file, never changes it. One list file per run; a URL in the same command is an error (add it to the file).

The simplest list is just addresses or ids:

```text
https://www.youtube.com/watch?v=Z8lf5oWKfj0
https://youtu.be/qyqCTMirNWg
PLeBgIYTbh-CwGJwFnluRTgBkvcM2q6jOO
```

A list can also be organised, in a way close to Markdown (a `.md` list looks like its index in a Markdown preview):

```text
!numbers: no
!layout: cards
# Railways of the world
> My collection. **Japan** first, then _the rest_; sources: https://example.org
## Japan
Z8lf5oWKfj0
> The best introduction, start here.
= Rail in numbers
The Largest Rail System In the World [qyqCTMirNWg].html
### My own recordings
Holiday in the Tatras.mp4
## A course for dessert
// a playlist next to nothing else puts its videos right here
PLeBgIYTbh-CwGJwFnluRTgBkvcM2q6jOO
```

| Line | Meaning |
|---|---|
| an address or id of a video | a video; also the name of its page or video file with `[VIDEO_ID]` (`Title [Z8lf5oWKfj0].html`) |
| an address or id of a playlist | its videos, read from YouTube each time the index is made (see below) |
| `Holiday.mp4` | a video file of your own in the output folder (`mp4`, `webm`, `m4v`, `mkv`; the name only, no folder) |
| `# Title` | the title of the index, at most once; without it, the file's name (`series`), or the playlist's title when the list has exactly one playlist |
| `## Chapter`, `### …`, `#### …` | chapters on three levels, shown as written (a skipped level or an empty chapter stays) |
| `> text` | a note: each such line is one paragraph; `**bold**`, `*italic*` or `_italic_`, `http(s)://` addresses are links, anything else stays as written. Notes after a video belong to it (shown with it, where `!layout` puts them), notes after a heading introduce the chapter, notes after a playlist follow all its videos; notes of a chapter stand at its indent, its videos and chapters one step in |
| `= Title` | a title of your own for the video, playlist or file on the very next line (instead of the title from the page, from YouTube or the file's name) |
| `// text` | a comment, ignored |
| `!numbers: no`, `!thumbnails: no` | settings for the whole list, at the top (before the first chapter, video or playlist), each at most once: no numbers (otherwise grey, before each title, numbered per level; the index looks the same without them); no images (a small round play button instead, the duration in the line). Both are `yes` by default; any case, the space after `:` optional |
| `!layout: plain`, `compact`, `cards` | how rows and notes look (a setting too): **`plain`** (the default) puts a video's note under its thumbnail, across the whole width, without a frame; **`compact`** puts it beside the thumbnail, under the title; **`cards`** puts the title, its line and the note into one rounded frame beside the thumbnail, for every row (at least as tall as the thumbnail). The notes of chapters and the list follow: without frames in `plain` and `compact`, framed in `cards` |

Blank lines do not matter. Every other line is an error: the run stops before anything is downloaded and names the line (`series.txt, line 7: not a video, playlist or video file: …`). Note that `#` now starts the title and chapters: comments start with `//`.

**Playlists in the list:** a playlist that is the only element of its level (not counting notes) puts its videos in its place; next to other videos, playlists or chapters it becomes a chapter one level lower, titled as on YouTube (at the third level its videos stand next to the others). Under an empty heading (`##` alone) the only playlist gives the heading its title. Each playlist gets two notes, as on its page on YouTube: its title, *Playlist*, the channel and the number of videos (YouTube's count, which includes videos it no longer shows), and its description as written. Titles always come from the pages, never from the playlist: YouTube sends the titles in a playlist translated into the language it is asked in (English), while the pages keep the originals.

**What the index shows:** each video in one dense row: its thumbnail with the duration on it (it plays the file in the index's player, below), the title linking to its page (in a new tab), and a small line: the language of the video, the file's format (hover for the file's name) and *YouTube* (hover for the original title). Videos are numbered on each level from 1, chapters too. What is missing in the folder is said in grey italics, and the console names the line:

| In the line | Meaning |
|---|---|
| *only the page downloaded* | the page is there, the video file is not (dimmed thumbnail) |
| *not downloaded* | neither page nor file: the title is the video's id (or the `= Title`, or the name in the line); `--index` downloads it |
| *file not found* | your own file is not in the output folder: check the name |
| *no longer on YouTube* | instead of the YouTube link: the video was gone at the last `--refresh-json` |
| *playlist could not be read* | in the place of a playlist YouTube did not give and the index did not keep |

Good to know about the index:

- **It always shows what is in the folder.** It is made at the end of every run with `--index` (also after `Ctrl+C`; when `Ctrl+C` comes while the playlists are read at the start, nothing has been downloaded and the index stays as it was), from the pages (only their metadata, at the top) and the files lying there, never from what this run downloaded. `--index`, `--index-only` and `--index … --load-json` give the same index for the same folder; why a download failed is only in the console. A page made by a version before the new index lacks the data the index needs: the console says which, make it again (`--load-json` or `--overwrite`).
- **Renaming is safe.** Pages and video files are found by `[video id]` in their names, so after renaming them the index links to the new names and still shows the original titles; run `--index-only` to refresh it.
- **Playlists are read each time** (only their list, one request per about 100 videos, also with `--index-only` and `--load-json`): videos added on YouTube appear in the index, removed ones disappear. The index keeps each playlist's list inside, invisibly; when YouTube cannot be reached, that list is used and the console says so. `--cookies` works for private playlists.
- **With the JSON options:** `--load-json`, `--update-json` and `--refresh-json` work with `--index` as with videos in the command, then make the index; the saved data are found by the video id in the output folder. With `--load-json`, a video of the list without saved data is skipped with a note (`No saved data for …; skipped.`).
- **`--index-only` only makes the index:** options that download or shape the pages (`--video`, `--transcript`, the JSON options, `--overwrite`, `--no-comments`, `--max-comments`, `--no-cards`, `--no-avatars`, `--no-snapshot`) are an error with it; `-o`, `--theme` and `--cookies` work.

**The player of the index:** a panel on the left, always there, with the list scrolling on the right (on narrow windows and phones it stays at the top, as on a video's page). A click on a thumbnail (or the round button) plays that file; until the first one the whole panel is greyed. Below the video and its position: one row of equal buttons that wraps in a narrow panel: **|◀◀** the previous file, to the start (stops the video), 10 seconds back, play/pause, 10 seconds forward, to the end, **▶▶|** the next file and **A** (*Autoplay*, off at first: when a file ends, the next one plays); then the speeds 0.25× to 2× (kept from file to file) and the title of the file playing. The previous and next file keep what the player was doing: playing goes on playing, stopped (paused, at the start or after the end) waits at the start of the other file, with its first frame and duration; after a file that could not be played, the state from before it. They skip rows without a file and are greyed at the first and last one; when the row of the new file is out of sight, the list scrolls just enough to show it (*Autoplay* scrolls only if the row that ended was in sight, so it never pulls you away from what you are reading). Only one audio track, the video's own, and no transcript: those are on the video's page (the title links to it, in a new tab, so the index keeps playing). A click on the file that is in the player does nothing; the panel controls it.

- Keys after the first play: as on a video's page (`Space`, `←` / `→`, `Ctrl`+`←` / `Ctrl`+`→`), plus `Shift`+`P` / `Shift`+`N` the previous / next file. Media keys and the picture-in-picture window can also go to the previous and next file.
- **A file that cannot be played** (moved or deleted since the index was made, or in a format the browser does not play, e.g. HEVC in Firefox or some `.mkv`; the browser does not tell these apart): the screen says *This file could not be played.* with its title, its thumbnail dims and only the previous and next file work. The previous, next and *Autoplay* skip it from then on; *Autoplay* stops at such a file the first time it meets it. Reload the page after putting the file right; `--index-only` brings the index up to date with the folder.
- Without JavaScript the index is a plain list (no panel); the links work as usual.

### Downloading the video

`yt2html "URL" --video` makes the page as usual, then downloads the video itself as an mp4 named like the page (`Title [id].mp4` next to `Title [id].html`), so the page plays it. Write the address first; parameters follow `--video`, separated by commas:

| Parameter | Meaning |
|---|---|
| (none) | the best quality up to 1080p in AV1, else H.264, with the original audio |
| `720p`, `480p`, … | a quality as an upper limit: the best one not above it, at any frame rate (`720p` takes 720p at 60 frames per second when there is one) |
| `720p30`, `1080p60`, … | the same with the frame rate as a limit too (the parameters in brackets in *Video formats*) |
| `audio:pl`, `audio:de`, … | an extra audio track in that language, as a separate m4a (`Title [id].pl.dubbed.m4a`): a dub by the author first, else YouTube's automatic dub, else another kind; never an audio description by itself. The language finds its regional code (`de` → `de-DE`); a code with a region must match exactly (`de-AT` is not `de-DE`). Repeat for more tracks |
| `audio:pl.auto-dubbed`, `audio:ru.descriptive`, … | exactly that version: `original`, `dubbed`, `auto-dubbed`, `descriptive`, or another kind the video has |
| `sub:en`, `sub:pl`, … | subtitles in that language as an SRT file next to the video (`Title [id].pl.translated.srt`), for a player such as VLC: the author's subtitles first, else the auto-generated ones (made from the speech of an audio track in that language), else YouTube's machine translation of the subtitles the transcript is made of. Codes as for `audio:`; the page's own subtitles under the video come from the transcript and need none of this |
| `sub:pl.author`, `sub:pl.auto-generated`, `sub:pl.translated` | exactly that kind (a translation always from the transcript's subtitles, see the *Transcript* row of *About this copy*) |
| `again` | download again every file this command makes that is already next to the page, into that file (also when renamed): the video (it belongs to every `--video`) and each track and subtitles asked for in it, not other files. Adding a track to an existing video needs no `again` (files that are there are kept); to replace a single track, delete its file and run the command again |

Example: `yt2html "URL" --video 720p30,audio:pl,sub:pl,again`. Parameters in any case of letters; above 1080p is not offered (the file is meant to play everywhere). Each item once: the same one twice, or a language both alone and with a role (`audio:pl,audio:pl.dubbed`), is an error, as is a code that is no language code (`audio:jp`), all before anything is downloaded; two roles of one language are two tracks (`audio:pl.dubbed,audio:pl.descriptive`). The codes are those of the *languages* table in *Video formats* and of `--video-formats`; a track or subtitles the video does not have are reported (`"audio:de-AT" not available`, `"audio:en" is already in the video`, `"audio:de-DE" gives the same track as "audio:de"; taken once`) together with what can be taken, and the rest goes on.

- **Extra audio tracks:** the page's player can play them instead of the video's own sound (see below); they also work on their own or in a player such as VLC (*Audio* › *Audio Track* › *Add audio file…*).
- **Subtitles:** SRT files with the same text and timing as YouTube's own SRT, made from the track the transcript uses as well (each track is downloaded once per run, so `--transcript bilingual:pl` with `sub:pl` normally asks YouTube for the Polish translation once, and a refusal is not asked again). A translation is asked for once, a random 70 to 100 seconds after the list of formats was fetched (YouTube refuses translations asked for sooner); refused (`HTTP 429`), it is reported as failed and the next run with the same `--video` tries again (with `--update-json`, the file is then also recorded in the saved data). Subtitles need no ffmpeg.

The order of work: the page first, then a fresh list of formats (the addresses in older data expire) and the download, then the page once more, from the data already in memory, so that its *Video file* row says what was downloaded (`downloaded 12.11.2026: 1080p, 30 fps av1 + en-US aac, mp4, 293 MB`) and *Video formats* marks it in yellow.

- **Interruptions:** the page is ready before the video, so an error or `Ctrl+C` during the download leaves it as it is, and running the same command again resumes the download. `Ctrl+C` while the comments are downloading stops the whole run after the page, as without `--video`; run the same command again to get the video (the page is skipped, only the video is downloaded), or limit the comments beforehand with `--max-comments`.
- **Existing files:** a file already next to the page is kept (`again` downloads it again): the video by the video's id in square brackets in its name, a track or subtitles by the id and their ending (`.pl.dubbed.m4a`, `.pl.translated.srt`), so renamed files count too (`01 Title [id].pl.dubbed.m4a`). For a page that already exists only the files are downloaded, and the page finds the video the next time it is opened; when every file asked for is already there (the video, each `audio:` track and `sub:` subtitles; without a role or kind any one in that language), YouTube is not asked at all and the next video does not wait, so running the same command again to fill the gaps of a playlist asks YouTube only about what is missing. Subtitles of a kind the video got later (the author's after automatic ones) are then not looked for: add `again`, or name the kind (`sub:pl.author`). A page made again (`--overwrite --video audio:pl`) describes the files that are there too: with what the saved data (`--write-json`) of their download say about the same file (the day, the variant), else only that they lie next to the page.
- **Playlists:** each video goes through the whole cycle, with a pause of 5–15 seconds before the next video that needed a download.
- **Limits:** `--video` cannot be used with `--load-json` (it needs YouTube) or `--index-only`. Without ffmpeg the page is made and the video skipped, with the command to install ffmpeg.

### Watching a downloaded video on the page

If the downloaded video lies **next to the page**, the page shows a turquoise **▶ Play** tile first among the facts. Under *Play* it names the video file: its quality as YouTube names it and the language of its audio (`1080p · en-US`; a long language code is shortened to the language, `en`). A browser cannot look into a folder, it can only try names, so the page tries, each time it is opened:

1. video files with the video's id in square brackets in their name, found **when the page was made**, whatever the rest of the name (`042 renamed [id].mp4`);
2. the page's own name (`Title [id].mp4` next to `Title [id].html`; also after renaming both the same way);
3. yt-dlp's default name `Title [id]` (when only the page was renamed).

So a video downloaded later works without making the page again if it has the page's name or yt-dlp's default name; under any other name, make the page again (`--load-json` or `--overwrite`) and it is found by its id. The same after renaming a video. Formats: `.mp4`, `.webm`, `.m4v`, `.mkv`.

**▶ Play** opens a player pinned on the left, so you can watch (or listen to a podcast) while scrolling the description, chapters, transcript and comments on the right; the thumbnail is hidden meanwhile. **✕ Close** pauses the video and restores the page; *Play* continues where you stopped.

- Buttons: to the start (stops the video), 10 seconds back, **↺ previous sentence**, play/pause, 10 seconds forward, to the end, and the speeds 0.25× (for language learning) to 2× (lectures, podcasts). Buttons that show symbols or language codes also carry a spoken name for screen readers and voice control (e.g. *To the start*, *Polish, auto-dubbed*), invisible on the page.
- **↺** goes back to the start of the previous sentence of the transcript, handy for repeating a phrase when learning a language; each further click goes one sentence further back. If that would be more than 20 seconds back (a long pause, music), or the page has no transcript, it goes 5 seconds back.
- Keys while the player is open: `Space` play/pause, `←` / `→` 10 seconds back/forward, `Shift`+`←` previous sentence, `Ctrl`+`←` / `Ctrl`+`→` to the start / to the end.
- **Other audio** (a working version): when `--video` downloaded extra tracks together with the page (`audio:pl`), a last row of switches shows their codes, the original first (a little wider, on at the start). One is on at a time; with a track on, the video plays muted and the track follows it, also when seeking, pausing or changing the speed. Only the tracks in the page's data get a switch: a track added later, for a page that already existed, needs the page made again with it (`--update-json --video audio:pl` with saved data, else `--overwrite --video audio:pl`; the file there is kept, not downloaded again). Renamed tracks play too: the page tries the file with the video's id and the track's ending found when the page was made, then its own name with that ending (`01 Title [id].pl.dubbed.m4a` next to `01 Title [id].html`), then the name the track was saved under. The page looks for every track's file as soon as it finds the video, so a track none of these names finds is greyed out at once; when the file is back, the switch works the next time the page is opened. The transcript and the subtitles stay those of the original.
- A separate video window (picture in picture) is available through the browser itself: right-click the video in Chrome or Edge, or use Firefox's own button on the video; the page returns to its normal layout meanwhile.
- On narrow windows and phones the player stays at the top and the page scrolls below it.
- Browsers play mp4 with H.264 video and AAC audio everywhere; `--video` downloads mp4 with AV1 (else H.264) and AAC, which Chrome, Edge and Firefox play too (Safari plays AV1 only with a hardware decoder). Videos in HEVC/H.265 do not play in Firefox; `.mkv` plays only in some browsers.

**Timestamps play the local copy.** While the player is open, a click on a timestamp plays your copy from that moment instead of opening YouTube (the timestamps turn turquoise). This works everywhere the page has timestamps:

- chapters and other timestamp lists (e.g. Walkthroughs);
- info cards;
- the transcript with timestamps and the bilingual transcript;
- the description and the AI-generated summary (times written in the text, e.g. `12:30`);
- comments (e.g. `3:15 best part`);
- the continuous transcript: it shows no times, but each sentence knows its own, so a click on a sentence plays from there.

With the player closed, timestamps open YouTube as before; `Ctrl`+click always opens YouTube.

*Subtitles*, ↺ and *Follow* use the transcript, so they need a page made with `--transcript`.

**Subtitles under the video.** *Subtitles* (off at first) shows the current sentence of the transcript under the video; each click adds context and then turns it off again: the sentence only (one hollow dot on the button), with one sentence before and after it in grey (one dot), with two (two dots), off. The sentences come from the first transcript with timestamps on the page (plain or bilingual), otherwise from the continuous one. Next to *Subtitles* there is a small button for each translation on the page (`pl`, `de`, … in the order of the bilingual transcripts; none without one). They work once *Subtitles* is on: a click shows that translation under the current sentence, another language replaces it, and a second click on the active one hides it. Turning *Subtitles* off also turns the translation off. A click on the subtitles shows the place in the transcript on the right: in the followed transcript while *Follow* is on, otherwise in the one the subtitles come from.

**Chapters** (off at first) shows the current chapter above the subtitles, on one line (a long title is cut with `…`); its place stays reserved, so turning it on or off never moves the subtitles. The current chapter is also marked in the chapter list. Buttons appear only when there is something to show: a page without a transcript has only *Chapters*, a page without chapters has no *Chapters*.

**Follow** marks the current sentence in the transcript on the right and keeps it in view as the video plays. With several transcripts on the page, pressing *Follow* again moves to the next one (*Follow 2/3*), and after the last one it turns off. Scrolling the page yourself also ends it; *Follow* then starts again with the transcript you followed last (as long as the page stays open).

### Video formats

Above *About this copy*, *Video formats* is folded to a grey line with a short summary: the top quality and the language of the original audio (`up to 1080p, 30 fps · original audio: en-US`). Opened, it lists what YouTube offered when the data was fetched:

- **Image** by quality (YouTube's name for it, as in its quality menu, with the frame rate, e.g. `1080p, 30 fps`), resolution (the actual size of the image, e.g. `1920×1080`; YouTube calls a wide `1920×804` or a vertical `1080×1920` "1080p" too) and codec (h264, av1, vp9; formats for YouTube Premium accounts in their own columns; HLS formats only named, since YouTube gives no reliable size for them) with approximate sizes including the audio. A quality a download of the video can take (up to 1080p, in AV1 or H.264) has its parameter in brackets, e.g. `1080p, 30 fps (1080p30)`.
- **Languages:** one row per audio track (code, language, role: original, dubbed by the author, auto-dubbed by YouTube, audio description; a single track whose language YouTube does not give takes the original language shown in the *Transcript* row) with the subtitles in that language (by the author, and auto-generated from that track's speech: a dub has its own); subtitles without such audio in rows of their own (the languages with audio first, the original's first).
- **Machine translation:** a line on YouTube's machine translation of subtitles (`machine-translated subtitles: possible in 155 other languages for each row with subtitles`, made on request; without subtitles `none (no subtitles to translate)`; `unknown (…)` when YouTube listed no languages, or when the list could not be read, which making the page again later usually fixes).
- **Colours:** cells in blue show what `--video` takes by default: the best quality up to 1080p in AV1, else H.264, with the original audio, as mp4. Cells in yellow show what `--video` downloaded, including the codes of downloaded subtitles and, in the line on machine translation, the translations (`downloaded: pl (from en)`); when it took something else, the default stays blue. Tracks and subtitles only found next to the page are yellow too (their language and kind are certain); a video only found is not (its variant is not known).

When YouTube sent no video or audio formats at all (it happens for a while, e.g. after several requests for the same video in a row; only the small preview images for the seek bar come), the section says so in one line; making the page again later usually brings them. The *Video file* row of *About this copy* says what `--video` downloaded, by day (`downloaded 12.11.2026: 1080p, 30 fps av1 + en-US aac, mp4, 293 MB; extra audio m4a: pl (dubbed), 69 MB`), then the files it only found next to the page, without a day (`next to the page: video 01 Title [id].mp4, 293 MB; subtitles srt: pl (translated)`), else `not downloaded`, and notes how the list came about (with or without Deno, signed in or not).

`--video-formats` prints the same choice on the screen without making a page (only the video's data is fetched, no comments; with `--load-json` from saved data, offline). It cannot be combined with the options that shape a page.

```
Give Me 1 Hour, I Will Make Artificial Intelligence Click Forever [fCEvvkAbJOs]
image (mp4, AV1 else H.264; sizes include the audio: en-US aac):
  1080p, 30 fps  (1080p30)  av1  ~293 MB  (default)
  720p, 30 fps   (720p30)   av1  ~214 MB
  ...
audio (mp4, aac; extra tracks m4a, aac, ~69 MB each):
  in the video: en-US (original)
  auto-dubbed: ar, bn, de-DE, es-US, fr-FR, hi, id, it, iw, ja, ko, ml, nl-NL, pa, pl, pt-BR, ru, ta, te, uk
subtitles (srt):
  auto-generated: en, ar, bn, de, es, fr, hi, id, it, iw, ja, ko, ml, nl, pa, pl, pt, ru, ta, te, uk
```

Both headers start with the container and codec of what goes into the video; after the semicolon, the image header names the audio track the sizes include and the audio header describes the extra tracks. The audio lines show the track in the video and, by role, the dubs a download can add as separate m4a files (`audio:CODE`, e.g. `audio:pl`; an audio description as `audio:CODE.descriptive`). The parameters in brackets and `audio:CODE` are what `--video` takes (see *Downloading the video*). The subtitle lines show what `sub:` can take besides machine translations: the author's subtitles and the auto-generated ones, by code.

### About this copy

At the bottom of every page, *About this copy* is folded to a single grey line with the snapshot date, which is there in any case, also with `--no-snapshot`. Opened, it describes this particular copy in rows that are always the same: *Downloaded*, *Page built*, *Playlist*, *Command*, *Video page*, *Markers* (chapters and other timestamp lists such as Walkthroughs), *Info cards*, *Transcript*, *Comments*, *Images*, *Video file*, *Software* and *Disclaimer*. They tell when and with which versions the copy was made, give the command that makes an equivalent copy again, and say what was left out or did not work, so two copies of the same video can be compared row by row.

## Good to know

- Comments take most of the time: YouTube serves about 20 per request, so 10,000 comments take a few minutes. `Ctrl+C` stops downloading them and still makes the page from the comments fetched so far; such a page counts as finished on the next run (use `--overwrite` for that video to get all comments). With several videos or a playlist the run stops there; run the same command again to continue with the videos that have no page yet.
- The number of downloaded comments is usually a bit lower than YouTube's count (deleted or hidden comments); the page shows both. A limited download (`--max-comments`) shows as fewer downloaded comments (*About this copy* says whether they were limited or interrupted); `No comments.` appears only when the video really has none. When comments are turned off, the section says so in YouTube's words (`Comments are turned off.`), or `Comments are unavailable.` when YouTube did not say why; a section with nothing to count has no line of numbers.
- Comment times are as YouTube showed them on the download day (`3 years ago`); hover over one to see the estimated date. Subscriber counts are rounded by YouTube (`1.23M`); views and likes are exact.
- YouTube's automatic captions mark a change of speaker with `>>`; the page shows a grey mark instead (a grey ` | ` in the continuous transcript) and leaves it out in the lines under the video.
- The transcript is the one YouTube's *Show transcript* opens: the captions of the video's original language, also for auto-dubbed videos. The AI summary is in the language of the video.
- `bilingual:CODE` uses YouTube's machine translation, so its quality varies. YouTube refuses translations asked for soon after the video's data was fetched, so the program waits 70 to 100 seconds first (shown on screen); a translation refused even then is left out with a note (see *Transcript versions*).
- A chapter list in a video description becomes real chapters on YouTube only if it starts at `0:00`, has at least three timestamps in ascending order and each chapter is at least 10 seconds long.
- Typical page size: a few hundred KB up to a few MB for thousands of comments.
- Keep the pages themselves, not only the saved data: a page holds its images, while `--load-json` downloads the thumbnail and avatars again, and YouTube may remove them over the years (missing avatars become letters). Rebuilding from saved data is for a newer look of the page; the extra audio switches and the *Video file* row come back only if the data know the files: saved (`--write-json`) in the same run as `--video`, or added later with `--update-json --video …` (a page made again with `--overwrite --video …` gets them anyway, from the files next to it).
- Browser cookies on Windows: Firefox works reliably; Chrome and other Chromium-based browsers encrypt their cookies in a way yt-dlp usually cannot read there.

## Troubleshooting

- **Fetching fails after it used to work:** YouTube changes often and yt-dlp follows within days; update first with `uv tool upgrade yt-video-archiver`. `yt2html --version` shows the yt-dlp version in use.
- **`Sign in to confirm you're not a bot`, age-restricted video:** use `--cookies firefox`. Firefox works best on Windows; Chrome and Edge encrypt their cookies in a way yt-dlp often cannot read.
- **A translation fails with `HTTP 429`:** YouTube refuses auto-translated captions to downloads at times (in November 2026 for days, also to yt-dlp alone, with cookies and from other networks). The page is made without it; try again later: `--update-json` with the same `--transcript` for the bilingual transcript (keeps the comments; needs the saved data) or `--overwrite`, the same `--video` for `sub:` subtitles.
- **`No transcript: ...` although YouTube shows *Show transcript*:** look for a yt-dlp warning about subtitles and a missing PO token; updating yt-dlp usually helps.
- **`Could not read them ...; using yt-dlp chapters instead`:** the page is made, but without the AI summary, People mentioned and similar sections, and with chapters under a plain `Chapters` heading (*About this copy* says so in its *Video page* row). Usually temporary; run again with `--overwrite`.
- **`Chapter source unclear: ...`:** the chapters are on the page, only without the grey origin note. Please report the video: YouTube has probably changed something.
- **`FAILED: ... this is a channel URL`:** pass the URL of a video or of a playlist.
- **`FAILED: ...: Video unavailable. ...`, `Private video. ...` and the like:** YouTube no longer shows the video (removed, its account terminated, made private), also in a playlist; nothing is saved for it. Each run tries it again; it does not stop the other videos. A video saved before keeps its page; `--refresh-json` records that it is gone (see *Saved data*).
- **`FAILED: https://www.youtube.com/watch?v=...` in a playlist:** yt-dlp's `ERROR` line above says why. Each run tries it again; it does not stop the other videos.
- **`series.txt, line 7: …` and nothing downloaded:** the list file has a line the program does not understand; the run stops before any download. Fix that line (comments start with `//`, no longer `#`; see *List files and their index*).
- **`Made by an older version, without the data the index needs (make it again): …`:** that page was made before the new index and lacks its metadata, so its row shows little. Make it again: `yt2html --index series.txt --load-json --transcript` with saved data, else `--overwrite`.
- ***playlist could not be read* in the index:** YouTube did not give the playlist and no earlier index kept its list. Run again when YouTube can be reached; a private playlist needs `--cookies firefox`.
- **`This file could not be played.` in the index's player:** the file was moved or deleted after the index was made, or the browser does not play its format; see *The player of the index*.
- **Some avatars are letters:** those images could not be downloaded (or the author has none).
- **`Info card link ... kept as a YouTube redirect`:** the website behind a link card could not be read; the card links through YouTube instead, which may stop working later. Run again with `--overwrite`, or leave the cards out with `--no-cards` if this keeps failing.
