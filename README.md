# yt-video-archiver

`yt2html` saves a YouTube video page as **one self-contained HTML file** for offline use, in the spirit of the SingleFile browser extension: description, chapters, comments and, with `--transcript`, the transcript, readable without YouTube and without an internet connection. It uses [yt-dlp](https://github.com/yt-dlp/yt-dlp); no AI, no browser, no API key.

With `--video` it also downloads the video itself as an mp4 next to the page, and on request extra audio tracks (needs ffmpeg); with `--transcript srt`, subtitles as SRT files. The page gets the same base name as yt-dlp's default video file name, `Title [video id].html`, so a video downloaded separately (e.g. with yt-dlp) can sit beside it too.

A **list file** of videos, playlists and video files of your own gets an **index page** with chapters, notes and its own player, for watching a whole series (see *List files and their index*).

## What the page contains

- **Thumbnail, title, channel** with its avatar and subscriber count.
- **Facts:** duration, publication date, views, likes, comment count, and in grey the *Snapshot* date (when the data was downloaded; added by the program, not by YouTube).
- **Full description** (what YouTube hides behind *Show more*) with clickable links, timestamps, `#hashtags` and `@handles`.
- **AI-generated video summary**, if YouTube offers one.
- **Chapters**, with a grey note saying whether they come from the description or were generated by YouTube, and other timestamp lists such as **Walkthroughs**, as plain vertical lists.
- **Info cards** the author placed in the video (the small "i" teasers linking to another video, a playlist, a channel or a website), with the time they appear, an image and the author's message.
- **People mentioned** (photos, names, descriptions) and the video's podcast or course (**Explore the podcast**, or YouTube's **Podcast** card), if YouTube shows them.
- **Transcript** with `--transcript`, already open, split by chapters: as continuous text, with timestamps, or side by side with a translation; in the original language or in others.
- **License**, if it is not the standard YouTube one (e.g. Creative Commons).
- **Comments**, the pinned one first (as on YouTube), then oldest first, every thread fully expanded, with likes, pinned and creator marks; up to 1,000 by default.
- **A player for your downloaded copy of the video**, if it lies next to the page (downloaded with `--video` or separately; see *Watching a downloaded video on the page*).
- **Video formats**, folded near the bottom: the qualities, codecs and approximate sizes YouTube offers for the video, its audio tracks (original, dubbed, auto-dubbed, audio description) and subtitles.
- **About this copy**, folded at the bottom: how this copy was made and what it lacks.

Images are embedded in the file; when a page is made again, it takes them from the old page instead of downloading them again (new ones are downloaded; `--page ovr` downloads all, `--json refresh` the thumbnail). The page works without JavaScript; a small built-in script only adds the player. It shows in light or dark colours according to the device it is opened on. Not included: YouTube's own video player, recommendations, YouTube's *Video details* (it repeats the facts).

## Installation

Requires [uv](https://docs.astral.sh/uv/) (it also installs a suitable Python by itself).

```powershell
uv tool install git+https://github.com/mwislowski/yt-video-archiver
uv tool update-shell
```

`uv tool update-shell` adds uv's command folder to `PATH` (once; open a new terminal afterwards). Check with `yt2html --version`.

| Task | Command |
|---|---|
| Update the program and yt-dlp | `uv tool upgrade yt-video-archiver` |
| Remove the program | `uv tool uninstall yt-video-archiver` |

For `--video` (downloading the video itself): [ffmpeg](https://ffmpeg.org/), which joins image and sound into one file (`winget install --id Gyan.FFmpeg -e`, then open a new terminal; macOS `brew install ffmpeg`; Linux: the package manager, e.g. `sudo apt install ffmpeg`). Pages and SRT files need no ffmpeg.

Optional: a JavaScript runtime recommended by yt-dlp for YouTube, e.g. Deno (`winget install DenoLand.Deno`; macOS `brew install deno`). Without it yt-dlp prints warnings about video formats; they are harmless for the page, but YouTube may then offer fewer video formats (the *Video formats* section then lists fewer).

### macOS and Linux

The program and its commands are the same; only uv is installed differently (then run the two commands above):

```sh
brew install uv                                    # macOS with Homebrew
curl -LsSf https://astral.sh/uv/install.sh | sh    # Linux, or macOS without Homebrew
```

Differences from Windows: put page names in quotes (`'Title [ID].html'`: square brackets are pattern characters in bash and zsh); a colon in a title stays `:` in file names (Windows gets `：`), so the same video has a slightly different file name on each system; browser cookies work with Chrome and other Chromium-based browsers too (macOS asks for Keychain access; Safari needs Full Disk Access for the terminal). The program is tested on Linux; macOS has not been tried yet.

## Usage

```powershell
yt2html "https://www.youtube.com/watch?v=..."
```

The page is saved in the current folder (e.g. the folder with your downloaded videos); `-o FOLDER` saves it elsewhere. Always put the URL in quotes: in PowerShell `&` in a URL would otherwise be treated as an operator.

Instead of a URL you can also give a video or playlist id (`Z8lf5oWKfj0`, `PLeBgIYTbh-CzUlJnPXenyingrNSXQgFoa`) or any file name with the id in square brackets, wherever it stands and whatever the extension (a page, a downloaded video): `"My title [Z8lf5oWKfj0].html"` or `"My title [Z8lf5oWKfj0].mp4"` stands for that video, `"Python course [PLeBgIYTbh-CzUlJnPXenyingrNSXQgFoa]"` for that playlist. Video names work the same way in list files. An id starting with `-` would be taken for an option: give it after `--` (`yt2html --video 720p -- -AbCdEfGhIj`), as a full address in quotes, or by its page's name.

### How the options work

Four options say what to make, one for each kind of file next to the page:

| Option | Its files | Without it |
|---|---|---|
| `--page` | the page (`Title [id].html`): what it shows and how | the page with the defaults |
| `--transcript` | the transcript on the page, and its SRT files | no transcript (none downloaded) |
| `--video` | the video (`Title [id].mp4`) and extra audio tracks (`.m4a`) | no video |
| `--json` | the saved data the page is made from (`Title [id].info.json`) | saved data are neither written nor read |

The same rules hold for all of them:

- **One value, parameters separated by commas, no spaces:** `--page ovr,comments:200,theme:dark`, `--transcript plain,dual:pl`, `--video 720p,audio:pl`. Each option at most once (a second one is an error, not a replacement). Letters in any case (`--page Theme:Dark`); paths, addresses and browser profile names stay as typed.
- **The address first:** `--page`, `--transcript` and `--video` may stand alone, so an address after them would be taken as their value: `yt2html "URL" --transcript`.
- **Files already there are skipped**, so running the same command again only does what is missing, and an interrupted run continues where it stopped. **`ovr`** (overwrite) makes a file again: `--page ovr` the page, `--video ovr` the video and its tracks, `--transcript ovr` the saved transcript.
- **One folder:** a video's page, saved data and files stay together in the output folder (`-o`, default the current one). A file given by its name (a page, saved data, an SRT file, a pattern) is taken there; one given with a path elsewhere is an error, before anything is read or written (use `-o` for that folder).
- **Requests that contradict each other are errors** (`--page ovr` with `--json load`: everything again from YouTube, and only from the saved data), and so are values the program does not know, all before anything is downloaded. A request without effect is not (`ovr` when there is nothing yet).
- **At most 100 videos from YouTube per run** (`--take`, see *Many videos*).

Two more options belong to the transcript and to signing in: `--olang CODE` (the video's original language, when YouTube shows it wrongly; see *The transcript*) and `--cookies BROWSER` (see *Signing in*).

### Common tasks

**What to archive**

| Task | Command |
|---|---|
| One video | `yt2html "URL"` |
| Several videos at once | `yt2html "URL1" "URL2" "URL3"` |
| All videos of a playlist (see *Many videos*) | `yt2html "https://www.youtube.com/playlist?list=..."` |
| Videos and playlists of a list file, with its index page (see *List files*) | `yt2html --index series.txt` |
| Save into another folder | `yt2html "URL" -o "D:\Videos\Channel"` |
| Make a page again although the video already has one (e.g. for newer comments); also for a whole playlist or list | `yt2html "URL" --page ovr` |
| More than 100 videos in one run | `yt2html "PLAYLIST URL" --take all` |

**The page and its transcript**

| Task | Command |
|---|---|
| Fewer comments (quick test), all of them, none | `--page comments:200`, `--page comments:all`, `--page comments:no` |
| The transcript, as continuous text | `yt2html "URL" --transcript` |
| The transcript with timestamps, and side by side with its Polish translation | `yt2html "URL" --transcript timed,dual:pl` |
| The transcript in Polish only | `yt2html "URL" --transcript plain:pl` |
| The transcript's subtitles also as SRT files | `yt2html "URL" --transcript timed,srt` |
| Page always dark, without info cards | `yt2html "URL" --page theme:dark,cards:no` |

**Video, saved data and the rest**

| Task | Command |
|---|---|
| Also download the video, after its page (an mp4 the page plays; needs ffmpeg) | `yt2html "URL" --video` |
| The same, at most 720p at 30 frames per second, with the Polish dub as an extra track | `yt2html "URL" --video 720p30,audio:pl` |
| List the qualities a download can take and the tracks it can add, without making a page | `yt2html "URL" --video-formats` |
| Also save the data the page is made from (see *Saved data*) | `yt2html "URL" --json write` |
| Add to saved data what is missing, e.g. a translation YouTube refused before | `yt2html VIDEO_ID --json write --transcript dual:pl` |
| Refresh counts and comments in the saved data | `yt2html VIDEO_ID --json refresh --transcript` |
| Make a page again from saved data only, offline | `yt2html VIDEO_ID --json load --transcript` |
| Merge a translation of your own into the saved data | `yt2html --json merge "Title [id].pl.own.srt"` |
| Merge your corrections of the transcript's text into the saved data | `yt2html --json merge "Title [id].en.fixed.srt"` |
| See what the saved data hold and what they lack, offline; one line per video | `yt2html "*.info.json" --json show`; `--json show:brief` |
| When YouTube asks to sign in or to confirm you are not a bot | `yt2html "URL" --cookies firefox` |
| Versions of the program and yt-dlp; all options | `yt2html --version`; `yt2html --help` |

Options combine, e.g. `yt2html --index series.txt -o "D:\Videos" --page comments:500 --transcript timed`.

### The page: `--page`

`--page` with comma-separated parameters shapes the page; `--page` alone changes nothing.

| Parameter | Meaning |
|---|---|
| `ovr` | make the page again although the video already has one in the folder (it keeps its current name): everything is downloaded again from YouTube; with `--json write` the saved data are replaced too (see *Saved data*) |
| `comments:N` | at most N comments, replies counted (default 1000) |
| `comments:all` | all comments (YouTube serves about 20 per request, so 10,000 take a few minutes) |
| `comments:0` | no comments, but the page keeps its *Comments* section with YouTube's count (`0 downloaded (YouTube shows 50)`), and *About this copy* says *limited to 0* |
| `comments:no` | no comments and no *Comments* section; *About this copy* says *left out* |
| `snap:no` | without the grey *Snapshot* date tile (the date stays in *About this copy*) |
| `cards:no` | without info cards |
| `avatars:no` | letters instead of the avatars of comment authors (a smaller file; the channel's avatar stays) |
| `theme:dark`, `theme:light` | the page always dark or always light (default `auto`: it follows the device that opens it) |

Neither `comments:0` nor `comments:no` asks YouTube for comments. With saved data (`--json load`, `write`, `refresh`), `comments:N` and `comments:no` narrow only the page; the data keep all their comments, so a later page without them shows all of them again; the default limit does not narrow saved comments. `cards:no` leaves the saved cards in the data the same way.

`Ctrl+C` while the comments download stops it and still makes the page from the comments fetched so far; such a page counts as finished on the next run (`--page ovr` gets all of them). With several videos or a playlist the run stops there; run the same command again to continue with the videos that have no page yet.

### The transcript: `--transcript`

Without `--transcript` the page has no transcript (and none is downloaded). `--transcript` alone adds it as continuous text in the video's original language; with versions, they appear on the page in the order given.

| Version | Result |
|---|---|
| `plain` (also the option alone) | continuous text, without timestamps |
| `timed` | one line per caption, each with its timestamp |
| `dual:CODE` | like `timed`, with the translation into that language (e.g. `dual:pl`) in a second column |

**Languages.** `plain` and `timed` take a language too: `plain:pl`, `timed:de`. A version without a code is in the original language of each video, also later in the list, so `--transcript plain,timed` works on a playlist with videos in several languages. A code in the original's language is the original itself: `dual:en` of an English video is shown as `timed`, and a version that turns out the same as an earlier one is shown once; the console and the *Transcript* row of *About this copy* say so.

**Where another language comes from.** `plain:pl` and `timed:pl` take your own Polish translation (merged with `--json merge`), else YouTube's machine translation of the original, else the author's own Polish subtitles, else the automatic subtitles of a Polish dub (made from its speech). The author's and a dub's subtitles are rare and have other lines and times, so they come last: they are downloaded only when YouTube does not give its translation (it often refuses it, see below), which costs one request, and only when the video has them. A kind after the code chooses one source, without the others in its place:

| Kind | Source |
|---|---|
| `plain:pl.author` | the author's subtitles in that language |
| `timed:pl.auto-generated` | the automatic subtitles of an audio track in that language (a dub) |
| `plain:pl.translated` | YouTube's machine translation of the original's subtitles |
| `plain:pl.own` | a translation of your own, merged with `--json merge` (see *Saved data*); it is only in the saved data, so it needs `--json write` (or `refresh`, `load`); without `--json` it is an error, and where the data have none in that language the page says `not available: plain:pl.own` |

`dual:CODE` puts the translation of the same lines beside the original, so it takes only a translation: without a kind your own, else YouTube's; `dual:pl.own` and `dual:pl.translated` choose one. Your own and YouTube's can both be in the saved data and on one page (`dual:pl.own,dual:pl.translated`), to compare them. The author's and automatic subtitles have other lines and times than the original: their section is headed e.g. *Polish, by the author*. What `--video-formats` lists under *subtitles* is what `.author` and `.auto-generated` can take.

**`srt`** writes each version's subtitles also as an SRT file next to the page, for a player such as VLC: `--transcript timed,dual:pl,srt` gives `Title [id].en.auto-generated.srt` (or `.en.author.srt`; `dual:CODE` brings the original too) and `Title [id].pl.translated.srt`; the author's or a dub's subtitles in another language get `.pl.author.srt` or `.pl.auto-generated.srt`. A translation of your own is not written (its `.own.srt` file is the source). The files have the transcript's lines and times (a line break inside a line becomes a space), the same as YouTube's own SRT. They are made with the page and from its data, so `--json load` makes them without YouTube; a file already there (also renamed, found by the id and its ending) is written over only when its text differs; a page that is skipped makes none. `srt` alone means `plain,srt`.

**`ovr`** (with `--json write` or `--json refresh`) downloads the saved transcript again, e.g. after setting the original language; translations of your own that still fit it are kept, the others dropped with a message. A translation of YouTube's that the command asks for (`dual:fr,ovr`) and that YouTube refuses now stays as saved when it still fits; those it does not ask for are not kept. When YouTube's data have no captions for it now, the saved transcript stays as it is, with a warning (nothing new came); only when `--olang` chose another language that has no captions is it dropped, and the console names everything lost with it (translations, your own with their SRT files to merge again, corrections, subtitles). Without `--json` the transcript is downloaded anyway, so `ovr` is an error there.

**`--olang CODE`** sets the video's original language, when you know it better than YouTube shows it (videos with automatic dubs, where YouTube sometimes opens with a dub's captions): the transcript is in it (none, if the video has no captions in it), the video's main audio for `--video` and the *Languages* table follow it, and the page no longer warns that the original is uncertain. With saved data it is recorded; a transcript in another language stays until `--transcript ovr`, with a warning. Not with `--json load` or `--json merge` (it chooses what is downloaded).

Examples: `--transcript`, `--transcript plain,timed`, `--transcript plain,dual:pl,dual:de,srt`, `--transcript timed:ja.author`. Each version at most once; a code that is no language code (`dual:jp`), an unknown kind or a repeated version stops the program before anything is downloaded.

What YouTube does not have or does not send is left out with a note, the page is made and counts as finished (the *Transcript* row says what was left out and why):

- a video without captions at all;
- subtitles or a translation the video does not have (the message lists what it has);
- a translation YouTube refuses to send (`HTTP 429`, which happens often) or whose download fails. Each translation is asked for once, a random 70 to 100 seconds after the video's data was fetched (YouTube refuses translations asked for sooner; the wait is shown on screen), and not again in that run. To add it later: `--json write` with the same `--transcript` (only the translation is fetched, the comments and the copy's date stay; see *Saved data*), or `--page ovr` (everything downloaded again); or translate the subtitles yourself and merge the translation (`--json merge`).

Only when the transcript itself cannot be downloaded is nothing saved for that video, so the next run tries again.

The page shows YouTube's change of speaker (`>>` in automatic captions) as a grey mark, in every version and in the translations too, and leaves it out in the lines under the video. Those lines always come from the original (a page with only translations has it hidden for them), with a language button for each translation on the page (see *Watching a downloaded video on the page*).

### Downloading the video: `--video`

`yt2html "URL" --video` makes the page as usual, then downloads the video itself as an mp4 named like the page (`Title [id].mp4` next to `Title [id].html`), so the page plays it. Parameters, separated by commas:

| Parameter | Meaning |
|---|---|
| (none) | the best quality up to 1080p in AV1, else H.264, with the original audio |
| `720p`, `480p`, … | a quality as an upper limit: the best one not above it, at any frame rate (`720p` takes 720p at 60 frames per second when there is one) |
| `720p30`, `1080p60`, … | the same with the frame rate as a limit too (the parameters in brackets in *Video formats*) |
| `audio:pl`, `audio:de`, … | an extra audio track in that language, as a separate m4a (`Title [id].pl.dubbed.m4a`): a dub by the author first, else YouTube's automatic dub, else another kind; never an audio description by itself. The language finds its regional code (`de` → `de-DE`); a code with a region must match exactly (`de-AT` is not `de-DE`). Repeat for more tracks. With `--json`, a track YouTube does not offer, or that could not be downloaded, is noted in the saved data (`--json show`: `extra audio de  not saved: …`). Tracks added in an earlier run stay in the data and on the page (`audio:de` after `audio:pl` keeps both) |
| `audio:pl.auto-dubbed`, `audio:ru.descriptive`, … | exactly that version: `original`, `dubbed`, `auto-dubbed`, `descriptive`, or another kind the video has |
| `ovr` | download again every file this command makes that is already next to the page, into that file (also when renamed): the video and each track asked for, not other files |

Example: `yt2html "URL" --video 720p30,audio:pl,ovr`. Above 1080p is not offered (the file is meant to play everywhere). Each item once: the same one twice, or a language both alone and with a role (`audio:pl,audio:pl.dubbed`), is an error, as is a code that is no language code (`audio:jp`), all before anything is downloaded; two roles of one language are two tracks (`audio:pl.dubbed,audio:pl.descriptive`). The codes are those of the *languages* table in *Video formats* and of `--video-formats`; a track the video does not have is reported (`"audio:de-AT" not available`, `"audio:en" is already in the video`, `"audio:de-DE" gives the same track as "audio:de"; taken once`) together with what can be taken, and the rest goes on. Subtitles are not part of `--video`: they come from the transcript (`--transcript srt`).

Extra audio tracks play in the page's player instead of the video's own sound (see below); they also work on their own or in a player such as VLC (*Audio* › *Audio Track* › *Add audio file…*).

The order of work: the page first, then a fresh list of formats (the formats' addresses expire) and the download, then the page once more, from the data already in memory, so that its *Video file* row says what was downloaded (`downloaded 12.11.2026: 1080p, 30 fps av1 + en-US aac, mp4, 293 MB`) and *Video formats* marks it in yellow.

- **Interruptions:** the page is ready before the video, so an error or `Ctrl+C` during the download leaves it as it is, and running the same command again resumes the download (the page is skipped, only the video is downloaded; a `….temp.mp4` left by a joining that did not finish is not taken for the video).
- **Existing files:** a file already next to the page is kept (`ovr` downloads it again): the video by the video's id in square brackets in its name, a track by the id and its ending (`.pl.dubbed.m4a`), so renamed files count too (`01 Title [id].pl.dubbed.m4a`). When every file asked for is already there, YouTube is not asked at all and the next video does not wait, so the same command over a playlist asks YouTube only about what is missing.
- **A page that is already there** is not made again: the files are downloaded and the page finds the video the next time it is opened. Its *Video file* row does not list them, and the player has no switch for a new audio track; the console says so. To add them, make the page again: `--json write` if it has saved data (the files are recorded in them), else `--page ovr` (the files there are kept, not downloaded again).
- **Without `--json`** saved data are not read, so a page made again describes the files only as lying next to it; with `--json write` the data record what was downloaded (the day, the variant).
- **Playlists:** each video goes through the whole cycle, with a pause of 5–15 seconds before the next video that needed a download.
- **Limits:** `--video` cannot be used with `--json load` or `--json merge` (it needs YouTube) or `--index-only`. Without ffmpeg the page is made and the video skipped, with the command to install ffmpeg. With `--olang` the main audio is the track in that language, when there is one.

### Saved data: `--json`

The data a page is made from can be saved next to it as `Title [id].info.json`: what yt2html uses of yt-dlp's data of the video (description, counts, formats, comments, the languages of the captions, …) together with what yt2html adds (the transcript and its translations, the chapters and other timestamp lists, info cards, the extras of the video page, what `--video` downloaded). They let you make the page again later without YouTube (a newer look after an update of yt2html), add what is missing, and refresh what changes. The file is yt2html's own format, with yt-dlp's names for its fields: it keeps no download addresses (they expire within hours, and they hold your IP address), so it is not a file for `yt-dlp --load-info-json`; whatever downloads takes fresh data from YouTube. `--json` takes one parameter:

| Parameter | What it does | Asks YouTube for | Comments and counts | The copy's date |
|---|---|---|---|---|
| `write` | saves the data with the page; where they are already there, adds what the options ask for and they lack | everything for a new video; only what is missing for saved data | downloaded now, or as saved | today, or as saved with a note of the update |
| `refresh` | as `write`, and refreshes what changes over time | the video's data with the comments, then what is missing | refreshed; the comments merged with the saved ones | as saved, with a note and, from another day, a *Refreshed* tile |
| `load` | makes the page from saved data only | nothing (images aside) | as saved | as saved |
| `merge` | adds a translation of your own (an SRT file) to saved data; makes no page | nothing | as saved | as saved, with a note of the update |
| `show` | lists what saved data hold; makes no page, changes nothing | nothing | as saved | as saved |

Without `--json` the program neither reads nor writes saved data: `--page ovr` then makes the page from YouTube alone, and a data file there stays as it was, no longer matching the page.

**`--json write`** depends on what the folder holds for the video:

- **Nothing:** a normal download; the page and its data are saved.
- **Page and data:** what the options ask for and the data lack is added: the transcript (`--transcript`), versions and translations not in the data, also those YouTube refused before (subtitles or a translation YouTube does not have are noted and not asked for again), the files of `--video` and the SRT files of `--transcript srt` that are not next to the page yet. Only these are asked of YouTube (the video's data without the comments, since caption addresses expire, then what is missing, with the same 70–100 s wait before a translation); the page is made again and the data saved back. **Nothing missing:** nothing is asked and the page and data stay as they are; for another look or fewer comments use `--json load`. If the page was not made from these data (after `--json merge`, an interrupted run or an edit of the file), the console says so and leaves it; `--json load` makes it again from them.
- **Data without a page:** the page is made from the data, with what is missing added.
- **A page without data:** skipped (`Skipped (page exists, no saved data to add to)`), since saving data now would describe today's video, not the page; `--page ovr --json write` downloads everything again and saves both.

**Page and data together:** the page is made first, with all its images; only then are the data and the page written, one right after the other, so `Ctrl+C` or a lost connection leaves both as they were. The page keeps an invisible mark of the data it was made from.

What stays: the comments, the counts (views, likes), the description and the copy's date (*Snapshot*, *Downloaded*). *About this copy* adds the day and time of each run that added something to *Downloaded*: `…; updated 20.11.2026 10:12` (what it added shows in the other rows; the data keep the details). With `--video`, the *Video formats* section takes the list the files were chosen from, as with a download.

**`--page ovr --json write`** always starts again: everything is downloaded from YouTube and replaces the page and the saved data, in their file. The console names everything only the old data had, part by part: `Replacing the saved data from 12.10.2026: … (lost: own translation pl; 14 comments no longer on YouTube; the history of 3 comments; the record of the video file (1080p av1); the notes of what did not come: transcript fr)`; also the transcript, the comments or the info cards when this command does not ask for them. The record of a file you deleted goes without a word. **The history stays:** the earlier runs and the earlier titles and descriptions go into the new data (YouTube cannot give them again), and the page's *Downloaded* row lists the runs before it (`before it: downloaded 12.10.2026; updated 20.11.2026 …`). A video YouTube no longer shows fails before anything is written.

**`--json refresh`** does what `write` does and also downloads the video's data again, with the comments, to refresh what changes over time:

- **Counts, title and description:** views, likes, subscribers and YouTube's comment count are taken anew, and so are the title, the description and the chapters and other timestamp lists made from them (the earlier title and description stay in the data; the page shows the current ones without a note). Info cards and the rest stay as saved.
- **Comments, merged by their id:** new ones are added; those still there are taken as they are now (text, likes, time; an earlier text stays in the data); those YouTube no longer sends stay on the page with a grey mark, `not on YouTube on 20.11.2026`, the day of the refresh that first missed them. A comment that is back later loses the mark (the data keep when it was missing). Comments turned off on YouTube since the download stay too, with a note above them, `As of 03.12.2026, comments on this video are turned off on YouTube; the ones below can no longer be seen there.` (gone again when they are on). With `--page comments:no` the saved ones stay as they are; after a download with a limit or one stopped with `Ctrl+C` nothing is marked, since missing comments prove nothing then. The default limit of 1,000 applies to the refreshed comments too (the console says when it cut them): `--page comments:all` refreshes all.
- **On the page:** the comments line and the *Comments* row of *About this copy* add how many are no longer on YouTube; *Downloaded* adds the day and time of each refresh, e.g. `…; refreshed 03.12.2026 18:40`; a *Refreshed* tile with the day of the last refresh stands next to *Snapshot* when it is another day (`--page snap:no` leaves out both). The copy's date stays.
- **A video no longer on YouTube** (removed, its account terminated, made private): the refresh records it (`No longer on YouTube: <YouTube's words> (recorded)`) and changes nothing else in the data: the title, description, counts and comments stay as saved, nothing missing is added, and the page is made again from them. On the page the *Refreshed* tile shows the day of that check in a muted red, also on the copy's day, and *Downloaded* adds the check with YouTube's words after the last one: `…; no longer on YouTube 03.12.2026 14:05 “Video unavailable. This video is no longer available because the YouTube account associated with this video has been terminated.”`. Each later refresh checks again; when the video is back, the next refresh is an ordinary one, the tile is grey again and the earlier checks stay in *Downloaded* without YouTube's words. YouTube's thumbnails go with the video; the page keeps the one it had. Other refusals (`Sign in to confirm you're not a bot`, `try again later`) may not last: the video fails (`FAILED: …`) and the data stay as they were.
- Everything else as for `write`: without saved data a full download, a page without data skipped, the page made again, the data saved back; `Ctrl+C` during the comments stops the run after the page, as with a download. `--json refresh` with `--page ovr` is an error.

**`--json load`** makes pages only from saved data and asks YouTube for nothing:

- **What it takes:** the video id, also as the name of its page or video (`yt2html VIDEO_ID --json load`): the data are looked up by the id in square brackets in the output folder; a data file by its name (`"Title [id].info.json"`), or several with `*` and `?` (`"*.info.json"`; this works also in PowerShell and cmd, and square brackets are part of the name). Saved data are files ending in `.json`.
- **What comes from the data:** everything except images. The images come from the page being replaced; those it lacks are downloaded from their addresses in the data (YouTube may have removed them by then; missing avatars become letters), and what still does not come is noted in the page (`--json show`: `images  partly saved: …`). The snapshot date stays the day of the download.
- **Options:** `--page` and `--transcript` work as with a download, from what the data hold (fewer comments, another theme, any versions of a saved transcript, its SRT files). What is not in the data cannot be added (that is what `write` is for, and `refresh` for more comments): a translation that was not downloaded (a version neither in the data nor noted there as left out fails that video), the video (`--video` cannot be used with `--json load`).
- **Existing pages are always replaced**, without `ovr`; the page keeps its current name. The data stay as they are.
- **Missing data:** that video fails (`FAILED: …`, the run ends with exit code 1); nothing is downloaded instead.

**`--json merge`** adds a translation of your own to saved data: when YouTube refuses its machine translations (`HTTP 429`), translate the subtitles in the video's original language yourself (by hand or with a tool) and merge the result. Nothing is asked of YouTube, and no page is made.

1. Save the original's subtitles with the data: `yt2html "URL" --json write --transcript srt` gives `Title [id].en.auto-generated.srt` (or `.en.author.srt`), the same lines as the transcript.
2. Translate it and save the translation next to it as `Title [id].pl.own.srt` (`own` sets it apart from YouTube's kinds of subtitles).
3. `yt2html --json merge "Title [id].pl.own.srt"` (also as a pattern, `"*.own.srt"`) merges it into the saved data with the same id.
4. `yt2html VIDEO_ID --json load --transcript plain,dual:pl` shows it, in a second column headed `Polish, own translation` (`plain:pl` and `timed:pl` show it too, and `dual:pl.translated` YouTube's beside it, when the data have that).

- **What the file must be:** a translation of the subtitles the transcript was made from: the same number of lines, each starting at the same moment as the transcript's line, none empty. Words may move between neighbouring lines, lines may not be joined or split. Anything else is an error that names the first line that does not fit, and nothing is saved.
- **What it saves:** the translation as your own translation into that language, with the file's name and the day, beside YouTube's translation into it if the data have one (that stays). A version without a kind then takes yours, so `--json write` no longer asks YouTube for its translation into that language, unless you ask for it by name (`dual:pl.translated`). A translation of your own already there is replaced (with a message). `--page ovr --json write` downloads new data without it (the console names it among what was lost); the SRT file stays, merge it again.
- **On the page:** *About this copy* names it in the *Transcript* row (`dual with Polish (own translation)`) and adds the run to *Downloaded* (`…; updated 22.11.2026 14:05`); *Video formats* lists the translations of your own the page shows. The *Command* row leaves them out: a command cannot get them from YouTube.
- **Options:** only `-o`; `--transcript`, `--page`, `--video`, `--index` and the others are errors (with `--transcript`, the message gives the `--json load` command that shows the translation).

**Corrections of the transcript** go the same way: automatic subtitles often have obvious mistakes (names, terms, misheard words). Correct the original's SRT file (step 1 above) and save it as `Title [id].en.fixed.srt`, in the transcript's language; `yt2html --json merge "Title [id].en.fixed.srt"` merges it and `--json load --transcript` shows it.

- **What the file must be:** as for a translation, the same lines starting at the same moments, only their text corrected, so every translation still fits. A `.fixed.srt` in another language, or an `.own.srt` in the transcript's own language, is an error that names the right file name.
- **What it saves:** the corrected text beside YouTube's, which stays in the data; corrections already there are replaced (with a message). `--transcript ovr` keeps them when they still fit the transcript downloaded again, else drops them with a message; `--page ovr --json write` downloads new data without them (named among what was lost).
- **On the page:** the corrected text everywhere the original is shown (plain, timed, the left column of `dual`, the player's subtitles), headed `English, auto-generated, with own corrections`; *About this copy* adds to the *Transcript* row `the original with own corrections (Title [id].en.fixed.srt, 25.11.2026)`. The page cannot show YouTube's text instead, and the original's SRT file of `--transcript srt` stays YouTube's text (the source to correct).

**`--json show`** lists each part of a copy in its saved data, with what it holds or why it is missing, and which files lie next to them; it asks YouTube for nothing and changes nothing:

```
Kurs [Un9FT291lsU]  (Kurs [Un9FT291lsU].info.json, 4.2 MB)
  Data:       downloaded 22.11.2026 23:01 (yt2html 0.10.7)
              updated 25.11.2026 (translation en)
  Contents:   playlist            saved: video 3 of 12 in Kurs Pythona
              video page          saved
              markers             saved: chapters (12), from the description
              info cards          saved: none
              transcript          saved: pl (Polish, auto-generated), 812 lines
              transcript de       saved: own translation, 23.11.2026
              transcript en       saved: YouTube's translation
              transcript en.auto-generated  saved: subtitles of their own
              transcript fr       not saved: YouTube refused to send it (HTTP 429), 14.11.2026
              comments            saved: 412 of 430, 2 not on YouTube
              video file          saved: 1080p av1 + pl aac, 22.11.2026 (--video audio:en)
              extra audio en      saved: auto-dubbed
  Transcript: corrections: Kurs [Un9FT291lsU].pl.fixed.srt (25.11.2026)
              possible: plain, timed, dual:de, dual:en, plain:en.auto-generated
  Next to it: page, mp4 (described), en.auto-dubbed.m4a, 2 SRTs: pl (auto-generated), en (translated)
  (to try again: yt2html Un9FT291lsU --json write --transcript plain,dual:fr)
```

- **Levels:** `--json show:brief` gives one line per video with only what is missing (`Kurs [Un9FT291lsU]  not saved: transcript fr`, or `all saved`), for a look over a whole folder; `--json show:standard`, the same as `--json show`, the block above; `--json show:full` also names the parts no command asked for (`comments  not asked for: --page comments:no`, `video file  not asked for`), a full map of the copy.
- **`Contents`:** the parts in the order of *About this copy* on the page. Each is `saved`, `partly saved` (e.g. comments interrupted with `Ctrl+C`, a video page read without the player data), `not saved` (a command asked for it and it did not come: the reason and the day, `(not asked for again)` when YouTube does not have it, so the same command does not ask again) or, with `show:full`, `not asked for`. A translation, subtitles of their own and an extra audio track get a line of their own only when the data have them or note them as missing. The images are in the page, not in the data, so their line comes from the page next to the data (none without a page).
- **What it takes:** the sources of `--json load` (video ids, names, `.info.json` files, patterns such as `"*.info.json"`), or `--index FILE`: the videos of the list, its playlists as its index page keeps them (a playlist the index does not keep is left out, with a note). For several videos a last line sums them up: `12 videos: translation en in 9, own translations in 2; video in 12 (720p 8, 1080p 2, 480p 2; 1 not described); no page for 1` (with `--index`, also the videos of the list without saved data).
- **`possible`:** the `--transcript` versions `--json load` can show from the data, one for each source: `dual:CODE` for a translation (`dual:CODE.translated` for YouTube's when your own is there too; `plain:` and `timed:` take the same), `plain:CODE.KIND` for subtitles of their own.
- **`Next to it`:** found by the id in square brackets and the ending, as the page finds them. A video file is `described` when the data describe it (the same size): the *Video file* row and the yellow marks in *Video formats* show its quality; `not described` when they do not (downloaded without saved data, or replaced). `missing` names files the data describe that are gone. `page (not made from these data)`: the data changed after the page was made (`--json merge`, an interrupted run, an edit), with a hint to make it again.
- **Hints** in brackets: the command that asks again for what YouTube refused, and the one that makes a missing page.
- **Options:** `-o` and `--index` only; `--page`, `--transcript`, `--video`, `--video-formats`, `--olang` and `--take` are errors. A source without readable data is `FAILED` (exit code 1); the others are shown.

### Many videos

**Playlists:** a playlist URL (`https://www.youtube.com/playlist?list=...`) or id archives all videos of the playlist in its order, e.g. all episodes of a podcast. A link to a video opened from a playlist (`watch?v=...&list=...`) archives only that video. Channel URLs (`@name`) are not supported: open the channel's playlist and use its URL. Playlists are read first, then their videos are taken in the command's order; a video in two playlists, twice in one or also given on its own is taken once.

**Videos that already have a page are skipped**, so running the same command again only archives what is missing. A page is any `.html` file with the video id in square brackets in its name, e.g. `[Z8lf5oWKfj0]`: you may rename pages freely (`042 My title [Z8lf5oWKfj0] (copy).html`) as long as that part stays. If several files fit, the first by name is used and a note says so. Only the output folder itself is checked, not its subfolders.

**`--take N`:** a run takes at most 100 videos from YouTube (`--take 300` more, `--take all` without a limit). Only videos that need YouTube count, each once with all its files (page, transcript, video, tracks); a video whose page and files are there is skipped without YouTube and does not count, a failed one does. A longer playlist is done in parts: the console ends with `--take 100: 100 of 340 videos that need YouTube were taken; run the same command again for the next ones`. With `--page ovr` or `--json refresh` every video asks YouTube, so the same command would take the same ones again: the console then gives the `--take` that takes them all. `--json load`, `--json merge` and `--index-only` ask YouTube for nothing and refuse `--take`.

For a series of videos you want to keep together, write them into a **list file** and archive it with `--index` (next section): the list also gets an index page.

### List files and their index

A list file is a plain text file (UTF-8, Notepad's default; any extension: `series.txt`, `series.md`) with one video or playlist per line. `yt2html --index series.txt` archives what the list names and is not in the folder yet, then makes the **index page** `series.html` in the output folder (`-o`, next to the pages: its links are relative). It replaces only an index: when a page of that name is there that yt2html did not make as an index (your own `index.html`, or a video's page for a list named like it), the run stops before anything is downloaded and says so. `yt2html --index-only series.txt` only makes the index, from what is in the folder, and downloads nothing. The program only reads the list file, never changes it; it may lie anywhere. One list file per run; a URL in the same command is an error (add it to the file).

The simplest list is just addresses or ids:

```text
https://www.youtube.com/watch?v=Z8lf5oWKfj0
https://youtu.be/qyqCTMirNWg
PLeBgIYTbh-CwGJwFnluRTgBkvcM2q6jOO
```

A list can also be organised, in a way close to Markdown (a `.md` list looks like its index in a Markdown preview):

```text
!numbers: no
!layout: cards !theme: dark
# Railways of the world
> My collection. **Japan** first, then _the rest_; sources: [example.org](https://example.org)
## Japan
Z8lf5oWKfj0
> The best introduction, start here.
= Rail in numbers
The Largest Rail System In the World [qyqCTMirNWg].html
### My own recordings
Holiday in the Tatras.mp4
## A course for dessert
// a playlist next to nothing else puts its videos right here
PLeBgIYTbh-CwGJwFnluRTgBkvcM2q6jOO
```

| Line | Meaning |
|---|---|
| an address or id of a video | a video; also the name of its page or video file with `[VIDEO_ID]` (`Title [Z8lf5oWKfj0].html`) |
| an address or id of a playlist | its videos, read from YouTube each time the index is made (see below) |
| `Holiday.mp4` | a video file of your own in the output folder (`mp4`, `webm`, `m4v`, `mkv`; the name only, no folder) |
| `# Title` | the title of the index, at most once; without it, the file's name (`series`), or the playlist's title when the list has exactly one playlist |
| `## Chapter`, `### …`, `#### …` | chapters on three levels, shown as written (a skipped level or an empty chapter stays) |
| `> text` | a note: each such line is one paragraph; `**bold**`, `*italic*` or `_italic_`, `((grey))` (the grey the index uses for what the program adds; brackets inside in pairs, so `(((2020–2025)))` greys `(2020–2025)`); a link is `[text](https://address)` (an `http(s)://` address, up to the first `)`; with empty brackets, `[](https://address)`, the address itself shows); anything else stays as written, a bare address too. Notes after a video belong to it (shown with it, where `!layout` puts them), notes after a heading introduce the chapter, notes after a playlist follow all its videos; notes of a chapter stand at its indent, its videos and chapters one step in |
| `= Title` | a title of your own for the video, playlist or file on the very next line (instead of the title from the page, from YouTube or the file's name) |
| `= !date: 03.08.2019`, `= !lang: pl` | details of your own for the video or file below (not for a playlist), on `=` lines like the title, before or after it; several on one line (`= !date: 2019 !lang: pl`), each at most once. A `=` line that starts with `!date:` or `!lang:` holds details; any other is the title, so a title may start with `!`. `!date` is `DD.MM.YYYY`, `DD.MM.YY`, `MM.YYYY` or `YYYY`, leading zeros optional, from 1900 to this year (a two-digit year is the latest such year up to now: in 2026, `26` is 2026 and `27` is 1927); `!lang` is a language code (`pl`, `en-US`). They replace the date and language from the page and give your own files, and videos without a page, what they lack; `!dates: no` hides the dates too. Any case, the space after `:` optional |
| `// text` | a comment, ignored |
| `!numbers: no`, `!thumbnails: no`, `!dates: no` | settings for the whole list (see below): no numbers (otherwise grey, before each title, numbered per level; the index looks the same without them); no images (a small round play button instead, the duration in the line); no dates (otherwise a video's publication date opens the line under its title, `03.05.2024`, when its page is downloaded, and a playlist shows the span of its videos' dates) |
| `!layout: plain`, `compact`, `cards` | how rows and notes look: **`plain`** (the default) puts a video's note under its thumbnail, across the whole width, without a frame; **`compact`** puts it beside the thumbnail, under the title; **`cards`** puts the title, its line and the note into one rounded frame beside the thumbnail, for every row (at least as tall as the thumbnail). The notes of chapters and the list follow: without frames in `plain` and `compact`, framed in `cards` |
| `!theme: light`, `dark` | the index always light or dark (default `auto`: it follows the device); the video pages take theirs from `--page theme:` |

Settings stand at the top (before the first chapter, video or playlist), each at most once, one or several on a line (`!numbers: no !layout: cards`); `yes` and `auto` are the defaults; any case, the space after `:` optional. Blank lines do not matter. Every other line is an error: the run stops before anything is downloaded and names the line (`series.txt, line 7: not a video, playlist or video file: …`). Note that `#` starts the title and chapters: comments start with `//`.

**Playlists in the list:** a playlist that is the only element of its level (not counting notes) puts its videos in its place; next to other videos, playlists or chapters it becomes a chapter one level lower, titled as on YouTube (at the third level its videos stand next to the others). Under an empty heading (`##` alone) the only playlist gives the heading its title. Each playlist gets two notes: *Playlist* and its title, the number of videos (YouTube's count, which includes videos it no longer shows) with, in grey, the span of their publication dates, oldest to newest, as far as the pages in the folder tell them (`known range …` or `known …` when some are not downloaded), and *Channel* with its name; then its description, each of its lines a paragraph as in your notes (blank lines left out, spaces at the ends trimmed). YouTube gives no dates in a playlist, so the span comes only from the downloaded pages. Titles always come from the pages, never from the playlist: YouTube sends the titles in a playlist translated into the language it is asked in (English), while the pages keep the originals.

**Videos removed from a playlist** whose pages are in the folder stay in the index: at the end of the playlist, in the order of their old places, each with *removed from the playlist* in its line, and the playlist's notes count them apart, in grey: *(+2 removed from the playlist, kept here)*. The rest of the playlist follows YouTube's current order; a video back in the playlist is in its place again, and one the index shows elsewhere (in another playlist or on a line of its own) is shown there only. A page knows the playlist it was downloaded from (and its place there); a video downloaded on its own disappears when its playlist drops it.

**What the index shows:** each video in one dense row: its thumbnail with the duration on it (it plays the file in the index's player, below), the title linking to its page (in a new tab), and a small line: the publication date and the language of the video (or those of `= !date:` and `= !lang:`), the file's format (hover for the file's name) and *YouTube* (hover for the original title). Videos are numbered on each level from 1, chapters too. What is missing in the folder is said in grey italics, and the console names the line:

| In the line | Meaning |
|---|---|
| *only the page downloaded* | the page is there, the video file is not (dimmed thumbnail) |
| *not downloaded* | neither page nor file: the title is the video's id (or the `= Title`, or the name in the line); `--index` downloads it |
| *file not found* | your own file is not in the output folder: check the name |
| *no longer on YouTube* | instead of the YouTube link: the video was gone at the last `--json refresh` |
| *playlist could not be read* | in the place of a playlist YouTube did not give and the index did not keep |

Good to know about the index:

- **It always shows what is in the folder.** It is made at the end of every run with `--index` (also after `Ctrl+C`, and after each part of `--take`; when `Ctrl+C` comes while the playlists are read at the start, nothing has been downloaded and the index stays as it was), from the pages (only their metadata, at the top) and the files lying there, never from what this run downloaded. `--index`, `--index-only` and `--index … --json load` give the same index for the same folder; why a download failed is only in the console.
- **Renaming is safe.** Pages and video files are found by `[video id]` in their names, so after renaming them the index links to the new names and still shows the original titles; run `--index-only` to refresh it.
- **Playlists are read each time** (only their list, one request per about 100 videos, also with `--index-only` and `--json load`): videos added on YouTube appear in the index. The index keeps each playlist's list inside, invisibly; when YouTube cannot be reached, or sends a playlist only in part (yt-dlp: *Incomplete data received*), that list is used and the console says so, so a shortened list is never taken for the playlist. `--cookies` works for private playlists.
- **With `--json`:** `load`, `write` and `refresh` work with `--index` as with videos in the command, then make the index; the saved data are found by the video id in the output folder. With `load`, a video of the list without saved data is skipped with a note (`No saved data for …; skipped.`). `merge` is an error with `--index`.
- **`--index-only` only makes the index:** it takes `-o` and `--cookies`; the options that download or shape the pages (`--page`, `--transcript`, `--olang`, `--video`, `--json`, `--take`) are errors with it.

**The player of the index:** a panel on the left, always there, with the list scrolling on the right (on narrow windows and phones it stays at the top, as on a video's page). A click on a thumbnail (or the round button) plays that file; until the first one the whole panel is greyed. Below the video and its position: one row of equal buttons that wraps in a narrow panel: **|◀◀** the previous file, to the start (stops the video), 10 seconds back, play/pause, 10 seconds forward, to the end, **▶▶|** the next file and **A** (*Autoplay*, off at first: when a file ends, the next one plays); then the speeds 0.25× to 2× (kept from file to file) and the title of the file playing. The previous and next file keep what the player was doing: playing goes on playing, stopped (paused, at the start or after the end) waits at the start of the other file, with its first frame and duration; after a file that could not be played, the state from before it. They skip rows without a file and are greyed at the first and last one; when the row of the new file is out of sight, the list scrolls just enough to show it (*Autoplay* scrolls only if the row that ended was in sight, so it never pulls you away from what you are reading). Only one audio track, the video's own, and no transcript: those are on the video's page (the title links to it, in a new tab, so the index keeps playing). A click on the file that is in the player does nothing; the panel controls it.

- Keys after the first play: as on a video's page (`Space`, `←` / `→`, `Ctrl`+`←` / `Ctrl`+`→`), plus `Shift`+`P` / `Shift`+`N` the previous / next file. Media keys and the picture-in-picture window can also go to the previous and next file.
- **A file that cannot be played** (moved or deleted since the index was made, or in a format the browser does not play, e.g. HEVC in Firefox or some `.mkv`; the browser does not tell these apart): the screen says *This file could not be played.* with its title, its thumbnail dims and only the previous and next file work. The previous, next and *Autoplay* skip it from then on; *Autoplay* stops at such a file the first time it meets it. Reload the page after putting the file right; `--index-only` brings the index up to date with the folder.
- Without JavaScript the index is a plain list (no panel); the links work as usual.

### Signing in: `--cookies`

When YouTube asks to sign in (an age-restricted video, a private playlist) or to confirm you are not a bot, `--cookies firefox` uses the browser's cookies (the browser need not be open; without a profile, the one used most recently). A given profile: its folder name (Firefox: `about:support`, *Profile Folder*) or path, `--cookies "firefox:fTW1hk7Y.Profile 1"`. On Windows Firefox works reliably; Chrome and other Chromium-based browsers encrypt their cookies in a way yt-dlp usually cannot read there. Unlike yt-dlp's `--cookies`, which takes a `cookies.txt` file, this one takes a browser. With `--json load` and `--json merge` it has no effect (nothing is downloaded; the console says so).

### Watching a downloaded video on the page

If the downloaded video lies **next to the page**, the page shows a turquoise **▶ Play** tile first among the facts. Under *Play* it names the video file: its quality as YouTube names it and the language of its audio (`1080p · en-US`; a long language code is shortened to the language, `en`). A browser cannot look into a folder, it can only try names, so the page tries, each time it is opened:

1. video files with the video's id in square brackets in their name, found **when the page was made**, whatever the rest of the name (`042 renamed [id].mp4`);
2. the page's own name (`Title [id].mp4` next to `Title [id].html`; also after renaming both the same way);
3. yt-dlp's default name `Title [id]` (when only the page was renamed).

So a video downloaded later works without making the page again if it has the page's name or yt-dlp's default name; under any other name, make the page again (`--json load` or `--page ovr`) and it is found by its id. The same after renaming a video. Formats: `.mp4`, `.webm`, `.m4v`, `.mkv`.

**▶ Play** opens a player pinned on the left, so you can watch (or listen to a podcast) while scrolling the description, chapters, transcript and comments on the right; the thumbnail is hidden meanwhile. **✕ Close** pauses the video and restores the page; *Play* continues where you stopped.

- Buttons: to the start (stops the video), 10 seconds back, **↺ previous sentence**, play/pause, 10 seconds forward, to the end, and the speeds 0.25× (for language learning) to 2× (lectures, podcasts). Buttons that show symbols or language codes also carry a spoken name for screen readers and voice control (e.g. *To the start*, *Polish, auto-dubbed*), invisible on the page.
- **↺** goes back to the start of the previous sentence of the transcript, handy for repeating a phrase when learning a language; each further click goes one sentence further back. If that would be more than 20 seconds back (a long pause, music), or the page has no transcript, it goes 5 seconds back.
- Keys while the player is open: `Space` play/pause, `←` / `→` 10 seconds back/forward, `Shift`+`←` previous sentence, `Ctrl`+`←` / `Ctrl`+`→` to the start / to the end.
- **Other audio** (a working version): when the page knows extra tracks (`--video audio:pl` together with the page, or recorded in its saved data), a last row of switches shows their codes, the original first (a little wider, on at the start). One is on at a time; with a track on, the video plays muted and the track follows it, also when seeking, pausing or changing the speed. A track added later, for a page that already existed, needs the page made again (see *Downloading the video*). Renamed tracks play too: the page tries the file with the video's id and the track's ending found when the page was made, then its own name with that ending (`01 Title [id].pl.dubbed.m4a` next to `01 Title [id].html`), then the name the track was saved under. The page looks for every track's file as soon as it finds the video, so a track none of these names finds is greyed out at once; when the file is back, the switch works the next time the page is opened. The transcript and the subtitles stay those of the original.
- A separate video window (picture in picture) is available through the browser itself: right-click the video in Chrome or Edge, or use Firefox's own button on the video; the page returns to its normal layout meanwhile.
- On narrow windows and phones the player stays at the top and the page scrolls below it.
- Browsers play mp4 with H.264 video and AAC audio everywhere; `--video` downloads mp4 with AV1 (else H.264) and AAC, which Chrome, Edge and Firefox play too (Safari plays AV1 only with a hardware decoder). Videos in HEVC/H.265 do not play in Firefox; `.mkv` plays only in some browsers.

**Timestamps play the local copy.** While the player is open, a click on a timestamp plays your copy from that moment instead of opening YouTube (the timestamps turn turquoise). This works everywhere the page has timestamps:

- chapters and other timestamp lists (e.g. Walkthroughs);
- info cards;
- the transcript with timestamps and the dual transcript;
- the description and the AI-generated summary (times written in the text, e.g. `12:30`);
- comments (e.g. `3:15 best part`);
- the continuous transcript: it shows no times, but each sentence knows its own, so a click on a sentence plays from there.

With the player closed, timestamps open YouTube; `Ctrl`+click always opens YouTube.

*Subtitles*, ↺ and *Follow* use the transcript, so they need a page made with `--transcript`.

**Subtitles under the video.** *Subtitles* (off at first) shows the current sentence of the original under the video; each click adds context and then turns it off again: the sentence only (one hollow dot on the button), with one sentence before and after it in grey (one dot), with two (two dots), off. Next to *Subtitles* there is a small button for each translation on the page (`pl`, `de`, … in the order of the transcripts, each language once; none without one; subtitles of the author or of a dub in another language have other lines and get none). They work once *Subtitles* is on: a click shows that translation under the current sentence, another language replaces it, and a second click on the active one hides it. When the page has two translations into one language (yours and YouTube's), its button carries a small index, `pl₁`, numbered in the order of the transcripts: a click on the active button goes to the next one (`pl₂`), and after the last turns the translation off; another language keeps the one shown last. Turning *Subtitles* off also turns the translation off. A click on the subtitles shows the place in the transcript on the right: in the followed transcript while *Follow* is on, otherwise in the one the subtitles come from.

**Chapters** (off at first) shows the current chapter above the subtitles, on one line (a long title is cut with `…`); its place stays reserved, so turning it on or off never moves the subtitles. The current chapter is also marked in the chapter list. Buttons appear only when there is something to show: a page without a transcript has only *Chapters*, a page without chapters has no *Chapters*.

**Follow** marks the current sentence in the transcript on the right and keeps it in view as the video plays. With several transcripts on the page, pressing *Follow* again moves to the next one (*Follow 2/3*), and after the last one it turns off. Scrolling the page yourself also ends it; *Follow* then starts again with the transcript you followed last (as long as the page stays open).

### Video formats

Above *About this copy*, *Video formats* is folded to a grey line with a short summary: the top quality and the language of the original audio (`up to 1080p, 30 fps · original audio: en-US`). Opened, it lists what YouTube offered when the data was fetched:

- **Image** by quality (YouTube's name for it, as in its quality menu, with the frame rate, e.g. `1080p, 30 fps`), resolution (the actual size of the image, e.g. `1920×1080`; YouTube calls a wide `1920×804` or a vertical `1080×1920` "1080p" too) and codec (h264, av1, vp9; formats for YouTube Premium accounts in their own columns; HLS formats only named, since YouTube gives no reliable size for them) with approximate sizes including the audio. A quality a download of the video can take (up to 1080p, in AV1 or H.264) has its parameter in brackets, e.g. `1080p, 30 fps (1080p30)`.
- **Languages:** one row per audio track (code, language, role: original, dubbed by the author, auto-dubbed by YouTube, audio description; a single track whose language YouTube does not give takes the original language shown in the *Transcript* row) with the subtitles in that language (by the author, and auto-generated from that track's speech: a dub has its own); subtitles without such audio in rows of their own (the languages with audio first, the original's first).
- **Machine translation:** a line on YouTube's machine translation of subtitles (`machine-translated subtitles: possible in 155 other languages for each row with subtitles`, made on request; without subtitles `none (no subtitles to translate)`; `unknown (…)` when YouTube listed no languages, or when the list could not be read, which making the page again later usually fixes).
- **Translations of your own** (`--json merge`) that the page shows: a line under it, `own translations: pl (added 22.11.2026), de (added 25.11.2026)`, the codes in yellow.
- **Colours:** cells in blue show what `--video` takes by default: the best quality up to 1080p in AV1, else H.264, with the original audio, as mp4. Cells in yellow show what `--video` downloaded; when it took something else, the default stays blue. Tracks only found next to the page are yellow too (their language and role are certain); a video only found is not (its variant is not known).

When YouTube sent no video or audio formats at all (it happens for a while, e.g. after several requests for the same video in a row; only the small preview images for the seek bar come), the section says so in one line; making the page again later usually brings them. The *Video file* row of *About this copy* says what `--video` downloaded, by day (`downloaded 12.11.2026: 1080p, 30 fps av1 + en-US aac, mp4, 293 MB; extra audio m4a: pl (dubbed), 69 MB`), then the files it only found next to the page, without a day (`next to the page: video 01 Title [id].mp4, 293 MB`), else `not downloaded`, and notes how the list came about (with or without Deno, signed in or not).

`--video-formats` prints the same choice on the screen without making a page (only the video's data is fetched, no comments; with `--json load` from saved data, offline). It counts towards `--take` and cannot be combined with `--page`, `--transcript`, `--video`, `--index` or `--json write`, `refresh` and `merge`.

```
Give Me 1 Hour, I Will Make Artificial Intelligence Click Forever [fCEvvkAbJOs]
image (mp4, AV1 else H.264; sizes include the audio: en-US aac):
  1080p, 30 fps  (1080p30)  av1  ~293 MB  (default)
  720p, 30 fps   (720p30)   av1  ~214 MB
  ...
audio (mp4, aac; extra tracks m4a, aac, ~69 MB each):
  in the video: en-US (original)
  auto-dubbed: ar, bn, de-DE, es-US, fr-FR, hi, id, it, iw, ja, ko, ml, nl-NL, pa, pl, pt-BR, ru, ta, te, uk
subtitles (srt):
  auto-generated: en, ar, bn, de, es, fr, hi, id, it, iw, ja, ko, ml, nl, pa, pl, pt, ru, ta, te, uk
```

Both headers start with the container and codec of what goes into the video; after the semicolon, the image header names the audio track the sizes include and the audio header describes the extra tracks. The audio lines show the track in the video and, by role, the dubs a download can add as separate m4a files (`audio:CODE`, e.g. `audio:pl`; an audio description as `audio:CODE.descriptive`). The parameters in brackets and `audio:CODE` are what `--video` takes (see *Downloading the video*). The subtitle lines show the video's own subtitles by code: the author's and the auto-generated ones, which `--transcript` takes for the original and for other languages (`plain:ja.author`, `timed:pl.auto-generated`); machine translations are not listed.

### About this copy

At the bottom of every page, *About this copy* is folded to a single grey line with the snapshot date, which is there in any case, also with `--page snap:no`. Opened, it describes this particular copy in rows that are always the same: *Downloaded*, *Page built*, *Playlist*, *Command*, *Video page*, *Markers* (chapters and other timestamp lists such as Walkthroughs), *Info cards*, *Transcript*, *Comments*, *Images*, *Video file*, *Software* and *Disclaimer*. They tell when and with which versions the copy was made, give the command that makes an equivalent copy again (with the options that differ from their defaults), and say what was left out or did not work, so two copies of the same video can be compared row by row.

## Good to know

- The number of downloaded comments is usually a bit lower than YouTube's count (deleted or hidden comments); the page shows both. A limited download (1,000 by default) shows as fewer downloaded comments (*About this copy* says whether they were limited or interrupted); `No comments.` appears only when the video really has none. When comments are turned off, the section says so in YouTube's words (`Comments are turned off.`), or `Comments are unavailable.` when YouTube did not say why; a section with nothing to count has no line of numbers.
- Comment times are as YouTube showed them on the download day (`3 years ago`); hover over one to see the estimated date. Subscriber counts are rounded by YouTube (`1.23M`); views and likes are exact. A video nobody has liked yet shows `0` likes; when the author hides the like count (or the video page could not be read), *Likes* shows `—`.
- The transcript is the one YouTube's *Show transcript* opens: the captions of the video's original language, also for auto-dubbed videos (`--olang` when YouTube gets it wrong). The AI summary is in the language of the video.
- `dual:CODE` and `plain:CODE.translated` use YouTube's machine translation, so their quality varies. YouTube refuses translations asked for soon after the video's data was fetched, so the program waits 70 to 100 seconds first (shown on screen); a translation refused even then is left out with a note (see *The transcript*).
- A chapter list in a video description becomes real chapters on YouTube only if it starts at `0:00`, has at least three timestamps in ascending order and each chapter is at least 10 seconds long.
- Typical page size: a few hundred KB up to a few MB for thousands of comments.
- Keep the pages themselves, not only the saved data: a page holds its images, and `--json load` takes them from it; without the page they are downloaded again, and YouTube may remove them over the years (missing avatars become letters). Rebuilding from saved data is for a newer look of the page; the extra audio switches and the dated *Video file* row come back only if the data know the files: saved with `--json write` in the same run as `--video`, or added later with `--json write --video …`.
- An SRT file is written over whenever the transcript it comes from changes, so corrections made in it by hand are lost: correct a translation in your own `.own.srt` file, or the original in a `.fixed.srt` file, and merge it again.

## Troubleshooting

- **Fetching fails after it used to work:** YouTube changes often and yt-dlp follows within days; update first with `uv tool upgrade yt-video-archiver`. `yt2html --version` shows the yt-dlp version in use.
- **`Sign in to confirm you're not a bot`, age-restricted video:** use `--cookies firefox` (see *Signing in*).
- **`Warning: the original language is uncertain` (videos with YouTube's automatic dubbing):** YouTube sent no audio tracks to tell the original from the dubs, and the video's YouTube page did not name it either, so the transcript and the page's language follow the captions YouTube opens with, which may be a dub's. The page says so above the transcript. If you know the original language, give it: `--olang CODE` (with saved data, `--json write --olang CODE --transcript ovr`); or make the page again later (`--page ovr`), with `--cookies firefox` if YouTube asked to confirm you're not a bot.
- **A translation fails with `HTTP 429`:** YouTube refuses auto-translated captions to downloads at times, sometimes for days (also to yt-dlp alone, with cookies and from other networks). The page is made without it; try again later with `--json write` and the same `--transcript` (keeps the comments; needs the saved data) or `--page ovr`. Or translate the subtitles yourself and merge the translation with `--json merge` (see *Saved data*).
- **`FAILED: no connection to YouTube (…)`:** the computer lost its connection (the name `www.youtube.com` did not resolve, or there was no network). The run stops at that video: it and the ones after it are as they were, pages and data alike, so no page is left with placeholders for its images. With `--video`, files downloaded for the video before the connection went are kept and described (`Video: the connection was lost; saved what was downloaded: …; not downloaded: …`, then `this video is saved as far as it got`); what was not downloaded is shown as `not saved` in `--json show`. Run the same command again when the connection is back; what was done is not asked for again.
- **`Audio FAILED: de-DE (auto-dubbed): …`:** one extra track could not be downloaded; the video and the other tracks are downloaded and described all the same, and the track is shown as `not saved` in `--json show`. The same command tries it again.
- **`Video FAILED: …`:** the video file could not be downloaded; the extra audio tracks are downloaded all the same, and with `--json` the video file is shown as `not saved` in `--json show`, with the command to try again. **`Video skipped: …`** (no ffmpeg, no formats in YouTube's list, nothing within the quality asked for): with `--json` what was asked for is noted the same way.
- **`No transcript: ...` although YouTube shows *Show transcript*:** look for a yt-dlp warning about subtitles and a missing PO token; updating yt-dlp usually helps.
- **`Could not read them ...; using yt-dlp chapters instead`:** the page is made, but without the AI summary, People mentioned and similar sections, and with chapters under a plain `Chapters` heading (*About this copy* says so in its *Video page* row). Usually temporary; run again with `--page ovr`.
- **`Chapter source unclear: ...`:** the chapters are on the page, only without the grey origin note. Please report the video: YouTube has probably changed something.
- **`FAILED: ... this is a channel URL`:** pass the URL of a video or of a playlist.
- **`FAILED: ...: Video unavailable. ...`, `Private video. ...` and the like:** YouTube no longer shows the video (removed, its account terminated, made private), also in a playlist; nothing is saved for it. Each run tries it again; it does not stop the other videos. A video saved before keeps its page; `--json refresh` records that it is gone (see *Saved data*).
- **`FAILED: https://www.youtube.com/watch?v=...` in a playlist:** yt-dlp's `ERROR` line above says why. Each run tries it again; it does not stop the other videos.
- **`... is not in the output folder`:** a file was given with a path to another folder; give `-o` that folder, or the name only (see *How the options work*).
- **`series.txt, line 7: …` and nothing downloaded:** the list file has a line the program does not understand; the run stops before any download. Fix that line (comments start with `//`; see *List files and their index*).
- ***playlist could not be read* in the index:** YouTube did not give the playlist and no earlier index kept its list. Run again when YouTube can be reached; a private playlist needs `--cookies firefox`.
- **`This file could not be played.` in the index's player:** the file was moved or deleted after the index was made, or the browser does not play its format; see *The player of the index*.
- **Some avatars are letters:** those images could not be downloaded (or the author has none).
- **`Info card link ... kept as a YouTube redirect`:** the website behind a link card could not be read; the card links through YouTube instead, which may stop working later. Run again with `--page ovr`, or leave the cards out with `--page cards:no` if this keeps failing.
